# Настройка рабочего окружения на Windows

Эта инструкция — как повторить на домашнем компьютере (Windows) то же
самое рабочее окружение, что уже настроено на Mac: терминал + Claude
Code + VS Code + локальный запуск проекта + доступ к серверу по SSH.
Ничего в самом проекте это не меняет — просто вторая машина, с которой
можно с ним работать.

**Прочитать после этой инструкции, если ещё не читал(а):**
`PROJECT_BRAIN.md` (корень репозитория) — что это за проект и как всё
устроено, `CLAUDE.md` (корень репозитория) — как мы работаем с Claude
Code в этом проекте. Обе подхватятся автоматически, как только откроешь
эту папку в Claude Code — ничего специально просить не нужно, это
происходит на любом компьютере одинаково.

## Что перенесётся само, а что нет

- **Переносится само (через GitHub)**: весь код, вся документация
  (`CLAUDE.md`, `PROJECT_BRAIN.md`, `LEARNING.md`, `docs/`) — просто
  клонируешь репозиторий, и всё это уже там.
- **Не переносится, и не должно**: локальная память Claude Code
  (то, что ассистент "помнит" между сессиями на конкретном
  компьютере) — она привязана к конкретной машине/аккаунту. Это не
  потеря: всё, что важно на постоянной основе, уже записано в файлы
  выше. Новая сессия на Windows прочитает те же файлы и будет вести
  себя так же.
- **Не переносится вообще, и переносить не нужно**: локальные секреты
  для разработки (`server/.env`, `server/.env.test`) — на Windows
  создаёшь их заново, с новыми случайными значениями (шаг 5). Они
  нужны только для того, чтобы приложение на твоём компьютере вообще
  запустилось, синхронизировать их с Mac не нужно.

## 1. Установить базовые инструменты

Ставь в этом порядке — каждый следующий шаг может зависеть от
предыдущего.

### 1.1 Git

Скачать и установить: https://git-scm.com/download/win — при установке
можно оставить все настройки по умолчанию. Вместе с Git ставится
**Git Bash** — терминал, в котором привычные Unix-команды (`ls`, `cd`,
`cat` и т.п.) работают так же, как на Mac. Дальше в этой инструкции все
команды — для Git Bash (или обычного PowerShell, где это без разницы —
отдельно отмечу, если будет разница).

После установки, в любом терминале задать своё имя/почту для коммитов
(это то, что будет видно в истории git — можно то же самое, что и на
Mac):
```bash
git config --global user.name "Твоё Имя"
git config --global user.email "твоя@почта"
```

### 1.2 Node.js

Проект использует Node.js версии 24. Проще всего поставить через
**nvm-windows** (менеджер версий Node, позволяет держать нужную версию
и не путаться, если понадобится другая для чего-то ещё):

1. Скачать установщик `nvm-setup.exe` с
   https://github.com/coreybutler/nvm-windows/releases (последний
   релиз, файл `nvm-setup.exe`)
2. Установить, открыть **новый** терминал (важно — старый не увидит
   `nvm`, если был открыт до установки)
3. ```bash
   nvm install 24
   nvm use 24
   node -v   # должно показать v24.x.x
   ```

### 1.3 PostgreSQL

Нужна локальная база для разработки (продакшен-база — отдельно, на
сервере, её трогать с домашнего компьютера не нужно).

**Как сделано на домашнем ПК владельца (2026-11-07).** На этом
компьютере уже стоит отдельный, *учебный* PostgreSQL 18 (служба
`postgresql-x64-18`, порт `5432`, папка `E:\PostgreSQL\18`). Его
**не трогаем**. Для проекта поставлена своя, полностью независимая
копия:

| Что | Где |
|---|---|
| Программа PostgreSQL **16.15** (та же основная версия, что `postgres:16` на сервере) | `E:\MyTracker\postgres16` |
| Данные (сами базы) | `E:\MyTracker\pgdata16` |
| Порт (номер «двери», через которую подключаются) | `5433`, только с этого компьютера (`localhost`) |
| Пароль пользователя `postgres` | скрытый файл `E:\MyTracker\.pgpass_init` (не в git) |
| Лог (журнал работы сервера базы) | `E:\MyTracker\pgdata16.log` |
| Запуск / остановка / консоль | `E:\MyTracker\start-db.cmd`, `stop-db.cmd`, `open-db.cmd` |

Это **не служба Windows**: после перезагрузки база сама не стартует —
перед работой запустить `start-db.cmd` (двойной клик). Проверить, что
работает: `E:\MyTracker\postgres16\bin\pg_isready.exe -h localhost -p 5433`.

Как это повторить с нуля (если папку `E:\MyTracker` потеряли):
1. Скачать архив без установщика: `https://get.enterprisedb.com/postgresql/postgresql-16.15-1-windows-x64-binaries.zip`
   (официальная сборка EDB), распаковать папку `pgsql` в `E:\MyTracker\postgres16`.
2. Придумать пароль, записать в `E:\MyTracker\.pgpass_init`, затем:
   ```bash
   E:/MyTracker/postgres16/bin/initdb.exe -D E:/MyTracker/pgdata16 -U postgres \
     --pwfile=E:/MyTracker/.pgpass_init --auth=scram-sha-256 -E UTF8 --locale=C
   ```
3. Дописать в конец `E:\MyTracker\pgdata16\postgresql.conf`:
   `port = 5433` и `listen_addresses = 'localhost'`.
4. Запустить `start-db.cmd` и перейти к шагу 4 ниже.

(Обычный вариант для «чистого» компьютера — установщик с
https://www.postgresql.org/download/windows/, порт по умолчанию `5432`.
Тогда в строках подключения ниже вместо `5433` будет `5432`.)

## 2. Склонировать репозиторий

```bash
git clone git@github.com:Elf1movv/TaskTrackerNew.git
cd TaskTrackerNew
```

Если `git clone` по SSH откажет (спросит пароль или выдаст ошибку
доступа) — значит на этом компьютере ещё нет SSH-ключа, привязанного к
твоему GitHub-аккаунту. Это отдельный ключ, не тот, что для сервера
(см. шаг 6) — для GitHub:
```bash
ssh-keygen -t ed25519 -C "твоя@почта"
cat ~/.ssh/id_ed25519.pub
```
Скопировать выведенный текст (начинается с `ssh-ed25519`) и добавить
на github.com → фото профиля → **Settings** → **SSH and GPG keys** →
**New SSH key** → вставить, сохранить. После этого `git clone` выше
должен сработать.

Открыть склонированную папку в VS Code: либо `code .` в терминале
(находясь внутри папки `TaskTrackerNew`), либо через File → Open Folder.

## 3. Настроить переменные окружения

Три файла — все **не в git** (специально, чтобы секреты не утекали в
публичный репозиторий), создаются вручную по образцу уже существующих
`.example`-файлов:

```bash
cp .env.example .env
cp server/.env.example server/.env
cp server/.env.test.example server/.env.test
```

Открыть `server/.env` в VS Code и заполнить:
- `DATABASE_URL` — соберём после шага 4, когда будет создана локальная
  база
- `BETTER_AUTH_SECRET` — любая случайная строка, для локальной
  разработки не важно какая именно (не обязана совпадать с Mac —
  просто подписывает сессионные куки на **твоём** локальном сервере):
  ```bash
  node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
  ```
  Вставить то, что выведется, в `BETTER_AUTH_SECRET=""`
- `BETTER_AUTH_URL` — уже стоит правильное значение
  (`http://localhost:3001`), не трогать
- `RESEND_API_KEY` — можно оставить пустым: без него письма (сброс
  пароля, подтверждение почты) не отправляются по-настоящему, а просто
  печатаются в лог терминала, где крутится сервер — этого достаточно
  для разработки

`server/.env.test` — то же самое, отдельная база для тестов (шаг 4).
`.env` в корне — трогать не нужно, там уже правильное значение
(`VITE_API_URL=/api`).

## 4. Создать локальные базы данных

Нужны две базы: `tasktracker` — для запуска сайта у себя, и
`tasktracker_test` — только для автотестов (тесты при каждом запуске
**стирают её и заполняют заново**; `server/vitest.setup.ts` откажется
запускаться, если в имени базы нет слова `test`). Обе живут только на
этом компьютере и никак не связаны ни с боевой базой, ни с базой
тестового сайта на VPS.

Открыть консоль базы — `E:\MyTracker\open-db.cmd` (или
`E:/MyTracker/postgres16/bin/psql.exe -h localhost -p 5433 -U postgres`).
Посмотреть и поменять данные в виде таблиц в браузере — `cd server`,
затем `npx prisma studio`. Всё, что здесь меняется, видно только на
этом компьютере: настоящих пользователей mytracker.space это не касается.
Дальше внутри `psql` (приглашение `postgres=#`):
```sql
CREATE DATABASE tasktracker;
CREATE DATABASE tasktracker_test;
\q
```

Теперь вписать `DATABASE_URL` в `server/.env` и `server/.env.test`
(пароль — тот же, от `postgres`):
```
# server/.env
DATABASE_URL="postgresql://postgres:ТВОЙ_ПАРОЛЬ@localhost:5433/tasktracker"

# server/.env.test
DATABASE_URL="postgresql://postgres:ТВОЙ_ПАРОЛЬ@localhost:5433/tasktracker_test"
```
На домашнем ПК оба файла уже созданы 2026-11-07 (пароль — из
`E:\MyTracker\.pgpass_init`, `BETTER_AUTH_SECRET` — случайные строки).
(На Mac используется вход без пароля через отдельного пользователя
`maria` — на Windows PostgreSQL по умолчанию требует пароль даже для
localhost, поэтому здесь используется `postgres` с паролем. Работает
так же, просто чуть другая строка подключения.)

## 5. Установить зависимости и применить миграции

```bash
# из корня репозитория
npm install

cd server
npm install
npx prisma generate
npx prisma db push      # создаёт таблицы в tasktracker по schema.prisma
cd ..
```

**Почему `db push`, а не `migrate deploy` (выяснено 2026-11-07).**
Миграции — это пошаговая история изменений схемы базы. Цепочка
миграций проекта **не может собрать пустую базу с нуля**: миграция
`20260917144335` добавляет категории без владельца, а
`20260919075427` требует владельца у каждой строки — на пустой базе
она падает с ошибкой `P3018`. На сервере это не мешает: там эти шаги
давно пройдены, а восстановление из резервной копии миграций не
использует. Для локальных баз `prisma db push` создаёт таблицы прямо по
текущей `schema.prisma`, минуя историю.

Тестовой базе таблицы нужно создать отдельно, указав её адрес (в Git Bash):
```bash
cd server
export DATABASE_URL="$(node -e 'require("dotenv").config({path:".env.test",quiet:true});process.stdout.write(process.env.DATABASE_URL)')"
npx prisma db push --skip-generate
npm test
```
После переключения между `main` и веткой с другой схемой (например,
`feat/product-logic-redesign`) — выполнить `npx prisma generate` и
пересоздать таблицы тестовой базы: удалить и создать её заново в
`open-db.cmd` (`DROP DATABASE tasktracker_test; CREATE DATABASE tasktracker_test;`),
затем снова `db push`. Prisma сама запрещает Claude Code «сброс» базы
(`--force-reset`), поэтому пересоздание делается через консоль.

Проверено 2026-11-07: `main` — 64/64 тестов сервера,
`feat/product-logic-redesign` — 83/83.

## 6. Запустить проект локально

Нужны **два терминала одновременно** (в VS Code можно открыть второй
через `+` на панели терминала):

```bash
# терминал 1, из корня репозитория
cd server
npm run dev
```
```bash
# терминал 2, из корня репозитория
npm run dev
```

Открыть http://localhost:5173 — должна открыться страница входа/
регистрации. Зарегистрировать нового пользователя (это отдельная,
локальная база — не имеет отношения к настоящим пользователям на
mytracker.space) и убедиться, что всё работает.

## 7. Доступ к серверу (mytracker.space) по SSH

Отдельный ключ от того, что для GitHub (шаг 2) — для входа на сам VPS.

1. Сгенерировать новый ключ **специально для этого компьютера**
   (не копировать приватный ключ с Mac — правильная практика: у
   каждого устройства свой ключ, тогда потеря одного устройства не
   требует ничего менять на остальных):
   ```bash
   ssh-keygen -t ed25519 -C "windows-pc"
   ```
   Согласиться с путём по умолчанию, можно без пароля на ключ (или с
   паролем — на выбор)
2. Показать публичный ключ и скопировать вывод:
   ```bash
   cat ~/.ssh/id_ed25519.pub
   ```
3. На **Mac** (там уже есть рабочий доступ) выполнить, подставив
   скопированную строку вместо `ВСТАВЬ_СЮДА_ПУБЛИЧНЫЙ_КЛЮЧ`:
   ```bash
   ssh deploy@185.65.202.121 "echo 'ВСТАВЬ_СЮДА_ПУБЛИЧНЫЙ_КЛЮЧ' >> ~/.ssh/authorized_keys"
   ```
   (Если рядом нет Mac под рукой — можно попросить об этом же Claude
   Code в новой сессии, дав ему полученный публичный ключ.)
4. Проверить с Windows:
   ```bash
   ssh deploy@185.65.202.121
   ```
   Должно пустить без пароля. Дальше на сервере доступны те же команды,
   что описаны в `docs/DEPLOYMENT.md` (логи, статус контейнеров,
   ручной передеплой).

**Важно**: это доступ к **настоящему**, продакшен-серверу. Команды
вроде `docker compose down -v` там удаляют реальные данные
пользователей — см. предупреждения в `docs/DEPLOYMENT.md` перед тем,
как что-то там менять.

### 7.1 Заглянуть в саму продовую базу данных (не только в код)

PostgreSQL на сервере сознательно не открыт наружу (ради
безопасности), поэтому смотреть данные напрямую с Windows можно только
через тот же SSH — один порт с сервера "пробрасывается" на свой
компьютер (SSH-туннель):

```bash
ssh -L 5555:localhost:5555 deploy@185.65.202.121
# дальше, уже внутри этой SSH-сессии:
cd /var/www/tasktracker/server
npx prisma studio --port 5555 --browser none
```

Пока эта SSH-сессия открыта в терминале — открыть на своём компьютере
`http://localhost:5555` в браузере: это будет визуальный GUI (Prisma
Studio) с живой продовой базой — все таблицы, можно листать,
фильтровать и даже редактировать значения руками, без единой строчки
SQL. Закрыть — `Ctrl+C` в той же SSH-сессии (и не оставлять запущенным
без необходимости — пока туннель открыт, база технически достижима с
твоего компьютера).

Для более удобной постоянной работы — десктопное приложение вроде
**TablePlus** (есть версия под Windows): подключается через тот же
SSH-туннель напрямую к порту PostgreSQL (5432) внутри контейнера, не
нужно каждый раз руками запускать Prisma Studio.
