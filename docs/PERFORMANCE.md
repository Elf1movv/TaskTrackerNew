# Скорость приложения — проверка по темам ролика (2026-11-18)

Повод: ролик об оптимизации приложений, написанных с ИИ
(instagram.com/reel/DfU0RDUgotD, автор mrconsol). Само видео ассистенту
недоступно, а 31 совет автор присылает только по комментарию. Поэтому взяты
темы из подписи к ролику: картинки, запросы к базе, кеширование, шрифты,
поиск на каждую клавишу, «дёргающиеся» длинные списки, долгая загрузка,
проверка на слабых телефонах. Каждая тема проверена на нашем коде и замерена.

## Замеры

Локальная копия (`run-local.sh`), 6 привычек с историей 3–10 месяцев,
экран 390 px, первый запуск без кеша и без копии на телефоне.

| | Быстрый ПК | «Слабый телефон» (процессор ×4 медленнее, 1,6 Мбит/с, задержка 150 мс) |
|---|---|---|
| Запуск до готового экрана «Привычки» | 0,5 с | 3,3 с (из них код 417 КБ — 2,4 с) |
| Файл шрифтов Google (только список) | 0,2 с | 0,7 с, потом ещё сами шрифты |
| Переключение на «Год» | 20 мс | 200 мс |
| Отметка дня | 9 мс | 30 мс |

Повторный запуск в разы быстрее: код и `index.html` уже лежат на телефоне
(service worker, 2026-11-15). Медленным остаётся первый запуск после
установки и после каждого обновления.

## По темам

| Тема | Как у нас | Работает правильно? | Что сделать |
|---|---|---|---|
| **Картинки** | Только иконки приложения (3–15 КБ) и одна картинка в коде | Да | Ничего |
| **Поиск на каждую клавишу** | Поля поиска в приложении нет | — | Ничего (когда появится — задержка 300 мс перед поиском) |
| **Запросы к базе** | Каждый раздел — один запрос «все мои записи» (15 `findMany`), индексы по `userId` есть; данных у пользователя десятки строк | Да | Ничего сейчас; пересмотреть, если у кого-то станет >1000 записей |
| **Сжатие и кеш файлов** | Сжатие brotli (1,45 МБ → 0,42 МБ), файлы с хешем кешируются на год, копия приложения на телефоне | Да (сделано 2026-11-15) | Ничего |
| **Кеш данных** | Данные каждый запуск скачиваются заново, экраны секунду пустые | Нет | Уже в плане: «показать сразу, проверить сразу» (SWR + ETag), следующая итерация |
| **Код одним файлом** | Весь код — один файл 417 КБ (сжатый). Телефон качает и разбирает код всех экранов, хотя открыт один | Нет — главная причина 2,4 с | Разделить по экранам (`React.lazy`): сначала только открытый экран |
| **Графики (Recharts)** | Библиотека графиков — заметная часть файла. Графики есть только на компьютере (боковое меню и таблица привычек), на телефоне её никто не видит | Нет — телефон качает лишнее | Загружать графики отдельно и только на компьютере |
| **Шрифты** | Manrope и JetBrains Mono с Google: цепочка «наш CSS → CSS Google → файлы шрифтов», три сервера по очереди | Наполовину: `display=swap` есть (текст виден сразу), но JetBrains Mono **нигде не используется**, а цепочка медленная | Убрать JetBrains Mono; Manrope хранить у себя (`woff2`, только кириллица + латиница) и загружать сразу с `preload` |
| **Длинные списки** | Заметки и задачи — постранично (`Pager`), привычек десятки | Да | Ничего |
| **Тяжёлые расчёты** | Расчёты привычек ищут дату в массиве отметок перебором (`includes`) — для «Года» сотни тысяч сравнений; на слабом телефоне 200 мс | Терпимо, но заметно | Искать по набору (`Set`) — ожидаемо в несколько раз быстрее |
| **Проверка на слабом телефоне** | Не делали | Нет | Замер выше добавить в браузерные проверки (`run-local.sh`), чтобы видеть, не стало ли медленнее |

## Предлагаемая итерация «Скорость» (ждёт решения владельца)

1. Код по экранам + графики отдельно и только на компьютере.
2. Шрифты: убрать неиспользуемый, Manrope хранить у себя.
3. Расчёты привычек через `Set`.
4. Замер «слабого телефона» в `run-local.sh`.

Цель — первый запуск на слабом телефоне заметно быстрее 3,3 с, «Год» —
меньше 100 мс. После неё — кеш данных (SWR + ETag), он уже в BACKLOG.
