# Работа без сети: как у конкурентов и что взять нам (2026-11-18)

Вопрос владельца: приложение без интернета не открывается и не даёт ничего
делать. Как это устроено у конкурентов. Проверено по первоисточникам.

## Что нашли

**Todoist** — официальная документация Sync API
(https://developer.todoist.com/api/v1/):
- Правки отправляются пачкой «команд». Документация: «Each command will be
  processed in the specified order».
- У каждой команды свой `uuid`. Документация: «Todoist will not execute a
  command that has same UUID as a previously executed command». Поэтому
  команду можно безопасно повторить после обрыва связи, она не выполнится
  дважды.
- Новая запись получает временный номер (`temp_id`), сервер возвращает
  соответствие временных номеров настоящим (`temp_id_mapping`).
- На каждую команду сервер отвечает отдельно: `"ok"` или ошибка. Ошибки
  вида «запись не найдена» (`ITEM_NOT_FOUND`, код 400) — окончательные,
  такую команду повторять нельзя.
- Обратно сервер отдаёт только изменения с прошлой сверки (`sync_token`).
- Про конфликты — когда одну запись правили в двух местах — документация
  **ничего не говорит**: ни «побеждает последний», ни версий записей.

**Linear** — разбор того, как устроен их механизм синхронизации, по
исходному коду приложения
(https://github.com/wzhudev/reverse-linear-sync-engine). Это не
официальный источник, автор предупреждает о возможных неточностях.
- Полная копия данных — в IndexedDB на устройстве. Изменение сразу видно на
  экране, а в очередь ставится «транзакция».
- Очередь тоже хранится в IndexedDB. Без сети транзакции копятся и
  отправляются сами, когда связь появится. Очередь переживает перезапуск.
- Конфликты: «simple Last-Writer-Wins» (побеждает последний записавший), и,
  судя по устройству, **по отдельным полям**. Если два человека поменяли
  разные поля одной задачи, сохраняются оба изменения.
- Если сервер отклонил транзакцию, на устройстве она откатывается.
- Обратно сервер присылает только изменения, с номером по порядку
  (`lastSyncId`). Устройство видит, что что-то пропустило, и дозапрашивает.

**TickTick** — официального описания нет. Сторонняя справка похожего
сервиса описывает другой подход: при конфликте сохраняются обе версии, и
человек выбирает сам. Подтвердить, что так делает TickTick, не удалось.

## Что из этого следует для нас

У нас уже есть: копия данных на телефоне (сегодняшний кеш), номера новых
записей придумывает устройство (UUID — как `temp_id`, но сразу постоянные),
правки видны сразу с откатом при ошибке.

Нужно взять:
1. **Очередь правок на устройстве**, которая переживает перезапуск
   (Linear) и отправляется по порядку (Todoist).
2. **Повтор без двойного выполнения** (Todoist `uuid`). Наш сервер должен
   спокойно принять повторное «создай запись с этим id», если она уже
   создана: вернуть её, а не выдать ошибку.
3. **Отметка привычки — отдельным действием «отметить день X / снять
   отметку»**, а не отправкой всего списка отметок, как сейчас
   (`toggleHabit` шлёт весь `completedDates`). Иначе отметка с телефона без
   сети затрёт отметки, сделанные на компьютере. Это главная ловушка именно
   нашего приложения.
4. **Конфликт = побеждает последнее изменение, по отдельным полям**
   (Linear). Сейчас сервер на любую устаревшую правку отвечает 409
   «изменено в другом месте». Для правок из очереди — менять только
   присланные поля.
5. **«Запись удалена в другом месте» — окончательная ошибка** (Todoist):
   правку не повторять, убрать из очереди и сказать человеку.
6. **Видимый статус**: «нет сети», «ждёт отправки: N», сообщение, если
   правка не принята.

Не нужно: присылать только изменения (`sync_token`, `lastSyncId`) — у нас
мало данных, а ответ «не изменилось» (304) уже есть. Хранить обе версии и
спрашивать человека (TickTick) — сложнее, а пользы для трекера мало.

## Предлагаемые шаги

1. **Смотреть без сети** — приложение открывается без интернета из копии,
   плашка «Нет сети», кнопки изменения выключены.
2. **Отмечать без сети** — очередь (пункты 1, 2, 6), отметка привычки
   отдельным действием (3), выполнить задачу, создать заметку или задачу.
3. **Всё остальное без сети** — редактирование, удаление, порядок,
   календарь; правило «последний по полям» (4, 5).
