# 05.01. Today Dashboard [Frontend]

# Описание

Редакция ветки product-logic-redesign, третья итерация 2026-11-08 (тестовый
стенд). Главная показывает сегодняшние планы календаря, заметки перед
глазами, привычки, напоминания и обзор активных целей.
Список всех задач сюда не переносится.

# Функциональные требования

## Сегодня по плану

1. Над заметками показывается блок «Сегодня по плану»
   (`TodayPage.tsx:72`). Пока планы не загружены, блок не рендерится.
2. В блок попадают планы CalendarPlan с `'date'` = сегодня и
   `'onHold' !== true` (`selectTodayPlans.ts`):
   1. Сначала планы со временем, по возрастанию `'time'`
   2. Затем планы без времени — в колонке времени подпись «Без времени»
3. Видно не больше 5 строк; при большем числе последней строкой идёт
   ссылка «+N» (N — число скрытых планов).
4. Строка: чекбокс выполнения плана (`PlanToggleCheckbox`), время
   `HH:mm` или `HH:mm–HH:mm`, название. Выполненный план зачёркнут.
   Кроме выполнения, в блоке ничего не редактируется.
5. Название строки, «+N» и ссылка «Открыть календарь» в заголовке ведут
   на `/calendar?view=day&date=<сегодня>`.
6. Без подходящих планов показывается «На сегодня планов нет».

## Заметки

7. Основная кнопка создаёт заметку. Бывший TodayTasksCard заменён NotesCard.
8. Заметки имеют вкладки «Актуальные / Архив»: актуальные —
   `'archivedAt' === null`, архив — остальные. Дат у заметок нет:
   в `NoteForm` только название и описание.
9. Заголовок обязателен, описание необязательно. Описание в строке
   полностью скрывается/раскрывается стрелкой, даже для одной строки.
   Раскрытый текст размещается в пределах ширины карточки,
   растёт по высоте и переносит длинные слова. Редактирование — внутри блока.
10. Архивирование ручное, восстановление возвращает запись в «Актуальные».
    В длинном списке первые 10 заметок, затем «Показать ещё».
11. Заметки не попадают в Tasks, Calendar и статистику выполнения, пока
    их явно не перенесли в задачи (п. 16).
12. Соседний блок целей/напоминаний не растягивается вслед за описанием заметки.
13. Галочка заметки обратимо зачёркивает её; запись остаётся на месте,
    пока пользователь отдельно не архивирует или удалит её.
14. Ручка перестановки поддерживает мышь, касание и стрелки клавиатуры.
    Порядок сохраняется во всех вкладках после перезагрузки.
15. Удаление доступно в обеих вкладках, включая старые записи, через AlertDialog.
16. Перенос заметки в задачи (`NotesCard.tsx:91-121`):
    1. В строке заметки кнопка «Перенести в задачи» (иконка `ListPlus`)
    2. Нажатие заменяет строку формой `TaskForm` с `'draft'` —
       название и описание заметки подставлены; приоритет, категория и
       срок — значения по умолчанию новой задачи
       (см. [01.01. Task CRUD-FRONTEND](../01.%20Tasks/01.01.%20Task%20CRUD-FRONTEND.md))
    3. «Отмена» закрывает форму, заметка не меняется
    4. Сохранение («Добавить задачу») вызывает `moveNoteToTask` —
       `POST /api/notes/:id/to-task` с `'expectedUpdatedAt'` заметки и
       полями формы (`'id'` новой задачи генерируется на клиенте,
       `'completedAt' = null`). Обычный `addTask` не вызывается — дубликата нет
    5. Успех: перечитываются заметки и задачи, toast «Заметка перенесена
       в задачи», форма закрывается
    6. Ошибка (сеть, 400/404/409): toast.error «Не удалось перенести
       заметку — попробуйте ещё раз», заметки перечитываются, форма
       остаётся открытой. Кнопка сохранения заблокирована, пока запрос идёт
    7. Серверная логика — [14.01. Note Entity-BACKEND](../14.%20Notes/14.01.%20Note%20Entity-BACKEND.md), п. 6

## Прочее

17. Все созданные блоки привычек доступны сразу, включая пустые и блоки
    без привычек на сегодняшний день. Существующие расписания не меняются.
18. Привычки, приветствие, переключение карточки целей/напоминаний и
    существующее поведение прошлых напоминаний сохраняются.
