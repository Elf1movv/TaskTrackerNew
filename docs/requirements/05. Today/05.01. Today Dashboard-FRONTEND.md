# 05.01. Today Dashboard [Frontend]

# Описание

Главная страница приложения — сводка на сегодня: список недатированных
незавершённых задач (см. п. 2 — с 2026-09-29 ограничен `'dueDate' ===
null`), прогресс по всем целям (в паре с напоминаниями — карточка-
переключатель, см. п. 8), привычки, назначенные на сегодняшний день
недели. Своей серверной логики нет — собирает и фильтрует данные,
которые уже приходят через
`TaskProvider`/`GoalProvider`/`HabitProvider`/`ReminderProvider`.

С 2026-09-25 карточка задач переосмыслена: раньше это было "что
запланировано на сегодня" (задачи с `'dueDate'` = сегодня, плюс
бессрочные), теперь — плоский инбокс для быстрой записи ("не забыть").
Заголовок карточки (`today.title`) сменился с "Задачи на сегодня" на
**"Общие задачи"** (en: "Today's Tasks" → "General Tasks") — тот же
i18n-ключ, новое значение, не новый ключ. "Что запланировано на
конкретный день" — зона ответственности Календаря (`isTaskOnDay`, см.
`04. Calendar`), не этой страницы.

С 2026-09-25 по 2026-09-29 карточка была ещё и полностью независима от
даты — показывала все незавершённые задачи вообще, включая датированные
(задача с просроченным или будущим `'dueDate'` была видна здесь
одновременно с Calendar). С 2026-09-29, по итогам продуктового аудита
(см. `docs/BACKLOG.md`), это снова сузили: карточка показывает **только
недатированные** задачи (`'dueDate' === null`) — датированная задача
теперь исключительно в Calendar, никогда не дублируется сюда (см. п. 2,
`01.01. Task CRUD-FRONTEND.md`, Описание и п. 11.1).

# Функциональные требования

1. Шапка страницы — крупная дата (день недели, число, месяц и год) и
   кнопка "Add task" (обычная форма без зафиксированной категории и без
   зафиксированной даты — дата по умолчанию берётся из логики самой
   формы, то есть сегодня)
2. `'todayTasks'` (`selectTodayTasks`,
   `src/entities/task/lib/selectTodayTasks.ts`) — с 2026-09-29:
   `tasks.filter(task => task.dueDate === null && (!task.completed ||
   isCompletedToday(task)))`. Показывается только недатированная задача
   (`'dueDate' === null`) — датированная не появляется здесь никогда,
   независимо от того, просрочена она, назначена на сегодня или в
   будущем; такая задача — зона ответственности Calendar (см.
   `01.01. Task CRUD-FRONTEND.md`, Описание). Среди недатированных —
   невыполненная видна всегда, выполненная видна ещё до конца дня, в
   который была выполнена (`isCompletedToday`, то же правило, что уже
   использует страница Tasks, см. `01.01. Task CRUD-FRONTEND.md`, п. 11.2),
   затем пропадает
   1. История правила: до 2026-09-21 бездатная задача оставалась на
      Today бессрочно вне зависимости от статуса — реальный баг (см.
      `LEARNING.md`). 2026-09-21 это исправили, но перегнули палку —
      бездатная задача стала видна только в день создания (`'createdAt'`),
      пропадая на следующий день независимо от `'completed'`. По прямой
      обратной связи 2026-09-23 правило переписано: датированная задача
      видна только в день `'dueDate'`, бессрочная невыполненная видна
      каждый день, бессрочная выполненная — ещё в день `'completedAt'`,
      затем пропадает
   2. С 2026-09-25 это дата-зависимое правило заменено на полностью
      дата-независимое — часть более крупного переосмысления страницы:
      "что запланировано на сегодня" стало зоной ответственности
      Календаря (`isTaskOnDay`, `04. Calendar`), а эта карточка вместо
      этого стала простым инбоксом "быстро записать и не забыть" — весь
      список несделанного разом, без привязки к датам, включая
      датированные задачи (видны здесь **и** в Calendar одновременно)
   3. По прямой обратной связи 2026-09-28 добавлен `isCompletedToday`-хвост
      (выполненная задача остаётся видимой, зачёркнутой, до конца дня
      выполнения, а не пропадает мгновенно) — без видимого подтверждения
      клика пользователю казалось, что чекбокс не сработал
   4. С 2026-09-29, по итогам продуктового аудита (см.
      `docs/BACKLOG.md`), дата-независимость сузили обратно: показ
      датированной задачи здесь **и** в Calendar одновременно приводил к
      путанице (тот же пункт мог существовать в двух видах — быстро
      вписанный недатированный и отдельно поставленный в календаре
      датированный, с одинаковым названием, без какой-либо видимой связи
      между ними). Теперь показ по дате не читается вообще **кроме**
      самого разделения "есть/нет `'dueDate'`" — недатированная видна
      независимо от прошлой логики дат, датированная не видна никогда,
      что и есть нынешнее правило (см. начало пункта)
3. `'habits'` на Today (`selectTodayHabits`,
   `src/entities/habit/lib/selectTodayHabits.ts`) — только привычки, у
   которых сегодняшний день недели (`new Date().getDay()`) входит в
   `'activeDays'`; привычка вне сегодняшнего расписания на Today не
   рендерится вовсе (не показывается приглушённой — просто отсутствует
   в списке). Управлять такой привычкой (редактировать/удалить/отметить
   задним числом) можно только со страницы Habits, см. `03.02. Habit
   History-FRONTEND.md`. Цели на этой странице по-прежнему **не
   фильтруются** — показываются все, независимо от прогресса или даты.
   С 2026-09-24 этот уже отфильтрованный список дальше раскладывается по
   блокам (`HabitGroup`) — привычка вне сегодняшнего расписания не
   просто не видна, а из-за этого фильтра ещё и не даёт своему блоку
   показаться на Today вовсе, если в блоке больше нет других привычек на
   сегодня, см. `03.04. Today Habit Groups-FRONTEND.md`
4. Три блока на странице: карточка задач (`today.title` = "Общие задачи",
   см. Описание; 2/3 ширины на широких экранах), карточка-переключатель
   "Прогресс целей ↔ Напоминания" (1/3 ширины, см. п. 8) — оба в одном
   ряду, и список карточек-блоков привычек на всю ширину под ними (до
   2026-09-24 — плоская сетка без группировки, см. `03.04. Today Habit
   Groups-FRONTEND.md`)
5. `TodayTasksCard` показывает полосу прогресса (выполнено/всего) и
   список задач (см. п. 2) с полным CRUD (переключение, редактирование,
   удаление — без диалогов подтверждения) плюс переупорядочивание внутри
   этого списка
6. Переупорядочивание задач на Today — **отдельный** от переупорядочивания
   на странице Tasks и от переноса дат в Calendar набор перетаскиваний
   (разные внутренние типы для drag-and-drop), но в конечном счёте меняет
   то же самое поле `'order'` у той же самой задачи
7. Пустое состояние карточки задач — `today.noTasksToday`, с 2026-09-25
   "Нет незавершённых задач"/"No unfinished tasks" (было "На сегодня
   задач нет"/"No tasks for today" — тот же ключ, новое значение, в
   духе переосмысления п. 2)
8. Третий блок ряда — не фиксированная сводка целей, а
   `GoalReminderSwapCard`: карточка "Прогресс целей" (`GoalProgressSummary`)
   и карточка "Напоминания" (`ReminderSummary`) делят одну ячейку сетки,
   переключаются круглой кнопкой в правом верхнем углу карточки. Сама
   карточка при заходе на Today один раз автоматически открывается на
   "Напоминаниях", если они есть. Круглая кнопка-переключатель несёт
   счётчик предстоящих напоминаний (бейдж/`Tooltip`) — единственное место
   на странице Today с этой информацией, так как на этой странице
   глобальный колокольчик (п. 9) не рендерится вовсе (история этого
   поведения — два захода 2026-09-23, см. `13.02. Reminder
   Entity-FRONTEND.md`, п. 25). Полное описание анимации переключения,
   обеих карточек, автооткрытия, фильтра приоритета в `ReminderSummary` и
   клика по строке цели (переход на редактирование, п. 21-23 `02.01. Goal
   CRUD-FRONTEND.md`) — в `13.02. Reminder Entity-FRONTEND.md`, пп. 20-32
   (эта фича рассматривается как единое целое, а не отдельно для каждой
   из двух карточек)
9. Глобальный колокольчик напоминаний (`13.03. Reminder
   Bell-FRONTEND.md`), видный в правом верхнем углу экрана на любой другой
   защищённой странице, на Today **не рендерится** —
   `{location.pathname !== "/today" && <ReminderBell />}`
   (`src/app/layouts/RootLayout.tsx:45`). До 2026-09-23 (второй заход) он
   был виден и здесь тоже, одновременно с бейджем на кнопке
   `GoalReminderSwapCard` (п. 8) — два колокольчика с одной и той же
   информацией на одной странице; на Today теперь только один
