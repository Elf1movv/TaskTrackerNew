# 04.04. Day & Week Timeline [Frontend]

# Описание

Часовая шкала суток (00:00–23:00) с отдельной строкой "весь день" сверху
— общий виджет `calendar-timeline`, которым пользуются оба вида, День (1
колонка) и Неделя (7 колонок, по одной на день недели). Своей серверной
логики нет — под капотом обычный `updateTask`/`updateReminder`.

С 2026-09-24 (в отличие от версии этой фичи из того же дня, но более
раннего коммита) вид "День" пережил отдельный редизайн: статическая
правая панель убрана целиком, вместо неё — клик/драг прямо по часовой
сетке создаёт задачу/напоминание нужной длительности, существующий блок
задачи можно тянуть за нижний край, меняя длительность, а редактирование
и быстрое добавление открываются всплывающим `CalendarItemPopover`,
заякоренным в точке клика/отпускания. У задачи впервые появилось поле
`'endTime'` — конец временного блока. Цвет блока/чипа на шкале теперь
фиксирован по **типу** сущности (Задача/Напоминание/Цель), а не по
приоритету — приоритет остался виден через форму иконки. Цель на этой
шкале стала полностью пассивным маркером, без клика и перетаскивания.

Вид "Неделя" в этом раунде **не редизайнился** — он автоматически
наследует общие изменения `calendar-timeline` (фиксированные цвета,
формы, пассивная цель), потому что использует те же `HourGrid`/
`AllDayRow`, но сохраняет собственную старую компоновку "шкала + правая
панель с формами" и весь свой флоу добавления/редактирования, включая
CRUD цели — см. п. 13.

# Функциональные требования

1. `HourGrid`/`AllDayRow` универсальны по числу колонок дней
   (`columns: HourGridColumn[]`/`AllDayColumn[]`, каждая несёт свой
   `'day'` и уже отфильтрованный набор задач/напоминаний/целей/привычек,
   `HourGrid.tsx:15-22`, `AllDayRow.tsx:11-21`) — вид "День" передаёт
   массив из одной колонки (`anchorDate`), вид "Неделя" — массив из семи
   (`buildWeekRange`). Сам виджет не знает, что показывает День или
   Неделю — только "сколько колонок дать"
2. Разбиение задач/напоминаний на "со временем"/"без времени" делает
   страница (`CalendarDayView.tsx:52-55`, `CalendarWeekView.tsx:60-80`),
   не сам виджет — задачи/напоминания с `'time' !== null` идут в
   `HourGrid`, без времени — в `AllDayRow`
   1. Цель **всегда** в `AllDayRow`, никогда в `HourGrid` — у
      `'targetDate'` только дневная точность (`isGoalDueOnDay`, см.
      `04.02. Month View-FRONTEND.md`, п. 5.5), своего поля времени суток
      у цели нет вообще
   2. Привычка тоже всегда в `AllDayRow`, но показывается **только
      количеством** — иконка `Repeat` + число (`AllDayRow.tsx:117-122`),
      без отдельной строки на каждую привычку и без клика — тот же
      компактный принцип, что у маркера привычки в ячейке сетки "Месяца"
      (`04.02`, п. 3.1)
3. `HourGrid` — 24 строки фиксированной высоты (`HOUR_HEIGHT_PX = 64`px,
   общая константа для CSS сетки и для пиксельной математики в
   `shared/lib/timeOffset.ts`, чтобы они не могли разойтись). Элементы
   позиционированы абсолютным смещением в пикселях от
   `minutesFromMidnight('time')`, а не 96-рядной CSS-сеткой
   1. При монтировании сетка один раз автоматически прокручивается так,
      чтобы примерно текущее время оказалось по центру видимой области
      (`hasScrolledToNow` ref, `HourGrid.tsx:64-70`) — иначе свежеоткрытая
      страница всегда открывалась бы на 00:00, пряча ту часть суток, ради
      которой вид и открыли. Автопрокрутки к краю контейнера во время
      самого драга (создания/резайза/перетаскивания) нет — см. Известные
      ограничения, п. 4
   2. Линия "сейчас" — тонкая красная горизонтальная линия с точкой у
      левого края, позиция пересчитывается раз в 60 секунд
      (`setInterval`, `HourGrid.tsx:56-59`), показывается только в
      колонке того дня, для которого `isToday(column.day)` — у остальных
      колонок (соседние дни недели) линии нет вообще
4. Карточка задачи со временем (`TimedTaskBlock`) — с 2026-09-24 высота
   **переменная**, а не фиксированная: `timeToOffsetPx(endTime) -
   timeToOffsetPx(time)`, с полом `MIN_BLOCK_HEIGHT_PX = 18`px
   (`blockHeightPx`, `HourGrid.tsx:216-220`). Если у задачи `'endTime' ===
   null` (задача создана до этой фичи, либо создана/отредактирована без
   явного конца) — используется старый фиксированный
   `FALLBACK_BLOCK_HEIGHT_PX = 22`px, то же поведение, что было у всех
   задач до этого раунда
   1. Карточка — `PriorityDot` (с `'colorOverride'`, п. 8) + `'time'`
      (моноширинным шрифтом) + название, левая рамка фиксированного цвета
      `ENTITY_TYPE_COLORS.task`, зачёркнуто и приглушено, если задача
      выполнена. Клик (`onClick`, не `onPointerDown` — см. п. 6.4.1)
      открывает `CalendarItemPopover` в режиме `edit-task`, заякоренной в
      `getBoundingClientRect()` самой карточки
5. **Создание задачи/напоминания кликом или драгом вниз по пустому месту
   колонки** (День, новое в этом раунде; см. п. 13 — Неделя эту
   возможность не получила):
   1. Жест — press-and-drag-down: колонка ловит `onPointerDown` только на
      собственном фоне (`onCreatePointerDown`, `useCreateDrag.ts`), не на
      существующих блоках — у блока свой `onPointerDown` уже вызывает
      `stopPropagation()` (см. п. 6.4.1), поэтому начатый на блоке жест
      никогда не долетает до обработчика колонки
   2. Пока драг идёт — пунктирный превью-прямоугольник цвета
      `ENTITY_TYPE_COLORS.task` растёт от точки нажатия вниз, до текущей
      позиции курсора (`preview`, `HourGrid.tsx:181-191`). Оба конца
      снэпаются к 15-минутному шагу через `offsetPxToTime` — та же
      функция и тот же шаг, что уже использует перетаскивание по времени
      (п. 7.2)
   3. Тянуть вверх выше точки нажатия нельзя — превью зажимается в
      нулевую длину относительно точки старта, диапазон никогда не
      переворачивается (`useCreateDrag.ts:49-59`)
   4. При отпускании (`onEnd` из общего `usePointerVerticalDrag`, который
      использует `pointerCapture` — жест не срывается, даже если курсор
      успел выйти за пределы прокручиваемого `overflow-auto` контейнера
      сетки во время движения):
      1. Если получившаяся длительность **меньше 15 минут** (в том числе
         обычный клик без сдвига мыши вообще) — это трактуется как
         "просто клик": создаётся блок по умолчанию **30 минут**,
         начиная с точки нажатия (`CLICK_FALLBACK_MINUTES`,
         `DEFAULT_BLOCK_MINUTES`, `useCreateDrag.ts:9-10, 71-75`)
      2. Иначе — используется реально протянутый диапазон
      3. Открывается `CalendarItemPopover` в режиме `create` с
         `'defaultTime'`/`'defaultEndTime'`, заякоренной в
         прямоугольнике, соответствующем вычисленному диапазону
         (`useCreateDrag.ts:77-80`) — сама задача/напоминание ещё не
         создаётся, пока пользователь не введёт название и не сохранит
         форму в попапе
6. **Изменение размера существующего блока задачи** (День, новое в этом
   раунде; только у задачи — у напоминания нет `'endTime'`, см. `01.01.
   Task CRUD-FRONTEND.md`, п. 5.8.4):
   1. Тонкая (`h-2`, ~8px) невидимая ручка вдоль нижнего края блока,
      курсор `cursor-ns-resize` (`HourGrid.tsx:279-292`) — рендерится
      только если родитель `HourGrid` получил `'onResizeTask'` (у Недели
      не рендерится вовсе, см. п. 13)
   2. Драг живой превью-высоты блока во время движения (`draftEndTime`,
      `useResizeDrag.ts`) — новый `'endTime'` не может стать раньше, чем
      `'time'` задачи плюс 15 минут (`MIN_DURATION_MINUTES`,
      `clampedEndTimeAtClientY`, `useResizeDrag.ts:7, 24-33`), блок не
      может схлопнуться в нулевую/отрицательную длительность
   3. При отпускании сразу вызывается `onResizeTask(taskId, endTime)` →
      `resizeTask` провайдера (`04.01`, п. 7.6) — без попапа и без
      подтверждения, изменение сохраняется немедленно, потому что
      меняется только граница блока, а не название/другие поля
   4. Три детали сосуществования с уже существующим перетаскиванием
      блока целиком (`react-dnd`, тип `"calendar-task-time-move"`,
      `useDragItem`/`useDropTarget`, п. 7) и с кликом на блок (п. 4.1),
      не очевидные из кода на первый взгляд:
      1. Собственный `onPointerDown` блока вызывает `stopPropagation()`
         (`HourGrid.tsx:255`) — иначе начало жеста на существующем блоке
         запускало бы ещё и создание нового (п. 5.1) на колонке-предке
      2. Ручка ресайза получает `draggable={false}`, чтобы нативный
         HTML5 drag (`react-dnd`) не запускался с неё — её родитель-блок
         несёт `draggable=true` для перетаскивания целиком — **и**
         отдельный собственный `onClick={e => e.stopPropagation()}`
         (`HourGrid.tsx:288`). Это не избыточность: `stopPropagation()`
         на `pointerdown` не останавливает отдельно синтезируемое
         браузером событие `click` после отпускания кнопки — у него свой
         независимый путь всплытия. Без отдельного перехвата `click`
         резайз-жест на короткую дистанцию (когда мышь почти не
         сдвинулась) открывал бы попап редактирования сразу после
         резайза — реальный баг, найден и исправлен в рамках этого
         раунда
      3. Корневой элемент блока задачи — `<div role="button"
         tabIndex={0}>`, не `<button>` (`HourGrid.tsx:249-259`): нативная
         `<button>` не может валидно содержать другой интерактивный
         дочерний элемент (саму ручку), а обработчики клавиатуры (`Enter`/
         `Space` → тот же `onEdit`) добавлены вручную, чтобы не терять
         доступность
7. **Перетаскивание задачи по времени целиком** (`"calendar-task-time-move"`,
   отдельный от дневного `"calendar-task-move"` вида "Месяц"/строки "весь
   день", п. 9):
   1. Целью перетаскивания служит **вся колонка дня целиком**, не
      отдельная ячейка часа (`useDropTarget` на весь `TimelineDayColumn`,
      `HourGrid.tsx:131-138`) — 24 вложенных цели на одну колонку
      воспроизвели бы тот же баг двойного срабатывания, для которого в
      `useDropTarget` уже есть защита `monitor.didDrop()` (см.
      `04.01. Calendar Infrastructure-FRONTEND.md`, файлы)
   2. Y-координата отпускания (второй аргумент `onDrop` — координаты
      клика в пикселях, `useDropTarget`) переводится в снэпнутое время
      через `offsetPxToTime` — по умолчанию с шагом **15 минут**
      (`snapMinutes`, `shared/lib/timeOffset.ts:32-34, 53-55`), потому что
      курсор мыши почти никогда не попадает ровно в конкретную минуту
   3. При отпускании вызывается `onRescheduleTask(taskId, day, time)` →
      `rescheduleTaskTime` провайдера (`04.01`, п. 7.5) — меняет
      `'dueDate'`, `'time'` **и**, с 2026-09-24, `'endTime'` (сдвинутый на
      ту же дельту минут, чтобы длительность блока не "съезжала" при
      переносе), в отличие от перетаскивания на день в
      `AllDayRow`/"Месяце", которое трогает только `'dueDate'`
8. **Фиксированный цвет по типу сущности**, заменивший цвет по приоритету
   в этом виджете (решено в рамках этого раунда): `ENTITY_TYPE_COLORS`
   (`src/shared/lib/colors.ts`) — `task: "#5b7fc7"`, `reminder:
   "#c9a63a"`, `goal: "#a35bc7"`, подобраны из общей палитры
   `PALETTE_COLORS` и сверены с `PRIORITY_COLORS`/
   `REMINDER_PRIORITY_COLORS` на отсутствие совпадений. Это касается
   именно левой рамки/фона блоков и чипов часовой шкалы и строки "весь
   день" — приоритет здесь больше не кодируется цветом вообще, только
   формой иконки:
   1. `PriorityDot`/`ReminderPriorityIcon` получили ранее не
      использовавшийся проп `'colorOverride'` (`PriorityDot.tsx:17-24`,
      `ReminderPriorityIcon.tsx:18-25`) — здесь передаётся
      `ENTITY_TYPE_COLORS.task`/`.reminder` вместо
      `PRIORITY_COLORS[priority]`/`REMINDER_PRIORITY_COLORS[priority]`,
      но сама иконка (`ChevronDown`/`Equal`/`ChevronsUp`) остаётся разной
      по приоритету — форма как вторая, избыточная подсказка (полезна не
      только эстетически, но и для дальтоников), не единственная
   2. Форма — тоже фиксированный признак типа: у задачи остаётся
      `rounded-md` прямоугольник, у напоминания — `rounded-full` пилюля
      (и в `HourGrid`, и в `AllDayRow`) — цель см. отдельно, п. 10
9. `AllDayRow` — перетаскивание задачи на другой день переиспользует **тот
   же** тип драга, что уже принимает ячейка "Месяца" (`"calendar-task-move"`,
   см. `04.02`, п. 11) — элемент без времени можно перенести только на
   другой день, не на конкретную минуту. Напоминания здесь не
   перетаскиваются вообще — напоминания нигде в приложении не
   перетаскиваются
   1. С 2026-09-24 строка **не** скрывается на пустой день, если у неё
      есть `'onAddUntimed'` (см. п. 10) — раньше (`hasAnyContent` проверка)
      строка целиком возвращала `null`, если ни в одной из колонок не
      было вообще никакого содержимого; теперь это условие смягчено до
      `!hasAnyContent && !onAddUntimed` (`AllDayRow.tsx:51-54`), иначе
      кнопка "+" пустого дня не могла бы отрендериться вовсе. У Недели,
      которая `'onAddUntimed'` не передаёт (п. 13), поведение на пустой
      день не изменилось — строка по-прежнему скрывается целиком
10. Кнопка "+" в строке "весь день" (День, новое в этом раунде; проп
    `'onAddUntimed'`, опциональный — у Недели не передан, кнопки нет,
    `AllDayRow.tsx:123-131`) — открывает `CalendarItemPopover` в режиме
    `create` без времени (`defaultTime: null, defaultEndTime: null`) для
    этого конкретного дня
    1. **Цель на этой строке — пассивный маркер, без клика, без
       перетаскивания, без формы** (решено в рамках этого раунда,
       `AllDayGoalChip`, `AllDayRow.tsx:179-191`): плашка `Target`-иконка
       на кружке цвета `ENTITY_TYPE_COLORS.goal` + название, обычный
       `<div>`, не `<button>` — намеренно, чтобы не было никакой
       кликабельности/фокуса с клавиатуры на элементе, который ничего не

       зарезервирована только за задачей и напоминанием
    2. Цель попадает в эту строку тем же селектором, что и раньше
       (`isGoalDueOnDay`, без изменений), меняется только то, как она
       рендерится
    3. Drop-цель для перетаскивания цели (`useDropTarget({type:
       "calendar-goal-move"})`) убрана из ячейки строки "весь день"
       полностью — у Дня/Недели больше нет никакого CRUD цели через эту

       страницы `/goals` **или**, для Недели, через её собственную панель

    4. Привычки в строке "весь день" видны только числом (п. 2.2) — клик
       по этому числу ничего не делает
11. `CalendarItemPopover` (`src/widgets/calendar-item-popover`) —
    заменил статическую боковую панель Дня. Один попап на три режима:
    1. `create` — открывается после драга/клика на сетке (п. 5.4.3) или
       клика на "+" строки "весь день" (п. 10). Показывает `ToggleGroup`
       "Задача"/"Напоминание" (`calendar.typeTask`/`calendar.typeReminder`)
       по умолчанию на "Задача" — **без варианта "Цель"**, у Дня нет
       создания цели вообще (см. п. 10.3). Переключение типа
       перемонтирует `TaskForm`/`ReminderForm` целиком — недописанный
       черновик при переключении типа теряется, известное и принятое
       мелкое неудобство (см. Известные ограничения, п. 5)
    2. `edit-task`/`edit-reminder` — открывается кликом по существующему
       блоку/чипу; без переключателя типа (тип уже зафиксирован) и с
       кнопкой "Удалить" вместо неё
    3. Заякорен через Radix `PopoverAnchor`'s `'virtualRef'` — виртуальную
       ссылку на объект `{getBoundingClientRect}`, собранный из
       прямоугольника, где жест/клик закончился, а не через реальный DOM-
       элемент-триггер (`CalendarItemPopover.tsx:47`) — первое
       использование этой возможности Radix в приложении: раньше
       `Popover` везде был заякорен на реальный элемент-триггер (например,
       `ReminderBell`), здесь якорная точка динамическая и не совпадает ни
       с одним постоянным элементом на странице
    4. `TaskForm`/`ReminderForm` получили новые опциональные пропы для
       использования здесь:
       1. `'embedded'` — убирает собственную обёртку-карточку с рамкой
          (`PopoverContent` уже даёт свою)
       2. `'onDelete'` — рендерит деструктивную кнопку "Удалить" в футере
          формы, без диалога подтверждения — тот же принцип мгновенного
          удаления без подтверждения, что уже применяется к задачам и
          напоминаниям в других местах приложения
       3. `'defaultTime'`/`'defaultEndTime'` у `TaskForm` и `'defaultTime'`
          у `ReminderForm` — подставляют вычисленные время начала/конца
       4. `'startExpanded'` у `TaskForm` — в отличие от уже существующего
          `'defaultDueDate'` (который только подставляет значение, не
          включая тумблер "Со сроком" — см. `01.01. Task
          CRUD-FRONTEND.md`, п. 5.1-5.2), этот проп **сразу включает**
          секцию срока/времени развёрнутой — попадание сюда означает, что
          пользователь только что буквально выполнил жест перетаскивания,
          которым и выбрал время, поэтому прятать только что выбранное
          значение сразу за свёрнутым тумблером было бы контр-интуитивно
12. Оба вида — "День" (полностью, `CalendarDayView.tsx`) и "Неделя"
    (частично, см. п. 13) — остаются компонентами уровня **страницы**
    (`src/pages/calendar/ui/`), не виджетами, потому что каждый компонует
    больше одного виджета-соседа — та же причина, что уже объяснена для
    всех пяти видов (`04.01. Calendar Infrastructure-FRONTEND.md`, п. 15).
    "День" в этом раунде дополнительно стал первым видом, реально
    использующим освобождённую ширину страницы (`04.01`, п. 16) — сетка
    растягивается на всю доступную ширину, вместо прежней компоновки
    "шкала + фиксированная 280px-панель"
13. **"Неделя" не редизайнилась в этом раунде** (сознательно, "один вид
    календаря за раз") — сохраняет старую компоновку `grid-cols-[1fr_280px]`
    (`CalendarWeekView.tsx:87`), где справа `lg:sticky lg:top-4` панель с
    формами `TaskForm`/`ReminderForm`/`GoalForm` напрямую (без
    `'embedded'`/`CalendarItemPopover'`), с прежним поведением: клик по
    карточке/чипу открывает форму этого элемента в панели, а когда никто
    не редактируется — панель показывает три кнопки быстрого добавления
    (Задача/Напоминание/Цель, `calendar.quickAdd`), всегда на **первый**
    день недели (понедельник, `firstDayKey`) вне зависимости от того,
    какая колонка была видна на экране в момент клика
    1. `HourGrid`/`AllDayRow` вызываются здесь без `'onResizeTask'`,
       `'onCreateDraft'`, `'onAddUntimed'` (`CalendarWeekView.tsx:116-121`,
       `110-115`) — соответствующие пропы у обоих компонентов
       опциональны именно ради этого: когда их нет, колонка не вешает
       `onPointerDown` вовсе и ручка изменения размера не рендерится, то
       есть Неделя автоматически сохраняет старое поведение
       "перетаскивание блока целиком — единственный способ поменять
       время", без изменений в логике этой страницы
    2. Единственное вынужденное изменение поведения Недели в этом раунде
       — то, что `AllDayGoalChip` (общий с Днём компонент, п. 10.1) стал
       пассивным: у сайдбара Недели пропал единственный триггер
       редактирования существующей цели (старый `onEditGoal` чипа), то
       есть отредактировать уже существующую цель через эту панель
       **больше нельзя**; создание **новой** цели через кнопку быстрого
       добавления по-прежнему работает, потому что использует отдельный,
       не связанный с чипом путь (`{kind: "new-goal"}`,
       `CalendarWeekView.tsx:137-139`). Это осознанное, временное
       несоответствие Дню, которое предполагается закрыть, когда до
       Недели дойдёт её собственный редизайн — специально не
       "докручено" сейчас заодно
14. Шапка недели (только вид "Неделя", `CalendarWeekView.tsx:89-108`) —
    ряд из 7 колонок над строкой "весь день": сокращённое название дня
    недели + число, сегодняшняя колонка выделена цветом (`text-primary`).
    Пустая ячейка слева (`w-12`) выравнивается с колонкой часовых
    подписей сетки под ней

# Известные ограничения

1. Два элемента с пересекающимся временем в `HourGrid` визуально
   накладываются друг на друга, а не раскладываются в отдельные
   "дорожки" рядом — полноценная раскладка по дорожкам не делалась
   осознанно, непропорционально сложно для личного трекера такого
   масштаба. Переменная высота блоков (п. 4) делает наложение немного
   заметнее, чем раньше, но саму раскладку в этом раунде не решали
2. Шаг снэпа при перетаскивании/создании/резайзе по времени — фиксированный
   15 минут, нельзя поставить задачу ровно на, например, `14:07`
3. Привычки в строке "весь день" видны только числом (п. 2.2) — клик по
   этому числу ничего не делает; увидеть, какая именно привычка, можно
   только через панель дня "Месяца" (`04.02`, п. 9.4) или страницу
   `/habits`
4. Нет автопрокрутки к краю прокручиваемой области (`max-h-[65vh]`) при
   драге создания/резайза/перетаскивания рядом с её верхней/нижней
   границей — жест просто не может выйти за пределы видимой сейчас части
   суток
5. Переключение переключателя "Задача"/"Напоминание" в попапе создания
   (п. 11.1) после того, как пользователь начал вводить название,
   отбрасывает черновик — обе формы полностью размонтируются и
   монтируются заново. Известное, принятое мелкое неудобство, не
   исправлялось в этом раунде
6. Перенос задачи с `'endTime'` через `rescheduleTaskTime` (п. 7.3), если
   сдвиг выталкивает `'endTime'` за `23:45`, зажимается/обрезается тем же
   способом, что и `offsetToTime` (см. `shared/lib/timeOffset.ts`), а не
   переносится на следующий день — в приложении нигде нет модели блока,
   пересекающего полночь
