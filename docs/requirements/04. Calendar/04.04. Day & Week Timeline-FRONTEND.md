# 04.04. Day & Week Timeline [Frontend]

# Описание

Часовая шкала суток (00:00–23:00) с отдельной строкой "весь день" сверху
— общий виджет `calendar-timeline`, которым пользуются оба вида, День (1
колонка) и Неделя (7 колонок, по одной на день недели). Правая боковая
панель — те же формы `TaskForm`/`ReminderForm`/`GoalForm`, что и везде на
календаре, но, в отличие от вида "Месяц" (`04.02`), сама панель дня не
переиспользуется — здесь эту роль играет часовая шкала, а боковая панель
только на редактирование конкретного элемента и на быстрое добавление.
Своей серверной логики нет.

# Функциональные требования

1. `HourGrid`/`AllDayRow` универсальны по числу колонок дней
   (`columns: HourGridColumn[]`/`AllDayColumn[]`, каждая несёт свой
   `'day'` и уже отфильтрованный набор задач/напоминаний/целей/привычек,
   `HourGrid.tsx:12-19`, `AllDayRow.tsx:9-19`) — вид "День" передаёт
   массив из одной колонки (`anchorDate`), вид "Неделя" — массив из семи
   (`buildWeekRange`). Сам виджет не знает, что показывает День или
   Неделю — только "сколько колонок дать".
2. Разбиение задач/напоминаний на "со временем"/"без времени" делает
   страница (`CalendarDayView.tsx:59-62`, `CalendarWeekView.tsx:61-73}`),
   не сам виджет — задачи/напоминания с `'time' !== null` идут в
   `HourGrid`, без времени — в `AllDayRow`
   1. Цель **всегда** в `AllDayRow`, никогда в `HourGrid` — у
      `'targetDate'` только дневная точность (`isGoalDueOnDay`, см.
      `04.02. Month View-FRONTEND.md`, п. 5.5), своего поля времени суток
      у цели нет вообще
   2. Привычка тоже всегда в `AllDayRow`, но показывается **только
      количеством** — иконка `Repeat` + число (`AllDayRow.tsx:112-117`),
      без отдельной строки на каждую привычку и без клика — тот же
      компактный принцип, что у маркера привычки в ячейке сетки "Месяца"
      (`04.02`, п. 3.1), просто без иконки `Target` рядом (у цели здесь
      уже есть собственная полноценная строка-чип, см. п. 7)
3. `HourGrid` — 24 строки фиксированной высоты (`HOUR_HEIGHT_PX = 64`px,
   общая константа для CSS сетки и для пиксельной математики в
   `timeOffset.ts`, чтобы они не могли разойтись). Элементы позиционированы
   абсолютным смещением в пикселях от `minutesFromMidnight('time')`, а не
   96-рядной CSS-сеткой (`HourGrid.tsx:21-23`)
   1. При монтировании сетка один раз автоматически прокручивается так,
      чтобы примерно текущее время оказалось по центру видимой области
      (`hasScrolledToNow` ref, `HourGrid.tsx:48-57`) — иначе свежеоткрытая
      страница всегда открывалась бы на 00:00, пряча ту часть суток, ради
      которой вид и открыли
   2. Линия "сейчас" — тонкая красная горизонтальная линия с точкой у
      левого края, позиция пересчитывается раз в 60 секунд
      (`setInterval`, `HourGrid.tsx:43-46`), показывается только в
      колонке того дня, для которого `isToday(column.day)` — у остальных
      колонок (соседние дни недели) линии нет вообще
4. Карточка задачи со временем (`TimedTaskBlock`) — фиксированная высота
   `22`px (`BLOCK_HEIGHT_PX`, `HourGrid.tsx:168`; у этого приложения нет
   модели длительности/времени окончания ни у задачи, ни у напоминания,
   только момент начала — карточка не может "растягиваться" на
   длительность, см. Известные ограничения, п. 1): `PriorityDot` +
   `'time'` (моноширинным шрифтом) + название, левая рамка цвета
   `PRIORITY_COLORS[priority]`, зачёркнуто и приглушено, если задача
   выполнена. Клик открывает `TaskForm` этой задачи в боковой панели (п. 8)
5. Карточка напоминания со временем (`TimedReminderBlock`) — тот же
   принцип, что у карточки задачи: `ReminderPriorityIcon` + `'time'` +
   название, левая рамка `REMINDER_PRIORITY_COLORS[priority]`, фон
   `bg-destructive/10` для критичного / `bg-primary/10` для обычного —
   то же цветовое правило, что у плашек напоминаний в ячейке "Месяца"
   (`04.02`, п. 13.1). Не перетаскивается — напоминания нигде в
   приложении не перетаскиваются
6. **Перетаскивание задачи по времени** (новый тип драга этой фичи,
   `"calendar-task-time-move"`, отдельный от дневного
   `"calendar-task-move"` вида "Месяц"/строки "весь день", п. 7):
   1. Целью перетаскивания служит **вся колонка дня целиком**, не
      отдельная ячейка часа (`useDropTarget` на весь `TimelineDayColumn`,
      `HourGrid.tsx:107-119`) — 24 вложенных цели на одну колонку
      воспроизвели бы тот же баг двойного срабатывания, для которого в
      `useDropTarget` уже есть защита `monitor.didDrop()` (см.
      `04.01. Calendar Infrastructure-FRONTEND.md`, файлы)
   2. Y-координата отпускания (второй аргумент `onDrop` — координаты
      клика в пикселях, `useDropTarget`) переводится в снэпнутое время
      через `offsetPxToTime` — по умолчанию с шагом **15 минут**
      (`snapMinutes`, `timeOffset.ts:18-24`), потому что курсор мыши
      почти никогда не попадает ровно в конкретную минуту
   3. При отпускании вызывается `onRescheduleTask(taskId, day, time)` →
      `rescheduleTaskTime` провайдера (`04.01`, п. 7.5) — меняет сразу оба
      поля, `'dueDate'` **и** `'time'`, в отличие от перетаскивания на
      день в `AllDayRow`/"Месяце", которое трогает только `'dueDate'`
7. `AllDayRow` — перетаскивание задачи/цели на другой день переиспользует
   **те же** типы драга, что уже принимает ячейка "Месяца"
   (`"calendar-task-move"`/`"calendar-goal-move"`, см. `04.02`, п. 11) —
   элемент без времени можно перенести только на другой день, не на
   конкретную минуту
   1. Строка целиком скрывается (`return null`), если ни в одной из её
      колонок нет вообще никакого содержимого — ни задачи, ни
      напоминания, ни цели, ни привычки (`hasAnyContent`,
      `AllDayRow.tsx:43-44`) — пустая полоса не показывается
8. Боковая панель (справа от шкалы, `lg:sticky lg:top-4`, `280`px) —
   единая для Дня и Недели:
   1. Клик по любой карточке/чипу на шкале или в строке "весь день"
      открывает форму этого элемента инлайн в панели (`editing` состояние
      — `{kind, id}`) — тот же принцип "клик открывает форму на месте",
      что у панели дня "Месяца" и у Повестки дня
   2. Пока ничего не редактируется — панель показывает три кнопки
      быстрого добавления (Задача/Напоминание/Цель) под подписью "Quick
      add" (`calendar.quickAdd`). В отличие от Повестки дня (`04.03`,
      п. 5, где кнопок добавления нет вовсе) — День/Неделя задуманы как
      основная точка входа для добавления нового, а не только просмотра
   3. Новая задача — `'defaultDueDate'` = день колонки (День) / первый
      день недели, понедельник (Неделя, `firstDayKey`); новое напоминание
      — тот же день через `'lockedDate'`; новая цель — тот же день через
      `'defaultTargetDate'` — те же самые пропы форм, что уже использует
      панель дня "Месяца" (`04.02`, п. 9.1, 9.3), без изменений в самих
      формах
      1. На Неделе быстрое добавление всегда предлагает **первый** день
         недели независимо от того, какая колонка была видна на экране в
         момент клика по кнопке "Quick add" — панель не привязана к
         конкретному дню, привязаны только формы редактирования уже
         существующих элементов (у них дата/срок берутся из самого
         элемента, а не из позиции колонки)
9. Шапка недели (только вид "Неделя", `CalendarWeekView.tsx:84-101`) — ряд
   из 7 колонок над строкой "весь день": сокращённое название дня недели +
   число, сегодняшняя колонка выделена цветом (`text-primary`). Пустая
   ячейка слева (`w-12`) выравнивается с колонкой часовых подписей сетки
   под ней
10. И "День", и "Неделя" — компоненты уровня **страницы**
    (`src/pages/calendar/ui/`), не виджеты, потому что каждый компонует
    больше одного виджета-соседа (`calendar-timeline` + формы) — та же
    причина, что уже объяснена для всех пяти видов, см.
    `04.01. Calendar Infrastructure-FRONTEND.md`, п. 15

# Известные ограничения

1. В приложении нет модели длительности/времени окончания ни у задачи, ни
   у напоминания — только момент начала. Два элемента с одинаковым
   `'time'` в `HourGrid` визуально накладываются друг на друга, а не
   раскладываются в отдельные "дорожки" рядом — полноценная раскладка по
   дорожкам не делалась осознанно, непропорционально сложно для личного
   трекера такого масштаба (`HourGrid.tsx:163-167`)
2. Шаг снэпа при перетаскивании по времени (п. 6.2) фиксированный — 15
   минут, нельзя перетащить задачу ровно на, например, `14:07`
3. Привычки в строке "весь день" видны только числом (п. 2.2) — клик по
   этому числу ничего не делает; увидеть, какая именно привычка, можно
   только через панель дня "Месяца" (`04.02`, п. 9.4) или страницу
   `/habits`
