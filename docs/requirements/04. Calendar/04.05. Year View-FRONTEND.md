# 04.05. Year View [Frontend]

# Описание

12 мини-месяцев одного года в сетке карточек — самый простой и
"безопасный" из пяти видов: без перетаскивания, без часовой шкалы, без
собственной боковой панели, только просмотр и переход в вид "День" по
клику на конкретный день. Своей серверной логики нет.

С 2026-09-25 точка-индикатор "есть ли что-то в этот день" под числом дня
заменена на **кольцо прогресса выполнения месяца** рядом с названием
месяца (п. 3) — точка отвечала только "здесь что-то запланировано",
не показывая, что из этого уже сделано, и это признали недостаточно
информативным. Мини-сетка дней (числа, клик → переход на "День") не
затронута — осталась ровно такой же, просто без точки под числом.

# Функциональные требования

1. Сетка — 12 карточек месяцев текущего года (`Date(year.getFullYear(),
   i, 1)` для `i` от 0 до 11, `CalendarYear.tsx:38`), раскладка адаптивная
   (`grid-cols-2` на средних экранах, `grid-cols-3` на широких)
2. Каждая карточка месяца — заголовок с названием месяца (и, если
   `'total' > 0`, кольцо прогресса рядом, см. п. 3), строка сокращённых
   названий дней недели (первая буква каждого), затем сетка дней через
   `buildMonthGrid(month)` — та же функция и то же правило "неделя с
   понедельника, всегда кратно 7, с приглушёнными ведущими/хвостовыми
   днями соседних месяцев", что у вида "Месяц" (`04.02`, п. 1), просто в
   уменьшенном виде (`text-[10px]`, `aspect-square` ячейки)
3. **Кольцо прогресса выполнения месяца** (`ProgressRing`, `size-9`,
   `strokeWidth={4}`, цвет `var(--primary)`) — новое в этой фиче, заменило
   собой прежнюю точку-индикатор под числом дня (см. Описание). Показывает
   долю выполненного за месяц по трём сущностям сразу — задачи, цели,
   привычки (не напоминания — у них нет понятия "выполнено", см. Известные
   ограничения):
   1. Задачи — `getTaskMonthCompletionStats(tasks, month)`: считает задачи,
      у которых `'dueDate'` попадает в этот месяц; `'done'` — подмножество
      с `'completed' = true`. Недатированная задача не входит ни в `'done'`,
      ни в `'total'` — она не принадлежит никакому месяцу, это не то же
      самое, что "не выполнена"
   2. Цели — `getGoalMonthCompletionStats(goals, month)`: у `Goal` нет
      реального понятия "выполнена в месяце X" (нет даты завершения,
      `'progress'` — доля выполненных milestones, не дата) — это явный,
      осознанно упрощённый прокси, подтверждённый пользователем через
      `AskUserQuestion` при планировании, а не случайное допущение: цель
      засчитывается в месяц, если её `'targetDate'` попадает в этот месяц,
      и считается "выполненной" этого месяца, только если `'progress' ===
      100`. Бессрочная (`targetDate: null`) цель исключена целиком — не
      входит ни в `'done'`, ни в `'total'` ни для одного месяца
   3. Привычки — `getHabitMonthCompletionStats(habit, month, today)` (см.
      "Где находится" — перенесена из `habit-history`), просуммированная
      по всем привычкам прямо в `CalendarYear.tsx` (`reduce`, без
      отдельной агрегирующей lib-функции ради одного сложения) — то же
      самое правило "запланировано/выполнено по месяцу", что уже
      использует годовой вид Привычек (см. `03.02. Habit
      History-FRONTEND.md`, п. 10): считает только дни по `'activeDays'`
      привычки, для текущего месяца — только по сегодняшний день
      включительно, для месяца раньше `'habit.createdAt'` — не считает
      вовсе
   4. `'done'`/`'total'` карточки месяца — простая сумма троих:
      `done = задачи.done + цели.done + привычки.done`, `total =
      задачи.total + цели.total + привычки.scheduled`; `'percent' =
      Math.round(done / total * 100)`, `0` при `'total' === 0`
   5. Кольцо рендерится, только если `'total' > 0` для этого месяца —
      месяц без единой датированной задачи/цели/запланированного дня
      привычки не показывает кольцо вовсе (тот же дух, что у прежней
      точки — "нечего показывать" не то же самое, что "0% выполнено")
   6. Клик по кольцу открывает `Popover` (`side="top"`) с названием
      месяца и текстом "{done} из {total}" (`calendar.yearMonthSummary`)
      — единственное взаимодействие с кольцом, отметить что-либо отсюда
      нельзя
4. У каждого дня в мини-сетке — только число, без какого-либо
   индикатора содержимого (до 2026-09-25 была точка, см. Описание) —
   единственный способ узнать, что запланировано на конкретный день,
   остался прежним: клик и переход на "День" (п. 6)
5. У года нет ни перетаскивания, ни инлайн-редактирования, ни панели
   дня — единственное интерактивное действие с днём мини-сетки **клик**
   (`onClick={() => onSelectDay(date)}`)
6. Клик по любому дню (включая ведущие/хвостовые дни соседнего месяца)
   переключает `'anchorDate'` на этот день **и** переключает сам вид с
   "Год" на "День" (`goToDate(day); setView("day")`,
   `CalendarPage.tsx:230-233`) — в отличие от клика по дню соседнего
   месяца в виде "Месяц" (`04.02`, п. 2.1), который остаётся в том же
   виде и просто меняет месяц сетки, здесь клик всегда уводит на другой
   вид целиком
7. Сегодняшний день выделен закрашенным фоном (`bg-primary
   text-primary-foreground`) — визуально приоритетнее приглушения
   соседнего месяца: сегодняшний день физически не может быть ведущим/
   хвостовым, как и в "Месяце"
8. Дни соседнего месяца внутри мини-месяца по-прежнему кликабельны
   наравне с днями текущего месяца — просто приглушённым цветом
   (`text-muted-foreground/40`) — то же правило видимости "соседний
   месяц приглушён, но не заблокирован", что у "Месяца" (`04.02`, п. 2)
9. Виджет самодостаточен — не зависит ни от одного виджета-соседа
   (`calendar-grid`, `day-detail-panel`, `calendar-timeline`,
   `habit-history`), только от `shared/lib` и сущностей (см. "Где
   находится" — перенос `getHabitMonthCompletionStats` в этой же фиче
   специально сохранил это свойство), поэтому, в отличие от Дня/Недели/
   Месяца, остаётся легитимным **виджетом** (`src/widgets/calendar-year`),
   а не компонентом уровня страницы (см. `04.01. Calendar
   Infrastructure-FRONTEND.md`, п. 15)

# Известные ограничения

1. Напоминания не участвуют в кольце прогресса месяца (п. 3) — у
   `Reminder` есть `'completed'`, но кольцо посчитано только по
   задачам/целям/привычкам; осознанно не добавлено, не пробел — Reminder
   концептуально ближе к разовому уведомлению, чем к "выполняемой"
   сущности наравне с остальными тремя
2. Прокси-правило для цели (п. 3.2 — засчитывается по `'targetDate'`,
   "выполнена" только при `'progress' === 100`) — упрощение, не точная
   модель: цель, доведённая до 90% и просроченная в этом месяце, не
   считается ни выполненной, ни отдельно "просроченной" — просто входит
   в `'total'`, но не в `'done'`, наравне с целью, у которой прогресс 0%
