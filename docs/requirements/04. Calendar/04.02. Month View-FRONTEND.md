# 04.02. Month View [Frontend]

# Описание

Помесячная сетка дней с боковой панелью выбранного дня — самый первый и
до 2026-09-24 единственный вид календаря (см. `04.01. Calendar
Infrastructure-FRONTEND.md` про пять видов и общее состояние). Панель
дня — полноценный CRUD по всем четырём сущностям, которые умеет
показывать календарь: Задачи и Цели редактируются и перетаскиваются на
другой день прямо отсюда, Напоминания — полноценный CRUD без
перетаскивания, Привычки — только просмотр (см. п. 9). Своей серверной
логики нет — под капотом обычный `PATCH /api/tasks/:id`/
`PATCH /api/goals/:id`, меняющий только `'dueDate'`/`'targetDate'`, и
обычный CRUD напоминаний.

С 2026-09-25 (первый раунд правок того дня) ячейка дня в сетке перестала
показывать маркеры цели/привычки (иконка `Target` + иконка `Repeat` с
числом) — убраны по прямой обратной связи, что ряд без подписи непонятен
и плохо читается. Панель дня (п. 9) не затронута — цели и привычки там
по-прежнему видны полностью, по названию; перетаскивание цели на ячейку
сетки для смены `'targetDate'` тоже не затронуто (п. 11) — убран только
пассивный индикатор в самой ячейке.

Тем же днём, вторым, более крупным раундом — вид пережил полный редизайн
в стиле TickTick, по прямому референсу-скриншоту:

1. Сетка растянута на всю ширину страницы (п. 6) — фиксированная
   `lg:w-[640px]` и центрирование (`justify-center`) убраны, та же
   "заполнить доступную ширину" конвенция, что уже была у Дня/Недели
   (`04.04`). Боковая панель дня (`DayDetailPanel`) не изменилась — та же
   фиксированная 260px-ширина и та же `motion.div layout`-анимация
   сжатия/расширения ряда при открытии/закрытии, просто теперь у неё
   больше пространства для анимации
2. Ячейка дня показывает задачи не точками-индикаторами приоритета
   (до 3 штук, без счётчика переполнения), а полным стеком строк —
   чекбокс + пастельная заливка по цвету категории + название, без
   ограничения на число строк (п. 3) — тот же визуальный приём (пастель
   по категории, чекбокс `TaskToggleCheckbox`, серая заливка выполненной
   задачи), что одновременно получили Day/Week (`04.04`), реализован
   здесь по образцу того же раунда правок
3. Клик по строке задачи (не по чекбоксу, не по пустому месту ячейки)
   открывает тот же попап редактирования `CalendarItemPopover`, что уже
   используют День/Неделя (п. 3.3) — раньше у Месяца вообще не было
   входной точки для редактирования задачи кликом, только через панель
   дня. Клик по пустому месту ячейки по-прежнему открывает панель дня —
   не изменилось
4. Корневой элемент ячейки — `<div role="button" tabIndex={0}>`, не
   `<button>` (см. п. 3) — тот же переход, что уже был у блока задачи в
   `HourGrid.tsx` (`04.04`), по той же причине: ячейке нужны вложенные
   независимо кликабельные дети (чекбоксы, строки задач), что невалидно
   внутри нативной `<button>`
5. Рамка плашки напоминания в ячейке — по приоритету
   (`REMINDER_BORDER_COLORS`, та же константа, что у Дня/Недели), а не
   фон, как было раньше (п. 14) — для единообразия с остальным
   календарём

# Функциональные требования

1. Сетка календаря — 7 колонок (дни недели, сокращённо), список дней
   всегда кратен 7 (`buildMonthGrid`, `src/shared/lib/calendarGrid.ts`,
   возвращает плоский `MonthGridDay[]` — `{date: Date, isCurrentMonth:
   boolean}`). Неделя начинается с **понедельника**, не с воскресенья
   (`WEEKDAY_LABELS`, `src/shared/lib/i18n/dateLocale.ts` —
   `["Mo", "Tu", ..., "Su"]`/`["Пн", "Вт", ..., "Вс"]`)
   1. Ведущие дни (перед 1-м числом месяца) считаются со сдвигом
      `(getDay(monthStart) + 6) % 7` (`calendarGrid.ts:26`), а не
      напрямую `getDay()` — `date-fns`'s `getDay()` сам по себе
      воскресенье-первый (`0 = Sun`), сдвиг переводит его в
      понедельник-первый, синхронно с `WEEKDAY_LABELS`
   2. Хвостовые дни (после последнего числа месяца) добавляются, только
      чтобы дополнить сетку до полной недели (`trailingCount`,
      `calendarGrid.ts:31`) — в отличие от ведущих дней, которых всегда
      от 0 до 6, хвостовых может не быть вовсе, если месяц уже
      заканчивается на воскресенье
   3. И ведущие, и хвостовые дни — реальные числа соседнего месяца
      (`isCurrentMonth = false`), а не пустые ячейки-заглушки: сетка
      никогда не показывает пустое место
2. Ячейки дней соседнего месяца (`isCurrentMonth = false`) визуально
   приглушены — текст и рамка более блёклые
   (`text-muted-foreground/50 border-border/40` вместо
   `text-foreground border-border`, `CalendarDayCell.tsx:86-87`), но
   остаются кликабельными и являются валидной целью для перетаскивания
   задачи/цели (п. 12) — те же `onSelect`/`useDropTarget`, что и у ячеек
   текущего месяца
   1. Клик по такой ячейке переключает `'anchorDate'` на месяц этого дня
      (`goToDate(date)`, вызывается из `handleSelectDay` в
      `CalendarPage.tsx:121-124`) и одновременно выбирает этот день
      (`selectDay(day)`) — панель дня (п. 8) сразу открывается с
      содержимым выбранного дня, в новой раскладке сетки уже этого
      месяца
3. Каждая ячейка дня показывает число и, если на день есть задачи
   (`isTaskOnDay`, см. п. 5) — полный стек строк-задач под ним, одна
   строка на задачу, **без ограничения по количеству** (до 2026-09-25,
   второй раунд, было до 3 иконок-индикаторов приоритета без названий,
   без счётчика "+N" на переполнении — редизайн в стиле TickTick заменил
   это на построчный список):
   1. Строка — чекбокс (`TaskToggleCheckbox`, `size={11}`) + (если задан)
      `'time'` моноширинным шрифтом + название, пастельная заливка
      `${resolveCategoryColor(task.category, categories)}33` (та же
      функция и тот же приём альфа-суффикса, что у `HourGrid`, `04.04`)
   2. Клик по чекбоксу переключает выполнение задачи на месте, не
      открывая ничего — обёрнут в собственный `onPointerDown`/`onClick`
      со `stopPropagation()` (двойной, тот же паттерн, что уже применён
      для ручки ресайза в `HourGrid.tsx`), чтобы тап не долетал до
      обработчика клика по строке
   3. Клик по остальной части строки (не по чекбоксу) вызывает
      `onEditTask(task.id, rect)` — открывает `CalendarItemPopover` в
      режиме `edit-task`, заякоренный в `getBoundingClientRect()` этой
      строки (`CalendarMonthView.tsx`'s `openEditTask`). Своя
      `stopPropagation()` на строке — иначе клик долетел бы и до
      `onSelect` самой ячейки, открыв заодно панель дня
   4. Выполненная задача (`task.completed`) — заливка становится плоской
      нейтральной (`var(--muted)`, теряет цвет категории целиком),
      название — `line-through text-muted-foreground`. Строка задачи в
      Месяце вообще не показывает точку приоритета (в отличие от
      `HourGrid`, где она есть) — здесь только чекбокс, время и название
   5. Так как строк может быть сколько угодно, а каждая ячейка CSS-сетки
      растягивается до высоты самой высокой ячейки своей строки недели
      (обычное поведение CSS Grid, ничего специально не считается) — вся
      неделя визуально растёт под самый загруженный день, как в
      референсе TickTick. Раньше у ячейки был `min-h-[84px]`, слегка
      растущий только из-за плашек напоминаний (см. п. 15) — теперь
      высота полностью определяется содержимым, явного `min-h` для задач
      нет
   6. Напоминания отображаются отдельно от задач, текстом с рамкой по
      приоритету, — см. п. 14. Цели и привычки в самой ячейке с
      2026-09-25 (первый раунд) никак не отмечены (см. Описание) —
      увидеть, какая именно цель/привычка на этот день, можно только
      открыв панель дня (п. 9)
4. Сегодняшний день выделен визуально отдельно от выбранного дня и от
   приглушения соседнего месяца (сегодняшний день физически не может
   быть в ведущих/хвостовых днях). У каждой ячейки дня всегда видимая
   рамка (`border` + один из четырёх цветов рамки в зависимости от
   состояния — выбран/сегодня/текущий месяц/соседний месяц,
   `CalendarDayCell.tsx:95-103`) — не только при наведении
5. Задача принадлежит дню календаря (`isTaskOnDay`,
   `src/entities/task/lib/isTaskOnDay.ts`) по одному из двух правил:
   1. `'dueDate'` задачи совпадает с этим днём — обычный случай
   2. Либо, если у задачи `'dueDate' = null`: задача выполнена
      (`'completed' = true`) и `'completedAt'` приходится на этот день —
      задача без срока, отмеченная выполненной, появляется в календаре в
      день, когда её выполнили, хотя у неё никогда не было `'dueDate'`.
      Без этого правила такая задача пропадала бы отовсюду сразу после
      выполнения (см. правило видимости на странице Tasks, `01.01. Task
      CRUD-FRONTEND.md`, п. 11), но нигде не появлялась бы взамен
   3. Задача без `'dueDate'`, которая ещё **не** выполнена, не
      принадлежит ни одному дню — в сетке календаря и в панели дня не
      показывается вообще, пока не получит `'dueDate'` или не будет
      выполнена
   4. Это правило используется и для иконок-приоритетов в сетке месяца
      (п. 3), и для списка задач панели выбранного дня (`selectedTasks`,
      п. 9)
   5. Цель принадлежит дню (`isGoalDueOnDay`,
      `src/entities/goal/lib/isGoalDueOnDay.ts`) по единственному
      правилу — `'targetDate'` совпадает с этим днём. Проще, чем у
      задачи: у `Goal` нет `'completed'`/`'completedAt'`, поэтому
      бессрочная (`targetDate: null`) цель никогда не появляется на
      календаре, запасного правила видимости у неё нет
   6. Привычка "принадлежит" дню (`selectHabitsOnDay`,
      `src/entities/habit/lib/selectHabitsOnDay.ts`) через
      `'activeDays'.includes(day.getDay())` — по дню недели, а не по
      конкретной дате: у `Habit` нет собственного поля-даты, привычка
      появляется на **любом** дне календаря (в любом месяце, вперёд и
      назад), чей день недели входит в её расписание
6. Раскладка сетки и панели дня — флекс-ряд на всю ширину страницы
   (`CalendarMonthView.tsx`): сетка — `lg:flex-1` (забирает всё
   свободное пространство), и, если панель открыта, панель дня
   (`lg:w-[260px]`, фиксированная) — рядом. До 2026-09-25 сетка была
   фиксированной `lg:w-[640px]` внутри внешнего `flex justify-center`
   (центрирование всего блока на странице) — оба убраны в рамках
   редизайна Месяца (см. Описание): та же "заполнить доступную ширину,
   без центрирования" конвенция, что уже была у Дня/Недели (`04.04`)
   1. Панель дня (`DayDetailPanel`) не изменилась — фиксированная
      260px-ширина, как и раньше; когда панель открыта, сетка просто
      делит строку с ней (`flex-1` сжимается на 260px), когда закрыта —
      занимает всю ширину сама
   2. Сдвиг при открытии/закрытии панели по-прежнему анимирован через
      `layout`-проп `motion.div` (framer-motion/motion-react
      layout-animation, не изменился этим раундом) — сетка плавно
      сжимается/расширяется, а не скачет
7. Навигация по месяцам ("предыдущий"/"следующий"/"сегодня") — общая для
   всех видов инфраструктура провайдера, см. `04.01. Calendar
   Infrastructure-FRONTEND.md`, пп. 4-5, 10
8. Панель выбранного дня (справа от сетки) видна, только пока какой-то
   день выбран:
   1. По умолчанию, при открытии страницы Calendar, ни один день не
      выбран (`selectedDay = null`, `CalendarProvider.tsx:20`) — панель
      не рендерится вовсе, никакая ячейка сетки не подсвечена как
      выбранная (`isSelected` в `CalendarGrid.tsx` — `false`, пока
      `selectedDay` не задан)
   2. Клик по ячейке дня в сетке выбирает этот день (`selectDay(day)`)
      — под сеткой открывается панель с содержимым именно этого дня,
      отобранным по правилам пп. 5, 5.5, 5.6. Для ячейки соседнего
      месяца тот же клик ещё и переключает месяц сетки (п. 2.1)
   3. Кнопка закрытия (иконка `X`, lucide-react) в шапке панели, рядом с
      заголовком дня — клик снимает выбор дня (`selectDay(null)`),
      панель закрывается. Общей кнопки добавления в шапке панели нет —
      у каждой из четырёх секций свой собственный "+" (п. 9)
   4. Кнопка "Сегодня"/"К сегодня" (`04.01`, п. 10) при клике на этом
      виде, помимо возврата к текущему месяцу, выбирает сегодняшний день
      — если панель была закрыта, она открывается с содержимым
      сегодняшнего дня
   5. Появление и закрытие панели анимировано (`motion/react`:
      `AnimatePresence` + `motion.div` в `CalendarMonthView.tsx`,
      `initial={{opacity: 0, x: 12}}`, `animate={{opacity: 1, x: 0}}`,
      `exit={{opacity: 0, x: 12}}`, `transition={{duration: 0.2}}`) —
      лёгкое проявление с небольшим сдвигом при открытии, обратное при
      закрытии; сдвиг всего блока сетка+панель при этом отдельно
      анимирован через `layout` (п. 6.2)
   6. У `motion.div` панели намеренно нет `key`, привязанного к дате дня
      — переключение между двумя уже открытыми днями (клик на другую
      ячейку, когда панель уже открыта) просто меняет её содержимое, без
      повторного проигрывания анимации; анимация проигрывается только на
      переходах "ничего не выбрано ↔ выбран день" (открытие/закрытие)
9. Панель выбранного дня (`DayDetailPanel`) — четыре независимые секции,
   каждая со своим "+" в заголовке секции: "Задачи", "Напоминания",
   "Цели" (новая в этой фиче), "Привычки" (новая, без "+" — см. п. 9.4)
   1. "Задачи" — полноценный CRUD: добавить, отредактировать (форма
      разворачивается прямо в строке), отметить выполненной, удалить
      (без диалога подтверждения) — тот же `TaskForm`/провайдер, что и
      на странице Tasks. Кнопка добавления открывает `TaskForm` с проп
      `'defaultDueDate'` = выбранный день — подставляет только значение
      поля даты, сам тумблер `'hasDueDate'` остаётся выключенным по
      умолчанию (см. `01.01. Task CRUD-FRONTEND.md`, п. 5.2)
   2. "Напоминания" — полноценный CRUD (добавление инлайн `ReminderForm`
      с `'lockedDate'` = этот день, переключение выполнения, редактирование,
      удаление без подтверждения) — без изменений, см. `13.02. Reminder
      Entity-FRONTEND.md`
   3. "Цели" — полноценный CRUD, тот же паттерн, что у "Задач": добавить
      (`GoalForm` с `'defaultTargetDate'` = выбранный день, см. `02.01.
      Goal CRUD-FRONTEND.md`, п. 4.1), отредактировать (форма
      разворачивается в строке), удалить (диалог подтверждения — как и
      везде у Goal, см. `02.01. Goal CRUD-FRONTEND.md`). Строка цели
      (`DayGoalRow`) показывает название и `'progress'` в процентах,
      перетаскивается на другой день (п. 12)
   4. "Привычки" — **только чтение**: `DayHabitRow` показывает иконку и
      название привычки, без добавления/редактирования/удаления/
      перетаскивания. `'activeDays'` — повторяющийся паттерн по дням
      недели, а не запись на конкретную дату, поэтому "перенести/
      добавить одно вхождение" не имеет смысла для этой модели данных —
      управлять самой привычкой (переименовать, сменить
      цвет/расписание) можно только со страницы `/habits`
10. Пустое состояние каждой секции — "No tasks scheduled" (Задачи),
    "No reminders yet" (Напоминания, тот же текст, что у пустого
    состояния карточки напоминаний на Today), "No goals due" (Цели),
    "No habits scheduled" (Привычки) — ни одно не показывается, пока
    открыта инлайн-форма добавления этой секции
11. **Перетаскивание задачи/цели на другой день**: строка задачи/цели в
    панели дня — источник перетаскивания, ячейка дня в сетке — цель,
    включая ячейки соседнего месяца (п. 2) — `moveTaskToDay`/
    `moveGoalDeadline` работают одинаково для дня из любого месяца, им
    важна только дата
    1. Два независимых типа перетаскивания на одной и той же ячейке —
       `"calendar-task-move"` и `"calendar-goal-move"` (`CalendarDayCell.tsx:53-60`)
       — два отдельных экземпляра `useDropTarget`, скомпонованные на один
       DOM-узел через общий `ref`-колбэк, потому что `react-dnd`'s
       `useDrop` принимает только один `'type'` за вызов, а ячейка
       должна принимать и перетаскиваемую задачу, и перетаскиваемую цель
    2. При наведении перетаскиваемой задачи или цели на ячейку та
       подсвечивается кольцом (`isOver`, объединённый из обоих hook'ов)
    3. При отпускании задаче меняется только `'dueDate'` на день этой
       ячейки, цели — только `'targetDate'`, остальные поля не трогаются.
       Перетаскивание задачи всегда выставляет `'dueDate'` — задача,
       попавшая на день только благодаря `'completedAt'` (п. 5.2) и не
       имевшая своего `'dueDate'`, при таком переносе получает настоящий
       `'dueDate'` этого дня
12. Переупорядочивание задач/целей **внутри** панели одного дня не
    поддерживается — только перенос между днями
13. Ячейка дня, помимо строк-задач (п. 3), показывает напоминания этого
    дня прямо текстом, без клика/тапа (`selectRemindersOnDay`,
    `CalendarDayCell.tsx`) — плашка со временем (если задано) и текстом
    напоминания (усечённым, `truncate`), стиль вдохновлён TickTick.
    Видно максимум **2** плашки (`MAX_VISIBLE_REMINDERS`,
    `CalendarDayCell.tsx:14`), при переполнении — счётчик "+N" под ними
    (в отличие от строк задач, п. 3, у которых счётчика переполнения нет)
    1. С 2026-09-25 плашка различается по `'priority'` напоминания (см.
       `13.02. Reminder Entity-FRONTEND.md`) **рамкой**, не фоном —
       `REMINDER_BORDER_COLORS` (та же константа, что у Дня/Недели,
       `src/entities/reminder/model/reminder.ts`), обычное (`"normal"`)
       получает жёлтую рамку, критичное (`"critical"`) — красную; фон
       плашки нейтральный (`bg-card`), не цветной — до этого раунда
       различие кодировалось фоном (красноватый `bg-destructive/15
       text-destructive` для критичного, нейтральный `bg-primary/10
       text-primary` для обычного). Для выбранной ячейки (`isSelected`)
       различие рамок не показывается — все плашки получают одинаковый
       полупрозрачный светлый фон (`bg-primary-foreground/20
       text-primary-foreground border-primary-foreground/40`), чтобы
       оставаться читаемыми на закрашенном фоне выбранного дня
    2. Плашка, перед временем/текстом, несёт ещё и собственную иконку
       приоритета (`ReminderPriorityIcon`, `size={8}`), показывается для
       **обоих** уровней приоритета, не только критичного. Цвет иконки —
       `REMINDER_BORDER_COLORS[reminder.priority]` (не выбранная ячейка)
       или `colorOverride="currentColor"` (выбранная ячейка), чтобы
       совпасть по цвету с текстом плашки на закрашенном фоне
14. Ячейка дня не строго квадратная (не `aspect-square`) и с 2026-09-25
    без явного `min-h` — высота полностью определяется содержимым
    (плашки напоминаний, п. 13, и стек строк задач, п. 3.5), растёт
    вместе с ним через обычное поведение CSS Grid (каждая ячейка строки
    растягивается до высоты самой высокой в этой же строке недели). До
    2026-09-25 у ячейки был `min-h-[84px]`, растущий только из-за плашек
    напоминаний — с появлением построчного списка задач без ограничения
    по числу строк отдельный `min-h` стал не нужен, содержимое и так
    почти всегда выше прежнего минимума
15. Клик по строке напоминания на карточке Today (`ReminderRow`, см.
    `13.02. Reminder Entity-FRONTEND.md`) открывает Calendar через
    one-shot query-параметр `?date=YYYY-MM-DD` (без `?view=`, поэтому
    попадает на вид по умолчанию провайдера — с 2026-09-25 это "День",
    не "Месяц", см. `04.01. Calendar Infrastructure-FRONTEND.md`, п. 1.1,
    14.1) — до 2026-09-25 этот же клик открывал "Месяц" на этот день
16. Переупорядочивание напоминаний (drag-and-drop) не поддерживается
    нигде — ни в сетке, ни в панели дня. Список всегда отсортирован по
    `'date'`, затем по `'time'` (см. `13.02. Reminder Entity-BACKEND.md`)

# Известные ограничения

1. Ячейка сетки с 2026-09-25 не даёт вообще никакой подсказки о том, что
   в этот день есть цель/привычка, пока панель дня не открыта (см.
   Описание) — до этого хотя бы присутствие/отсутствие маркера
   намекало на это, ценой неясности, что именно маркер означает
2. Секция "Привычки" панели дня целиком read-only (п. 9.4) — нет способа
   добавить/убрать привычку на конкретный день из календаря вообще, это
   осознанное следствие модели данных (`'activeDays'` — расписание, а не
   список дат), не пробел в реализации
3. Стек строк задач в ячейке (п. 3) не ограничен по числу — день с
   десятками задач растягивает ячейку (и всю неделю сетки вместе с ней)
   на соответствующую высоту, без счётчика "+N" и без внутреннего
   скролла ячейки. Осознанный выбор в пользу референса TickTick, не
   недосмотр — при типичной для персонального трекера нагрузке
   (единицы задач на день) это не проблема
