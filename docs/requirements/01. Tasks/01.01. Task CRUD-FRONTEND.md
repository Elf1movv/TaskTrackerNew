# 01.01. Task CRUD [Frontend]

# Описание

Редакция ветки product-logic-redesign, 2026-10-02. Задача — самостоятельное
дело по категории с необязательным сроком и целью. Главная показывает
заметки; календарь хранит самостоятельные планы или интервалы со ссылкой
на эту задачу. Указание срока не создаёт календарную запись.

# Функциональные требования

1. Создавать и редактировать заголовок, описание, категорию, приоритет,
   необязательный срок `'dueDate'` и цель `'goalId'`. Пустое название запрещено.
2. Срок выбирать с точностью до дня. Время работы задавать через
   «Запланировать», отдельно от срока. Приоритет переключается одной
   кнопкой. Компоненты и оформление соответствуют существующему приложению.
3. По умолчанию показывать активные задачи. Фильтры «Все / Активные / Готово»,
   категория и «Все / Без срока / Со сроком» применяются совместно.
4. В «Готово» доступна вся история, а не только сегодняшний день. По 10
   выполненных записей на страницу; сортировка по `'completedAt'` убыванию,
   затем `'id'`. Для старой записи без даты выполнения используется
   `'updatedAt'`. Невыполненные задачи этим лимитом не ограничены.
5. Смена фильтров сбрасывает страницу; возвращение выполненной задачи в
   активные корректирует последнюю страницу. Следующая страница заменяет
   предыдущую, а не дописывает строки снизу.
6. «Запланировать» создаёт отдельный CalendarPlan с `'taskId'`. Можно
   создать несколько интервалов. В задаче доступны ссылки на каждый,
   включая «Отложено». Срок не меняется при переносе любого интервала.
7. Выполнение в задаче, цели или связанном плане меняет одну исходную
   задачу. Течение времени не завершает задачу. Будущие интервалы остаются;
   «Убрать будущие интервалы» требует подтверждения и сохраняет прошлые.
8. «Напомнить» создаёт явно связанное напоминание с выбранной датой/временем.
9. Удаление задачи требует AlertDialog с количеством будущих/отложенных
   планов. Прошлая история сохраняется; будущие связанные планы и сигналы
   удаляются. Ошибки сохранения показываются через общий механизм toast.
10. Ссылка `/tasks?task=<id>` открывает исходную задачу, включая выполненную.
11. Неразобранные прежние записи доступны через общий блок перехода и не
    смешиваются с новой активной коллекцией. Правила перехода описаны в
    [плане](../../PRODUCT_LOGIC_IMPLEMENTATION_PLAN.md).
