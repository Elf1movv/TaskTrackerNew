# 01.01. Task CRUD [Frontend]

# Описание

Редакция второй итерации 2026-10-10, обновлена в итерации 3.1
(2026-11-08). Общие дела живут во вкладке задач. На странице Tasks
остался один фильтр — по категории; активные задачи упорядочены по сроку,
выполненные свёрнуты в отдельный раздел с постраничным просмотром.

# Где находится (файлы)

- `src/features/task-form/ui/TaskForm.tsx` — форма задачи (add + edit)
- `src/widgets/task-board/ui/TaskBoard.tsx` — страница списка: шапка со
  счётчиками, фильтр-чипы категорий, активные задачи, раздел
  «Выполненные»
- `src/widgets/task-board/ui/components/TaskRow.tsx` — строка задачи,
  перетаскивание только для недатированных активных
- `src/pages/tasks/connectors/TasksProvider.tsx` — фильтр категории,
  сортировка, страницы выполненных
- `src/pages/tasks/lib/filterTasks.ts` — `filterTasks()` (категория),
  `sortActiveTasks()`
- `src/shared/lib/dnd/useDragReorder.ts` — опция `'canDrag'`
- `src/shared/ui/pager.tsx` — общий переключатель страниц `Pager`
- `src/entities/task` — сущность и `TaskProvider`
- `src/pages/tasks` — страница, deep link `?task=<id>`

# Функциональные требования

1. Заголовок, описание, категория, приоритет, необязательный срок dueDate.
   Срок не создаёт план календаря. Выбора цели и кнопки планирования нет.
2. Фильтр списка — только фильтр-чипы категорий («Все» + по одной на
   категорию, см. [01.02. Categories-FRONTEND](./01.02.%20Categories-FRONTEND.md),
   п. 5). С 2026-11-08 (итерация 3.1) фильтры статуса
   («Все/Активные/Готово») и срока («Все/Без даты/С датой») удалены
   вместе с типами `StatusFilter`/`TaskDateFilter`. `filterTasks(tasks,
   categoryFilter)` оставляет задачи выбранной категории
   (`filterTasks.ts:5-7`). До 2026-11-08 она также скрывала неразобранные
   старые записи (`'legacyPending'`); с 2026-11-08 (выпускная уборка) поле
   удалено, скрытых задач нет.
3. Активные задачи (`'completed' === false`) показываются сразу, без
   лимита, и сортируются `sortActiveTasks` (`filterTasks.ts:13-20`):
   1. Сначала задачи со сроком — по возрастанию `'dueDate'`; при
      одинаковом сроке — в ручном порядке (`'order'` с сервера,
      сортировка стабильная)
   2. Затем задачи без срока — в ручном порядке
4. Перетаскиванием можно переставлять **только активные задачи без
   срока** (`TaskRow.tsx:16-23`): у них тип перетаскивания `"task"` и
   курсор-«рука». Задачи со сроком и выполненные получают тип
   `"task-fixed"` и `'canDrag' = false` в `useDragReorder` — их нельзя
   взять, и на них ничего не переставляется, потому что их место задаётся
   сроком или временем выполнения.
5. Пустое состояние, если активных задач нет: «Нет активных задач»
   (`tasks.noActiveTasks`), при выбранной категории — «Нет активных
   задач в категории X» (`tasks.noTasksIn`) (`TaskBoard.tsx:309-321`).
6. Выполненные задачи — отдельный раздел под активными
   (`TaskBoard.tsx:323-351`):
   1. Показывается, только если в выбранной категории есть выполненные
   2. Заголовок-кнопка «Выполненные (N)» (`tasks.completedSection`) со
      стрелкой; по умолчанию раздел **свёрнут** (локальный `useState`,
      не запоминается)
   3. В раскрытом разделе — 10 задач на страницу, `'completedAt'` по
      убыванию, затем `'id'`. Для старой записи без `'completedAt'`
      используется `'updatedAt'`
   4. Под списком — общий `Pager` (← «Назад» / «Страница N из M» /
      → «Далее»), при одной странице не показывается
   5. Смена категории сбрасывает страницу на первую. Если страница
      перестала существовать (задача возвращена в активные или удалена),
      показывается последняя существующая (`TasksProvider.tsx`)
7. Счётчик в шапке «осталось: N · выполнено: M» считается по всем
   задачам без учёта фильтра категории; «выполнено» — только за сегодня
   (`isCompletedToday`).
8. Галочка меняет только эту задачу. Удаление удаляет только задачу и
   с 2026-11-09 (аудит П10) сначала спрашивает подтверждение (`ConfirmAction`:
   «Удалить задачу?» / «Задача «{title}» будет удалена. Это действие нельзя
   отменить.», красная кнопка «Удалить»).
   Ни цель, ни календарные планы, ни заметки от этих действий не меняются.
9. /tasks?task=<id> открывает редактирование, включая выполненные записи.
10. Старые записи — обычные задачи. Во второй итерации неразобранные
    старые записи (`'legacyPending'`) были скрыты до выбора назначения в
    панели «Разобрать прежние записи». С 2026-11-08 (выпускная уборка)
    панель (`src/widgets/legacy-transition`) удалена: все существующие
    задачи видны в списке как обычные, их копии лежат только в служебном
    журнале `LegacyTransition` (см. 01.01 Backend, п. 8).
11. Ошибки сохранения показываются toast.
12. Срок задачи с 2026-11-08 виден в календаре маркером (Месяц, панель дня,
    Список), но планом не становится — см. 04.02 и 04.03.
13. `TaskForm` (`src/features/task-form/ui/TaskForm.tsx`) для новой задачи
    принимает необязательные пропы:
    1. `'draft'` — `{ title, description }`, подставляются в поля новой
       задачи. Остальные поля — обычные значения по умолчанию: приоритет
       `"medium"`, первая категория (или `'lockedCategory'`), срок выключен
       без `'defaultDueDate'`
    2. `'onCreate'` — заменяет `addTask`: форма передаёт поля задачи
       (`'completed' = false`) и ждёт `Promise<boolean>`. `false` — форма
       остаётся открытой; `true` — закрывается. Пока ожидание идёт, кнопка
       сохранения заблокирована и повторное сохранение (в т.ч. Enter) игнорируется
    3. При редактировании существующей `'task'` оба пропа игнорируются
    4. Используется переносом заметки в задачи (см. 05.01, п. 11)
14. Кнопка «Добавить задачу» при выбранной категории открывает форму с
    `'lockedCategory'` = этой категории (`TaskBoard.tsx:150-153`).

## Изменения 2026-11-09 (аудит, пачка 4)

Тип `Task` без `time` / `endTime`; `TaskForm` их не отправляет.
