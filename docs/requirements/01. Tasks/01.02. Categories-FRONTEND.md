# 01.02. Categories [Frontend]

# Описание

Список категорий, которые предлагает пикер `'category'` в форме задачи
(`TaskForm`) и вкладки-фильтры категорий на странице Tasks
(`TaskBoard`). До этой фичи список был жёстко зашит в код
(`TASK_CATEGORIES` в `entities/task/model/task.ts`, теперь удалён) —
теперь это отдельная сущность `Category`, персистентная на бэкенде.
`Task.category` при этом остался обычной строкой (не внешний ключ на
`Category`, см. `01.02. Categories-BACKEND.md`).

# Где находится (файлы)

- `src/entities/category/model/category.ts` — тип `Category`
- `src/entities/category/model/CategoryProvider.tsx` — `categories`,
  `addCategory`
- `src/entities/category/api/categoryRepository.ts` — REST-репозиторий,
  тот же `createRestRepository`, что у задач/целей/привычек
- `src/shared/lib/storage/usePersistedCollection.ts` — общий механизм
  оптимистичных обновлений (см. `01.01. Task CRUD-FRONTEND.md`)
- `src/features/task-form/ui/TaskForm.tsx` — пикер категории + инлайновое
  создание новой категории
- `src/widgets/task-board/ui/TaskBoard.tsx` — вкладки-фильтры категорий

# Функциональные требования

1. `useCategories()` отдаёт `'categories'` (список, загружается при
   монтировании `CategoryProvider`) и `addCategory(name)`
2. Список категорий — общий на всё приложение, без привязки к
   конкретной задаче. Фронтенд использует только чтение списка и
   создание новой категории — переименование, удаление и
   переупорядочивание категорий на бэкенде реализованы (см.
   `01.02. Categories-BACKEND.md`), но в UI для них пока нет входных
   точек — сознательно оставлено вне текущего объёма
3. Создание новой категории (`addCategory`):
   1. Доступно только из формы задачи — пункт `"+ New category"` в
      пикере категории (см. `01.01. Task CRUD-FRONTEND.md`, п. 4.2)
   2. Генерирует `'id'` на клиенте (`generateId()`), как и у задач/целей/
      привычек, чтобы можно было сразу оптимистично работать с новой
      категорией, не дожидаясь ответа сервера
   3. Имя не проверяется на дубликат на фронтенде до отправки — если имя
      уже существует, запрос на сервер завершится ошибкой (см. "Известные
      ограничения" в `01.02. Categories-BACKEND.md`), и `usePersistedCollection`
      откатит оптимистичное добавление, показав `toast.error`
4. Вкладки-фильтры категорий на странице Tasks (`TaskBoard`) — список
   строится как `["all", ...categories.map(c => c.name)]`, порядок
   вкладок соответствует порядку `'categories'` (то есть `'order'` с
   бэкенда), вкладка `"all"` всегда первая и не входит в саму сущность
   `Category`
5. Пикер категории в `TaskForm` показывает те же имена в том же порядке
