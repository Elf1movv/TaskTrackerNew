# 01.02. Categories [Frontend]

# Описание

Список категорий, которые предлагает пикер `'category'` в форме задачи
(`TaskForm`) и вкладки-фильтры категорий на странице Tasks
(`TaskBoard`). До этой фичи список был жёстко зашит в код
(`TASK_CATEGORIES` в `entities/task/model/task.ts`, теперь удалён) —
теперь это отдельная сущность `Category`, персистентная на бэкенде и
привязанная к конкретному пользователю (`'userId'`, см.
`01.02. Categories-BACKEND.md`). `Task.category` при этом остался
обычной строкой (не внешний ключ на `Category`, см.
`01.02. Categories-BACKEND.md`). Создание и удаление категории — обе
операции живут на странице Tasks (`TaskBoard`), в строке фильтров
категорий; форма задачи (`TaskForm`) только выбирает из уже
существующих категорий.

С 2026-09-25 у категории есть `'color'` (обязательное поле, см.
`01.02. Categories-BACKEND.md`) — тот же паттерн пикера-палитры
(`PALETTE_COLORS`, `src/shared/lib/colors.ts`), что уже был у цвета
цели/привычки. Цвет категории двигает не только `TaskBoard` — он
теперь красит пастельной заливкой блок задачи этой категории в
календаре (Day/Week/Month, см. `04.02. Month View-FRONTEND.md`,
`04.04. Day & Week Timeline-FRONTEND.md`) через
`resolveCategoryColor(task.category, categories)`, заменивший там
прежний единый цвет по типу сущности.

# Где находится (файлы)

- `src/entities/category/model/category.ts` — тип `Category` (включая
  `'color'`)
- `src/entities/category/model/CategoryProvider.tsx` — `categories`,
  `addCategory(name, color)`, `updateCategory(id, patch)`,
  `deleteCategory`
- `src/entities/category/model/categoryContext.ts` — контекст,
  `useCategories()`
- `src/entities/category/lib/resolveCategoryColor.ts` — новое в этой
  фиче: `resolveCategoryColor(categoryName, categories)`, находит цвет
  категории по имени задачи `'category'`, используется календарём (см.
  Описание), не самой этой фичей
- `src/shared/lib/colors.ts` — `PALETTE_COLORS` (общая палитра пикеров
  цвета — цель/привычка/категория) и `CATEGORY_FALLBACK_COLOR` (новое в
  этой фиче — нейтральный серый `#8a8a8a`, вне `PALETTE_COLORS`, чтобы
  никогда не совпасть с настоящим цветом категории; отдаётся
  `resolveCategoryColor`, когда `'category'` задачи — пустая строка или
  имя, не совпавшее ни с одной существующей категорией — оба случая
  неотличимы друг от друга на модели данных и обрабатываются одинаково)
- `src/entities/category/api/categoryRepository.ts` — REST-репозиторий,
  тот же `createRestRepository`, что у задач/целей/привычек
- `src/shared/lib/storage/usePersistedCollection.ts` — общий механизм
  оптимистичных обновлений (см. `01.01. Task CRUD-FRONTEND.md`)
- `src/features/task-form/ui/TaskForm.tsx` — только пикер категории
  (выбор из существующих, без создания новой)
- `src/widgets/task-board/ui/TaskBoard.tsx` — вкладки-фильтры категорий,
  удаление категории, инлайновое создание новой категории (с цветом, см.
  п. 3.3) и попап смены цвета уже существующей категории (см. п. 6)

# Функциональные требования

1. `useCategories()` отдаёт `'categories'` (список, загружается при
   монтировании `CategoryProvider`), `addCategory(name, color)`,
   `updateCategory(id, patch)` (новое в этой фиче — раньше `update` из
   `usePersistedCollection` был получен, но никуда не пробрасывался, см.
   `src/entities/category/model/CategoryProvider.tsx`) и
   `deleteCategory(id)`
2. Список категорий — свой у каждого пользователя (см.
   `01.02. Categories-BACKEND.md`, "ленивый" сид 4 стандартных категорий
   при первом запросе), не общий на всё приложение, как было раньше.
   Фронтенд использует чтение списка, создание, смену цвета и удаление
   категории — переименование и переупорядочивание категорий на бэкенде
   реализованы (см. `01.02. Categories-BACKEND.md`), но в UI для них
   пока нет входных точек — сознательно оставлено вне текущего объёма
3. Создание новой категории (`addCategory`), `src/widgets/task-board/ui/TaskBoard.tsx`:
   1. Точка входа — кнопка "+ Добавить категорию" (`tasks.addCategory`),
      последним элементом в строке фильтров категорий на странице Tasks.
      Раньше это делалось из формы задачи (пункт `"+ New category"` в
      пикере `TaskForm`) — эта возможность там убрана, вся логика
      (`isAddingCategory`/`newCategoryName`/`handleCreateCategory`)
      переехала в `TaskBoard`
   2. Клик по кнопке открывает инлайновую форму на том же месте
      (текстовое поле + строка цветных свотчей `PALETTE_COLORS` + кнопки
      "Добавить"/"Отмена"): Enter или клик "Добавить" вызывает
      `addCategory(name, color)`; Escape или клик "Отмена" закрывает
      форму без изменений. Пустое (после `.trim()`) имя не создаёт
      категорию. Цвет — локальный `useState(PALETTE_COLORS[0])`
      (`newCategoryColor`), по умолчанию первый цвет палитры, клик по
      свотчу меняет выбор до отправки формы, тот же визуальный паттерн
      (обводка выбранного кружка), что у пикера цвета цели/привычки
   3. Генерирует `'id'` на клиенте (`generateId()`), как и у задач/целей/
      привычек, чтобы можно было сразу оптимистично работать с новой
      категорией, не дожидаясь ответа сервера
   4. Имя не проверяется на дубликат на фронтенде до отправки — если имя
      уже существует **у этого же пользователя**, сервер отвечает `409
      { error: "Category name already exists" }` (см.
      `01.02. Categories-BACKEND.md`), и `usePersistedCollection`
      откатит оптимистичное добавление, показав `toast.error`
4. Удаление категории (`deleteCategory`), `src/widgets/task-board/ui/TaskBoard.tsx`:
   1. Точка входа — маленькая кнопка "×", появляющаяся при наведении
      (`group-hover`, `opacity-0 group-hover:opacity-100`) на
      вкладку-фильтр категории на странице Tasks, не в самом пикере формы
      (`TaskForm`). Radix `Select`/`SelectItem` плохо уживается со
      вложенной интерактивной кнопкой внутри пункта списка, поэтому
      удаление сделано именно в строке фильтров — обычные `<button>`,
      без Radix-обёртки
   2. Клик по "×" не удаляет категорию сразу — открывает `AlertDialog` с
      подтверждением (`categoryPendingDelete` в состоянии `TaskBoard`,
      `src/widgets/task-board/ui/TaskBoard.tsx:58,209-241`), тот же
      компонент, что и другие деструктивные подтверждения в проекте
   3. Заголовок и текст диалога зависят от того, есть ли у категории
      задачи (`taskCountInPendingCategory` — подсчёт `allTasks`, у
      которых `'category' === categoryPendingDelete.name`):
      1. Если задач нет — нейтральный заголовок/текст
         (`tasks.deleteCategoryTitle`/`tasks.deleteCategoryBody`), кнопка
         подтверждения — обычного стиля
      2. Если задачи есть — заголовок и текст предупреждают о количестве
         задач, которые тоже будут удалены
         (`tasks.deleteCategoryTitleWithTasks`/
         `tasks.deleteCategoryBodyWithTasks`, с `'count'`), кнопка
         подтверждения — `variant="destructive"` (красная)
   4. Подтверждение (`handleConfirmDeleteCategory`) вызывает
      `deleteCategory(id)`, затем, если удаляемая категория была активным
      фильтром (`categoryFilter === c.name`), сбрасывает фильтр на
      `"all"`, затем вызывает `refreshTasks()` — сервер каскадно удаляет
      на бэкенде все задачи с этой категорией в рамках `DELETE
      /api/categories/:id` (см. `01.02. Categories-BACKEND.md`, "Методы",
      п. 5.3), но локальная коллекция задач (`TaskProvider`) не узнаёт об
      этом сама по себе — `refreshTasks()` перечитывает список задач с
      сервера, чтобы убрать удалённые из UI
   5. Escape, клик вне диалога или кнопка "Отмена" закрывают диалог без
      изменений
5. Вкладки-фильтры категорий на странице Tasks (`TaskBoard`) — список
   строится как `["all", ...categories.map(c => c.name)]`, порядок
   вкладок соответствует порядку `'categories'` (то есть `'order'` с
   бэкенда), вкладка `"all"` всегда первая и не входит в саму сущность
   `Category`. Кнопка "+ Добавить категорию" из п. 3.1 идёт последней в
   этой же строке, после всех вкладок категорий
6. Смена цвета уже существующей категории (`updateCategory`), новое в
   этой фиче, `src/widgets/task-board/ui/TaskBoard.tsx`:
   1. Каждая вкладка-категория несёт маленький цветной кружок-свотч
      (`size-2.5 rounded-full`, `backgroundColor: c.color`) перед именем
      — клик по нему (`e.stopPropagation()`, чтобы не сработал заодно
      клик по самой вкладке-фильтру) открывает `Popover` с той же сеткой
      `PALETTE_COLORS`, что и при создании (п. 3.2)
   2. Клик по любому цвету в поповере сразу вызывает
      `updateCategory(c.id, { color })` — без подтверждения, без кнопки
      "Сохранить", изменение применяется мгновенно. Тот же принцип
      переиспользования простого попап-пикера, что и у смены цвета
      блока привычек (`HabitGroup.color`)
   3. Выбранный на данный момент цвет обведён контрастной обводкой
      (`outline: 2px solid var(--foreground)`) — тот же визуальный язык,
      что у выбора цвета при создании (п. 3.2) и у пикеров цвета
      цели/привычки
7. Пикер категории в `TaskForm` показывает те же имена в том же
   порядке, но без кнопки удаления, без пункта создания новой категории
   и без пикера цвета — см. п. 4.1, п. 3.1, п. 6
