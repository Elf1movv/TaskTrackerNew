# 11.01. Welcome Screens [Frontend]

# Описание

Два взаимоисключающих экрана-приветствия, показываемые сразу после
входа на `/today` — единственную точку приземления после логина:
модалка со списком фич при самом первом входе (сразу после подтверждения
почты) и короткая исчезающая анимация "с возвращением" при обычном
повторном входе. Различие определяется цепочкой query-параметров через
регистрацию → подтверждение почты → вход, не отдельным полем в БД.

# Где находится (файлы)

- `src/widgets/onboarding/ui/WelcomeModal.tsx` — модалка первого входа
- `src/widgets/onboarding/ui/WelcomeBackGreeting.tsx` — анимация
  повторного входа
- `src/widgets/onboarding/index.ts` — публичный API виджета
- `src/pages/auth/ui/RegisterPage.tsx` — передаёт `callbackURL` при
  регистрации
- `src/pages/auth/ui/LoginPage.tsx` — читает `'verified'`, выбирает
  адрес редиректа после входа
- `src/pages/today/ui/TodayPage.tsx` — читает query-параметры, монтирует
  нужный виджет, зачищает URL
- `src/shared/lib/i18n/dictionaries/en.ts` / `ru.ts` — ключи
  `onboarding.*`

# Функциональные требования

## Определение "первый вход" (регистрация → подтверждение почты → вход)

1. `RegisterPage` передаёт `callbackURL: "{origin}/login?verified=1"` в
   `authClient.signUp.email(...)` (`RegisterPage.tsx:31`). Better Auth
   сам подставляет эту ссылку в письмо подтверждения почты и делает
   HTTP-редирект браузера на неё после успешного перехода по ссылке
   подтверждения (подтверждено чтением исходников Better Auth, см.
   `LEARNING.md`) — код этого репозитория ссылку подтверждения не строит
   и редирект не обрабатывает сам
2. `LoginPage` читает query-параметр `'verified'` через `useSearchParams()`
   при сабмите формы входа. Если `'verified' === "1"` — это трактуется
   как первый вход сразу после подтверждения почты
3. При успешном входе `LoginPage` делает полный переход браузера
   (`window.location.href`, не `navigate()` — та же причина, что у
   обычного логин-редиректа, см.
   [09.01. Account Access-FRONTEND](../09.%20Authentication/09.01.%20Account%20Access-FRONTEND.md),
   "Известные ограничения", п. 1):
   1. Если `'verified' === "1"` → `/today?firstLogin=1`
   2. Иначе → `/today?welcomeBack=1`
4. Признак "первый вход" нигде не хранится как отдельное поле в БД —
   целиком выводится из цепочки query-параметров (см. "Известные
   ограничения")

## `TodayPage` — выбор и закрытие виджета

5. `TodayPageContent` читает `'firstLogin'`/`'welcomeBack'` из
   `useSearchParams()` при рендере
6. Если `'firstLogin' === "1"` — рендерится `<WelcomeModal open
   onClose={clearGreetingParam} />`
7. Если `'welcomeBack' === "1"` — рендерится `<WelcomeBackGreeting
   onDone={clearGreetingParam} />`
8. `clearGreetingParam` удаляет оба параметра из URL через
   `setSearchParams(..., { replace: true })` сразу после закрытия
   соответствующего виджета — обновление страницы (F5) после этого уже
   не показывает приветствие повторно
9. Ни один из двух виджетов не подключён больше нигде в приложении —
   `/today` единственная точка приземления после входа, оба параметра
   выставляются только `LoginPage`

## `WelcomeModal`

10. Модалка (`Dialog`) закрывается тремя равнозначными способами — кнопкой
    "Let's start", кликом вне модалки и `Escape` (`onOpenChange={next =>
    !next && onClose()}`) — все три вызывают один и тот же `onClose`
11. Показывает заголовок, вводный текст и список из 4 фиксированных
    пунктов (иконка + текст, `FEATURES` в `WelcomeModal.tsx`): Tasks,
    Goals, Habits, Calendar — порядок фиксирован в коде, не зависит от
    того, чем реально пользуется аккаунт

## `WelcomeBackGreeting`

12. При монтировании один раз выбирается случайный текст из 7 вариантов
    (`onboarding.back.1`…`onboarding.back.7`) через `useState(() =>
    ...)` — выбор не пересчитывается при повторных рендерах компонента
13. Приветствие видно 2.2 секунды (`setTimeout`), после чего запускается
    exit-анимация (`framer-motion`/`AnimatePresence`); `onDone`
    (= `clearGreetingParam`) вызывается из `onExitComplete` — то есть
    после того, как exit-анимация фактически завершилась, а не сразу по
    истечении таймера
14. Контейнер приветствия имеет `pointer-events-none` — пока оно
    показывается, клики по интерфейсу под ним не блокируются

# Известные ограничения

1. Признак первого входа существует только как query-параметр в цепочке
   редиректов, не в БД: если пользователь вручную откроет старую ссылку
   подтверждения `.../login?verified=1` (например, повторно перейдя по
   ссылке из письма) и войдёт, `WelcomeModal` покажется снова, даже если
   это далеко не первый его вход в приложение
2. Симметрично — если по какой-то причине `LoginPage` будет открыт без
   `'verified'` сразу после регистрации (например, пользователь вручную
   стёр этот параметр из адресной строки перед входом), будет показана
   `WelcomeBackGreeting`, а не `WelcomeModal`, несмотря на то что вход
   первый
3. Тексты обоих экранов (заголовок и 4 пункта `WelcomeModal`, все 7
   вариантов `WelcomeBackGreeting`) переведены через словари `i18n`
   (`useLanguage()`/`t()`)
