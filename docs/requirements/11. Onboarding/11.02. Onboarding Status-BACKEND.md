- `server/src/validation/onboarding.ts` — схема тела `PUT` (`zod`)
- `server/prisma/schema.prisma` — поля `User.onboardingStatus`,

- `server/prisma/migrations/20261110120000_onboarding_status/migration.sql`
- `server/src/app.ts` — монтирование `/api/me` с `express.json({ limit: "256kb" })`

# Схема данных

1. `User.onboardingStatus` — `String?`: `null` = онбординг ещё не пройден и
   не пропущен (его нужно показать), `"completed"` или `"skipped"`.
   Допустимые значения проверяются `zod`, не Postgres-enum'ом — как
   `Task.priority`
2. `User.onboardingAt` — `DateTime?`, когда статус последний раз менялся
3. Миграция `20261110120000_onboarding_status` добавляет обе колонки и
   ставит **всем уже существующим** пользователям `'onboardingStatus' =
   "completed"`, `'onboardingAt' = CURRENT_TIMESTAMP`: онбординг видят
   только те, кто зарегистрировался после выпуска. Миграция только
   добавляет колонки — код предыдущего выпуска с новой схемой работает
4. Хранится на сервере, а не в браузере, чтобы пройденный онбординг не
   всплывал заново на другом устройстве или в другом браузере (решение
   владельца 2026-11-09)

# Методы

1. При получении `GET /api/me/onboarding` сервер должен:
   1. Проверить сессию (`requireAuth`), иначе `401`
   2. Прочитать `'onboardingStatus'` текущего пользователя
   3. Вернуть `200 { "status": "completed" | "skipped" | null }`

2. При получении `PUT /api/me/onboarding` сервер должен:
   1. Проверить сессию (`requireAuth`), иначе `401`
   2. Проверить тело: `'status'` должен быть `"completed" | "skipped"`;
      иначе `400 { "error": "Invalid onboarding status" }`. Вернуть
      статус в `null` через API нельзя
   3. Записать `'onboardingStatus'` и `'onboardingAt' = now()` текущему
      пользователю
   4. Вернуть `200 { "status": <новый статус> }`

# Известные ограничения

1. Метод не проверяет переходы: `"completed"` можно сменить на
   `"skipped"`. Клиент этого не делает (пропуск повторного прохождения
   статус не трогает, см. 11.01, п. 23)
2. Под будущую продуктовую аналитику (BACKLOG, «Минимальная продуктовая
   аналитика») пара `'onboardingStatus'` + `'onboardingAt'` уже отвечает
   на вопрос «прошёл или пропустил и когда» запросом к базе
