# 09. Authentication

Аккаунты пользователей: регистрация по почте/паролю, обязательное
подтверждение почты перед первым входом, восстановление пароля через
письмо, выход. Реализовано через **Better Auth**, самостоятельно
хостится — данные сессий/пользователей лежат в той же PostgreSQL, что и
остальные данные приложения (не сторонний auth-сервис).

С этой фичи все данные приложения (`Task`, `Goal`, `Habit`, `Category`)
стали привязаны к конкретному пользователю (`'userId'`) — это не
отдельная фича, а изменение поведения существующих CRUD-эндпоинтов,
описанное прямо в соответствующих backend-доках:
[01.01. Task CRUD-BACKEND](./01.%20Tasks/01.01.%20Task%20CRUD-BACKEND.md),
[01.02. Categories-BACKEND](./01.%20Tasks/01.02.%20Categories-BACKEND.md),
[02.01. Goal CRUD-BACKEND](./02.%20Goals/02.01.%20Goal%20CRUD-BACKEND.md),
[03.01. Habit CRUD-BACKEND](./03.%20Habits/03.01.%20Habit%20CRUD-BACKEND.md).

- [09.01. Account Access-FRONTEND](./09.%20Authentication/09.01.%20Account%20Access-FRONTEND.md)
