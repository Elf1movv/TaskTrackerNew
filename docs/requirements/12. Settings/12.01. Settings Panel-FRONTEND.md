# 12.01. Settings Panel [Frontend]

# Описание

Кнопка-шестерёнка, закреплённая в правом верхнем углу каждой защищённой
страницы (десктоп и мобильные ширины одинаково), открывающая выезжающую
справа панель (`Sheet`) с двухуровневым меню. Корневой экран — список из
двух навигационных строк ("Аккаунт", "Внешний вид") и кнопки выхода;
клик по строке переводит на соответствующий экран. Это единственное
место в приложении, где можно сменить язык/тему или выйти из аккаунта —
раньше эти элементы дублировались в сайдбаре, который не виден на
мобильных ширинах (`hidden md:flex`), так что мобильные пользователи не
имели способа выйти или сменить язык/тему; переключатели и кнопка
выхода перенесены сюда из сайдбара (см.
[06.01. Sidebar Stats-FRONTEND](../06.%20Navigation/06.01.%20Sidebar%20Stats-FRONTEND.md),
"Известные ограничения").

# Функциональные требования

## Кнопка и панель

1. Кнопка-шестерёнка (иконка `Settings` из `lucide-react`) зафиксирована
   в правом верхнем углу (`fixed top-4 right-4 md:top-6 md:right-6`) —
   смонтирована в `RootLayout`, то есть видна на каждом маршруте,
   защищённом сессией (`/today`, `/tasks`, `/goals`, `/calendar`), но не
   на `/login`/`/register`/`/forgot-password`/`/reset-password`, которые
   рендерятся вне `RootLayout` (см.
   [09.01. Account Access-FRONTEND](../09.%20Authentication/09.01.%20Account%20Access-FRONTEND.md))
2. Клик по кнопке открывает `Sheet` со стороны `right` — затемняющий
   оверлей и панель шириной 3/4 экрана на мобильных ширинах,
   `sm:max-w-sm` на десктопе, с анимацией выезда/задвигания
   (`slide-in-from-right`/`slide-out-to-right`)
3. `Sheet` — управляемый (`open`/`onOpenChange` через состояние `open` в
   `SettingsPanel`), не неуправляемый: закрытие (крестик, клик по
   оверлею, Escape) сбрасывает `view` обратно в `null` (`handleOpenChange`,
   `SettingsPanel.tsx:19-24`) — при повторном открытии панель всегда
   показывает корневой список, а не тот под-экран, на котором её закрыли
4. Заголовок в шапке панели зависит от текущего экрана (`view`):
   1. `view === null` (корень) — "Настройки" (`settings.title`)
   2. `view === "account"` — "Аккаунт" (`settings.account.title`)
   3. `view === "appearance"` — "Внешний вид" (`settings.menu.appearance`)
5. На экранах "Аккаунт" и "Внешний вид" (`view !== null`) слева от
   заголовка в шапке появляется стрелка назад (`ArrowLeft` из
   `lucide-react`) — клик по ней вызывает `setView(null)` и возвращает к
   корневому списку. На корневом экране стрелки нет

## Корневой список (`SettingsMenu`)

6. Две навигационные строки, каждая — иконка, подпись, шеврон `ChevronRight`
   справа:
   1. "Аккаунт" (иконка `User`) — `onNavigate("account")`
   2. "Внешний вид" (иконка `Palette`) — `onNavigate("appearance")`
7. Под строками, после горизонтального разделителя — кнопка "Выйти"
   (`sidebar.logout`, иконка `LogOut`) — это не строка навигации, а
   немедленное действие: клик сразу вызывает `signOut()`
   (`SettingsMenu.tsx:46`), без подтверждающего диалога и без перехода
   на под-экран. Логаут не требует `window.location.href` — панель уже
   смонтирована внутри работающего `RootLayout`, и `useSession()` там
   сам реагирует на сброс сессии обычной client-side реактивностью (та
   же логика, что раньше была в `SidebarNav`, см.
   [09.01. Account Access-FRONTEND](../09.%20Authentication/09.01.%20Account%20Access-FRONTEND.md),
   "Выход")

## Экран "Аккаунт" (`AccountSection`)

8. Заголовок секции отдельно не выводится — заголовок "Аккаунт" уже
   показан в шапке панели (см. п. 4.2), сам компонент начинается сразу
   с почты
9. Почта — только для чтения, показывает значение пропа `email`
   (`session.user.email`, переданное из `RootLayout`) — секция не
   делает собственного запроса за данными пользователя
10. Пароль показан замаскированным (`••••••••` — литеральные точки, не
    настоящие символы: сервер никогда не присылает клиенту пароль в
    открытом виде, см.
    [09.01. Account Access-BACKEND](../09.%20Authentication/09.01.%20Account%20Access-BACKEND.md),
    "Схема данных") рядом с кнопкой "Изменить"
    (`settings.account.changePassword`)
11. Клик "Изменить" разворачивает инлайн-форму на месте замаскированной
    строки (`isChanging` в состоянии `AccountSection`) — вместо неё
    появляются поля "Текущий пароль", "Новый пароль", чекбокс "Выйти из
    остальных устройств" и кнопки "Сохранить"/"Отмена"

## Форма смены пароля

12. Оба поля пароля — `PasswordInput`: поле ввода плюс кнопка-иконка
    (глаз/перечёркнутый глаз) справа внутри поля, переключающая `type`
    между `"password"`/`"text"` только для этого конкретного поля —
    раскрывает то, что сейчас набрано в нём, а не хранимый пароль
    (сервер его не присылает, см. п. 10)
13. "Текущий пароль" — автофокус при открытии формы, без ограничения
    длины и без `PasswordRequirementsHint` (это уже существующий пароль,
    а не новый, который нужно проверять на соответствие правилам)
14. "Новый пароль" — `maxLength={MAX_PASSWORD_LENGTH}` (128), под полем
    — `PasswordRequirementsHint`, тот же компонент и те же два правила
    (длина 8–128, буква и цифра), что на регистрации (см.
    `09.01. Account Access-FRONTEND.md`, п. 5)
15. Чекбокс "Выйти из остальных устройств" (`revokeOtherSessions`) — не
    отмечен по умолчанию
16. Кнопка "Сохранить" задизейблена, пока `'currentPassword'` пуст или
    `meetsPasswordRequirements('newPassword')` не возвращает `true`, а
    также пока идёт отправка (`isSubmitting`)
17. Отправка (`handleSubmit`):
    1. Дополнительно не выполняется, если условия п. 16 не выполнены
       (защита сверх задизейбленной кнопки)
    2. Вызывает `changePassword({ currentPassword, newPassword,
       revokeOtherSessions })` (`authClient.changePassword`, см.
       [09.01. Account Access-BACKEND](../09.%20Authentication/09.01.%20Account%20Access-BACKEND.md),
       `POST /api/auth/change-password`)
    3. При успехе — `toast.success(t("settings.account.success"))`
       ("Пароль изменён"), форма сворачивается обратно к
       замаскированному виду, поля `currentPassword`/`newPassword`/
       `revokeOtherSessions` сбрасываются
    4. При ошибке — `toast.error(translateAuthError(error, t,
       "auth.error.generic"))`, тот же переводчик кодов ошибок, что у
       регистрации и входа (неверный текущий пароль → `error.code =
       "INVALID_PASSWORD"` → `auth.error.wrongCurrentPassword`, "Неверный
       текущий пароль."); форма остаётся открытой, введённые значения не
       теряются
18. Кнопка "Отмена" вызывает тот же сброс формы (`resetForm`), что и
    успешная отправка — сворачивает форму обратно к замаскированному
    виду, ничего не отправляя на сервер

## Экран "Внешний вид" (`AppearanceSection`)

19. Содержит только два уже существующих переключателя, друг под
    другом: `LanguageToggle` (EN/RU) и `ThemeToggle` (светлая/тёмная
    тема) — сами переключатели не изменились, изменилось только их
    расположение (были в подвале десктопного сайдбара, теперь здесь; см.
    [06.01. Sidebar Stats-FRONTEND](../06.%20Navigation/06.01.%20Sidebar%20Stats-FRONTEND.md))

# Известные ограничения

1. Панель содержит две навигируемые секции ("Аккаунт", "Внешний вид");
   компонент спроектирован для роста — добавить третью секцию означает
   добавить строку в `SettingsMenu`, новый `SettingsView` и новый `case`
   в `SettingsPanel.tsx`
2. Почта и имя пользователя — только для чтения; изменить их через эту
   панель нельзя, единственное реальное действие на экране "Аккаунт" —
   смена пароля (и опционально выход из остальных устройств заодно с
   ней)
3. Кнопка "Выйти" на корневом экране — единственное место в приложении,
   где можно выйти из аккаунта (десктопный сайдбар больше не дублирует
   её, см.
   [06.01. Sidebar Stats-FRONTEND](../06.%20Navigation/06.01.%20Sidebar%20Stats-FRONTEND.md),
   "Известные ограничения")
