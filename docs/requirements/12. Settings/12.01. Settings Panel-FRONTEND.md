# 12.01. Settings Panel [Frontend]

# Описание

Кнопка-шестерёнка, закреплённая в правом верхнем углу каждой защищённой
страницы (десктоп и мобильные ширины одинаково), открывающая выезжающую
справа панель (`Sheet`). Наверху панели — три вкладки: «Аккаунт», «Внешний
вид», «Уведомления» (с 2026-11-12; до этого — корневой список из двух строк
с переходом на под-экран). Внизу панели — кнопки «Установить приложение»,
«Пройти знакомство заново» и «Выйти». Это единственное место в приложении,
где можно сменить язык/тему, включить уведомления или выйти из аккаунта —
раньше часть этих элементов была в сайдбаре, который не виден на мобильных
ширинах (`hidden md:flex`), см.
[06.01. Sidebar Stats-FRONTEND](../06.%20Navigation/06.01.%20Sidebar%20Stats-FRONTEND.md),
"Известные ограничения".

# Функциональные требования

## Кнопка и панель

1. Кнопка-шестерёнка (иконка `Settings` из `lucide-react`) зафиксирована
   в правом верхнем углу (`fixed top-4 right-4 md:top-6 md:right-6`;
   на ширинах 640–1279 px `<main>` получает `sm:max-xl:pt-10`, чтобы
   кнопки «Добавить …» в шапках страниц не уходили под шестерёнку и
   колокольчик; уведомления-тосты — в правом **нижнем** углу, на телефоне
   над нижним меню, с 2026-11-09) —
   смонтирована в `RootLayout`, то есть видна на каждом маршруте,
   защищённом сессией (`/today`, `/tasks`, `/goals`, `/calendar`), но не
   на `/login`/`/register`/`/forgot-password`/`/reset-password`, которые
   рендерятся вне `RootLayout` (см.
   [09.01. Account Access-FRONTEND](../09.%20Authentication/09.01.%20Account%20Access-FRONTEND.md))
2. Клик по кнопке открывает `Sheet` со стороны `right` — затемняющий
   оверлей и панель шириной 3/4 экрана на мобильных ширинах,
   `sm:max-w-sm` на десктопе, с анимацией выезда/задвигания
   (`slide-in-from-right`/`slide-out-to-right`)
3. `Sheet` — управляемый (`open`/`onOpenChange` через состояние `open` в
   `SettingsPanel`). Открытая вкладка (`view`) при закрытии **не**
   сбрасывается: при повторном открытии панель показывает ту же вкладку
   (по умолчанию «Аккаунт»)

## Вкладки (с 2026-11-12)

4. Под заголовком «Настройки» — `ToggleGroup` из трёх вкладок с иконками:
   «Аккаунт» (`User`), «Внешний вид» (`Palette`), «Уведомления» (`Bell`).
   Все три подписи не помещаются, поэтому подписана только открытая
   вкладка — она шире (`flex-[3]`) с плавной сменой ширины, остальные —
   только иконка с `aria-label`
5. Содержимое вкладки — под ними, с прокруткой внутри панели:
   `AccountSection`, `AppearanceSection` или `NotificationsSection`

## Кнопки внизу панели

6. «Установить приложение» (`InstallAppButton`) — видна, только если
   браузер умеет устанавливать сайт как приложение и оно ещё не
   установлено (см. 15.01)
7. «Пройти знакомство заново» (с 2026-11-10, `settings.restartOnboarding`,
   иконка `Compass`): закрывает панель и открывает онбординг с первого
   шага. Колбэк `onRestartOnboarding` передаёт `RootLayout` (виджет не
   может импортировать другой виджет); на самой шестерёнке —
   `data-onboarding="settings-gear"`, её подсвечивает подсказка после
   первого пропуска онбординга (см.
   [11.01. Onboarding Flow-FRONTEND](../11.%20Onboarding/11.01.%20Onboarding%20Flow-FRONTEND.md), п. 22)
8. «Выйти» (`sidebar.logout`, иконка `LogOut`) — клик сразу вызывает
   `signOut()`, без подтверждения. Логаут не требует
   `window.location.href` — `useSession()` в `RootLayout` сам реагирует на
   сброс сессии (см.
   [09.01. Account Access-FRONTEND](../09.%20Authentication/09.01.%20Account%20Access-FRONTEND.md),
   "Выход")

## Вкладка "Аккаунт" (`AccountSection`)

9. Заголовок секции отдельно не выводится — открытая вкладка уже
   подписана (п. 4), сам компонент начинается сразу с почты
10. Почта — только для чтения, показывает значение пропа `email`
   (`session.user.email`, переданное из `RootLayout`) — секция не
   делает собственного запроса за данными пользователя
11. Пароль показан замаскированным (`••••••••` — литеральные точки, не
    настоящие символы: сервер никогда не присылает клиенту пароль в
    открытом виде, см.
    [09.01. Account Access-BACKEND](../09.%20Authentication/09.01.%20Account%20Access-BACKEND.md),
    "Схема данных") рядом с кнопкой "Изменить"
    (`settings.account.changePassword`)
12. Клик "Изменить" разворачивает инлайн-форму на месте замаскированной
    строки (`isChanging` в состоянии `AccountSection`) — вместо неё
    появляются поля "Текущий пароль", "Новый пароль", чекбокс "Выйти из
    остальных устройств" и кнопки "Сохранить"/"Отмена"

## Форма смены пароля

13. Оба поля пароля — `PasswordInput`: поле ввода плюс кнопка-иконка
    (глаз/перечёркнутый глаз) справа внутри поля, переключающая `type`
    между `"password"`/`"text"` только для этого конкретного поля —
    раскрывает то, что сейчас набрано в нём, а не хранимый пароль
    (сервер его не присылает, см. п. 10)
14. "Текущий пароль" — автофокус при открытии формы, без ограничения
    длины и без `PasswordRequirementsHint` (это уже существующий пароль,
    а не новый, который нужно проверять на соответствие правилам)
15. "Новый пароль" — `maxLength={MAX_PASSWORD_LENGTH}` (128), под полем
    — `PasswordRequirementsHint`, тот же компонент и те же два правила
    (длина 8–128, буква и цифра), что на регистрации (см.
    `09.01. Account Access-FRONTEND.md`, п. 5)
16. Чекбокс "Выйти из остальных устройств" (`revokeOtherSessions`) — не
    отмечен по умолчанию
17. Кнопка "Сохранить" задизейблена, пока `'currentPassword'` пуст или
    `meetsPasswordRequirements('newPassword')` не возвращает `true`, а
    также пока идёт отправка (`isSubmitting`)
18. Отправка (`handleSubmit`):
    1. Дополнительно не выполняется, если условия п. 16 не выполнены
       (защита сверх задизейбленной кнопки)
    2. Вызывает `changePassword({ currentPassword, newPassword,
       revokeOtherSessions })` (`authClient.changePassword`, см.
       [09.01. Account Access-BACKEND](../09.%20Authentication/09.01.%20Account%20Access-BACKEND.md),
       `POST /api/auth/change-password`)
    3. При успехе — `toast.success(t("settings.account.success"))`
       ("Пароль изменён"), форма сворачивается обратно к
       замаскированному виду, поля `currentPassword`/`newPassword`/
       `revokeOtherSessions` сбрасываются
    4. При ошибке — `toast.error(translateAuthError(error, t,
       "auth.error.generic"))`, тот же переводчик кодов ошибок, что у
       регистрации и входа (неверный текущий пароль → `error.code =
       "INVALID_PASSWORD"` → `auth.error.wrongCurrentPassword`, "Неверный
       текущий пароль."); форма остаётся открытой, введённые значения не
       теряются
19. Кнопка "Отмена" вызывает тот же сброс формы (`resetForm`), что и
    успешная отправка — сворачивает форму обратно к замаскированному
    виду, ничего не отправляя на сервер

## Вкладка "Внешний вид" (`AppearanceSection`)

20. Содержит только два уже существующих переключателя, друг под
    другом: `LanguageToggle` (EN/RU) и `ThemeToggle` (светлая/тёмная
    тема) — сами переключатели не изменились, изменилось только их
    расположение (были в подвале десктопного сайдбара, теперь здесь; см.
    [06.01. Sidebar Stats-FRONTEND](../06.%20Navigation/06.01.%20Sidebar%20Stats-FRONTEND.md))

## Вкладка "Уведомления" (с 2026-11-12)

21. Включение push-уведомлений, время утренних уведомлений, утренняя
    сводка, тестовое уведомление — см.
    [13.05. Push Notifications-FRONTEND](../13.%20Reminders/13.05.%20Push%20Notifications-FRONTEND.md),
    п. 7–9

# Известные ограничения

1. Новая вкладка = новый пункт в `TABS` и новый `SettingsView` в
   `SettingsPanel.tsx`. Четвёртая вкладка уже не поместится по ширине —
   понадобится другой вид (например, снова список)
2. Почта и имя пользователя — только для чтения; изменить их через эту
   панель нельзя, единственное реальное действие на вкладке "Аккаунт" —
   смена пароля (и опционально выход из остальных устройств заодно с
   ней)
3. Кнопка "Выйти" — единственное место в приложении, где можно выйти из
   аккаунта (десктопный сайдбар больше не дублирует её, см.
   [06.01. Sidebar Stats-FRONTEND](../06.%20Navigation/06.01.%20Sidebar%20Stats-FRONTEND.md),
   "Известные ограничения")
