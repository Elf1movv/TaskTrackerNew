# 06.01. Sidebar Stats [Frontend]

# Описание

Левый сайдбар с навигацией между страницами, компактным графиком
недельной активности и тремя текстовыми счётчиками под ним. Это
**глобальный** элемент интерфейса — виден на всех страницах приложения
одновременно, не только на Today, несмотря на то, что все три текстовых
счётчика показывают именно "на сегодня" (график — исключение, он
показывает срез за последние 7 дней, см. п. 7-11 ниже). Раньше в подвале
сайдбара, под счётчиками, были ещё переключатели языка/темы и кнопка
выхода — они удалены отсюда и перенесены в панель настроек (доступна на
любой ширине экрана, в отличие от сайдбара — см. п. 13 ниже и
[12.01. Settings Panel-FRONTEND](../../12.%20Settings/12.01.%20Settings%20Panel-FRONTEND.md)).

# Где находится (файлы)

- `src/widgets/navigation/ui/SidebarNav.tsx` — сам сайдбар, вычисление
  счётчиков и данных графика, подпись-название приложения
- `src/widgets/navigation/model/navItems.ts` — список пунктов меню
  (`labelKey` — ключ словаря i18n, не строка)
- `src/widgets/navigation/ui/MobileNav.tsx` — тот же список пунктов меню
  в нижней панели на мобильных экранах
- `src/shared/ui/weekly-activity-chart.tsx` — компонент `WeeklyActivityChart`
  (компактный sparkline/area-график), используется только из `SidebarNav`
- `src/shared/lib/date.ts` — `getLastNDays(n, referenceDate)`, строит
  скользящее окно из `n` дней, заканчивающееся на `referenceDate`
- `src/entities/task/lib/getTaskCompletionsByDay.ts` — считает
  выполненные задачи по дням для графика
- `src/entities/habit/lib/getHabitCompletionsByDay.ts` — считает
  выполненные привычки по дням для графика
- `src/shared/lib/i18n` — см.
  [07. Localization](../../07.%20Localization.md)

# Функциональные требования

1. Сайдбар скрыт на мобильных экранах (`hidden md:flex`) — виден только
   от планшетного размера и шире. На мобильных вместо него —
   `MobileNav`, нижняя панель с теми же пунктами меню (без счётчиков и
   без переключателей языка/темы)
2. В шапке сайдбара — статичная надпись `"MyTracker"` (название
   приложения, `SidebarNav.tsx:50`) и текущие месяц/год. Надпись не
   переведена на RU — как и категории, это не текст интерфейса, а
   название бренда (см. `07. Localization.md`)
3. Пункты меню — ссылки на Today/Tasks/Goals/Habits/Calendar
   (`NAV_ITEMS`, `navItems.ts`), в этом порядке, активный пункт
   подсвечен по текущему маршруту. "Привычки" (`/habits`, иконка
   `Repeat`) добавлен между Goals и Calendar 2026-09-21 — до этого
   отдельного маршрута для привычек не было, они были видны только на
   Today. Today (`HabitTrackerGrid`) по-прежнему показывает привычки, но
   только назначенные на сегодняшний день недели (см. `05.01. Today
   Dashboard-FRONTEND.md`); страница Habits (`/habits`) — единственное
   место с историей **всех** привычек и их полным управлением, см.
   `03.02. Habit History-FRONTEND.md`
4. Счётчик `'Tasks done'` — считает **только задачи, у которых
   `'dueDate'` равен сегодняшнему дню** (`isTaskOnDay(task, today)`,
   `SidebarNav.tsx:23`, тот же helper, что уже используют виды календаря),
   в формате "выполнено / всего". Задачи без срока или с другим сроком в
   этот счётчик не входят. *(Раньше счётчик брал `selectTodayTasks(tasks)`
   и фильтровал результат по `'completed' === true` — с 2026-09-25
   `selectTodayTasks` переписан на "все невыполненные задачи" (см. "05.
   Today"), поэтому такая фильтрация была структурно невозможна и
   счётчик всегда показывал `0 / X`. Исправлено переходом на
   `isTaskOnDay`, который не зависит от `selectTodayTasks` и восстанавливает
   изначальный смысл счётчика — "выполнено из тех, что должны были быть
   сделаны сегодня".)*
5. Счётчик `'Habits'` — "количество привычек, отмеченных сегодня /
   общее количество привычек" — не связан с streak (серией дней подряд),
   считает только сегодняшний день
6. Счётчик `'Active goals'` — **вводит в заблуждение по названию**: это
   просто общее количество целей (`goals.length`), без какой-либо
   фильтрации по прогрессу. Цель со `'progress' = 100` тоже учитывается
   в этом числе
7. Над тремя текстовыми счётчиками — компактный график недельной
   активности (`WeeklyActivityChart`), подписанный ключом
   `sidebar.statChartLabel` ("Активность за неделю" / "Weekly activity").
   Один график на два вида данных сразу: по каждому из последних 7 дней —
   сумма "выполненных задач в этот день" + "выполненных привычек в этот
   день" в одно число (`taskCounts[i] + habitCounts[i]`,
   `SidebarNav.tsx:37-44`)
8. Окно графика — **скользящие последние 7 дней, заканчивающиеся
   сегодня** (`getLastNDays(7, new Date())`,
   `src/shared/lib/date.ts:30`), а не текущая календарная неделя
   пн-вс. Это осознанно другая логика, чем у `getPeriodDays("week", …)`
   в `widgets/habit-history` (см. "03.02. Habit History-FRONTEND") — та
   привязана к календарной неделе и может быть всего одной точкой в
   понедельник, здесь же всегда ровно 7 точек. Подписи точек по оси X —
   двухбуквенные сокращения дня недели (`getWeekdayLabels`, те же, что в
   сетке "Месяца"), а не числа месяца
9. Данные для графика по задачам — `getTaskCompletionsByDay(tasks, days)`
   (`src/entities/task/lib/getTaskCompletionsByDay.ts`): считает по
   `'completedAt'` (когда задача реально была выполнена), а не по
   `'dueDate'` — задача с просроченным `'dueDate'`, выполненная сегодня,
   попадает в столбец сегодняшнего дня, а не дня дедлайна
10. Данные для графика по привычкам —
    `getHabitCompletionsByDay(habits, days)`
    (`src/entities/habit/lib/getHabitCompletionsByDay.ts`): засчитывает
    привычку в конкретный день только если этот день недели входит в
    `'activeDays'` **и** дата есть в `'completedDates'` — привычка, не
    запланированная на этот день недели, не может быть "выполнена" в нём,
    даже если в данных случайно есть отметка на эту дату
11. Цели **намеренно не входят** в график — у `Goal.progress` нет
    исторических данных по времени в базе (только текущее значение), а
    "правдивый" тренд по датам построить не из чего. Не пробел, осознанное
    решение
12. Визуально график — компактный вариант "area" из
    `widgets/habit-history/ui/HabitHistoryChart.tsx` (та же заливка
    градиентом через `var(--primary)`, та же тема CSS-переменных), но без
    оси Y (нет места под подписи в колонке сайдбара ~220px, значение видно
    в тултипе при наведении) и высотой `h-16` (64px). На `XAxis` явно
    задан `interval={0}`, чтобы отрисовались все 7 подписей дней — без
    этого recharts автоматически пропускает часть тиков (тот же паттерн
    квирка есть и в уже существующем `HabitHistoryChart.tsx`, который эту
    правку не получил — не затронут в рамках этой фичи)
13. Все три текстовых счётчика и график пересчитываются реактивно при
    любом изменении соответствующих данных — отдельного запроса к
    серверу для них нет, используются те же `tasks`/`goals`/`habits` из
    общих провайдеров
14. Сайдбар заканчивается сразу после блока счётчиков — подвала с
    переключателями языка/темы и кнопкой выхода больше нет
    (`SidebarNav.tsx` не импортирует `LanguageToggle`/`ThemeToggle`/
    `signOut`/`Button`/`LogOut`). Эти элементы теперь в панели настроек,
    доступной на любой ширине экрана через кнопку-шестерёнку — см.
    [12.01. Settings Panel-FRONTEND](../../12.%20Settings/12.01.%20Settings%20Panel-FRONTEND.md)

# Известные ограничения

1. До этого изменения переключатели языка/темы и кнопка выхода жили в
   подвале десктопного сайдбара, который скрыт на мобильных ширинах
   (`hidden md:flex`, см. п. 1) — то есть мобильные пользователи не
   имели способа сменить язык/тему или выйти из аккаунта. Консолидация
   в единственное место (панель настроек) устранила это ограничение, не
   продублировав элементы в двух местах сразу
