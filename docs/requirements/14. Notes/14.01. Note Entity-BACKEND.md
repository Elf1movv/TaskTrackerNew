# 14.01. Note Entity [Backend]

1. Все `/api/notes` требуют сессию; `'userId'` берётся из неё.
2. `GET /api/notes` возвращает только записи владельца по `'order'`.
3. `POST /api/notes` проверяет UUID, непустое название до 500 символов,
   описание до 50000 символов, реальную дату `'showFrom'` или null и
   `'archivedAt'` или null. Запись добавляется в конец списка.
4. `PATCH /api/notes/:id` принимает `'patch'` и `'expectedUpdatedAt'`.
   Чужая запись — 404, несовпавшая версия — 409 с `'current'`.
5. `PATCH /api/notes/reorder` меняет только порядок; блокировки берутся
   по отсортированным id, клиент получает новые версии.
6. `DELETE /api/notes/:id` ограничен владельцем. Основное пользовательское
   действие интерфейса — архивирование с возможностью восстановления.

# Известные ограничения

Дата появления не запускает фоновые push. Отдельного раздела Notes
в боковом меню и постоянного преобразования заметки в задачу нет.
