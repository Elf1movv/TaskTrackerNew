# 10.01. Feedback Widget [Frontend]

# Описание

Тонкая плашка "оставить отзыв", смонтированная под контентом каждой
защищённой страницы приложения, и модалка с формой (текст + опциональный
скриншот), которую она открывает. Временная фича на период беты — не
постоянная часть продукта (см. "Известные ограничения").

# Где находится (файлы)

- `src/widgets/feedback/ui/FeedbackBanner.tsx` — плашка, флаг
  `FEEDBACK_BETA_ENABLED`
- `src/widgets/feedback/ui/FeedbackDialog.tsx` — модалка с формой
- `src/shared/ui/toggle-group.tsx` — переиспользуемый сегментированный
  тумблер (`ToggleGroup`/`ToggleGroupItem`), тот же компонент, что и в
  других местах приложения (см. п. 4 ниже), используется для выбора
  типа отзыва
- `src/widgets/feedback/index.ts` — публичный API виджета
- `src/app/layouts/RootLayout.tsx` — точка монтирования плашки
- `src/shared/lib/i18n/dictionaries/en.ts` / `ru.ts` — ключи `feedback.*`

# Функциональные требования

## Видимость плашки

1. `FeedbackBanner` рендерится только если константа
   `FEEDBACK_BETA_ENABLED` (`FeedbackBanner.tsx:9`) равна `true` — сейчас
   так и есть; при `false` компонент возвращает `null` целиком. Это
   единственный переключатель — полноценной инфраструктуры фиче-флагов в
   проекте нет (см. "Известные ограничения")
2. Плашка смонтирована в `RootLayout.tsx:33`, внутри `<main>`, под
   анимированным контентом текущей страницы — видна на каждом маршруте,
   защищённом сессией (`/today`, `/tasks`, `/goals`, `/calendar`), но не
   на `/login`/`/register`/`/forgot-password`/`/reset-password`, которые
   рендерятся вне `RootLayout` (см.
   [09.01. Account Access-FRONTEND](../09.%20Authentication/09.01.%20Account%20Access-FRONTEND.md))

## Открытие формы

3. Клик по плашке открывает `FeedbackDialog` — состояние `open` живёт в
   `FeedbackBanner` (`useState`)

## Форма (`FeedbackDialog`)

4. Над `Textarea` — сегментированный тумблер типа отзыва
   (`ToggleGroup type="single"`/`ToggleGroupItem`, `variant="outline"`,
   `size="sm"`, `FeedbackDialog.tsx:84-97`) с двумя вариантами, оба видны
   и кликабельны одновременно — "Баг" (`feedback.typeBug`) и
   "Предложение" (`feedback.typeSuggestion`). Значение хранится в
   состоянии `type` (`useState<"bug" | "suggestion">`), по умолчанию
   `"bug"` — совпадает с формулировкой самой плашки, которая начинается
   со слов "Нашли баг" (`feedback.bannerLabel`). Выбранный `type`
   отправляется в теле POST-запроса (см. п. 10.2 ниже). Это осознанно
   другой паттерн, чем циклический `PriorityToggle` у `Task.priority`/
   `Reminder.priority` (одна кнопка, значение переключается по клику по
   кругу, см. [13.02. Reminder Entity-FRONTEND](../13.%20Reminders/13.02.%20Reminder%20Entity-FRONTEND.md)) —
   здесь оба варианта нужны видимыми и выбираемыми напрямую, а не
   спрятанными за циклом, поэтому выбран `ToggleGroup`, а не ещё один
   цикл-тумблер
5. `Textarea` для текста отзыва, автофокус при открытии
6. Кнопка отправки задизейблена, если текст пуст (`!message.trim()`) или
   пока идёт отправка (`isSubmitting`)
7. Кнопка "Attach a screenshot" открывает системный выбор файла (скрытый
   `<input type="file" accept="image/*">`, триггерится через `ref`)
8. При выборе файла:
   1. Если размер файла больше 5MB (`MAX_IMAGE_BYTES`) — показать
      `toast.error(t("feedback.imageTooLarge"))`, файл не принимается,
      поле файла сбрасывается (`e.target.value = ""`), чтобы повторный
      выбор того же файла снова вызвал `onChange`
   2. Иначе — прочитать файл через `FileReader.readAsDataURL`, положить
      результат (base64 data URL) в `imageData`
9. Пока `imageData` заполнен — вместо кнопки "Attach" показывается
   превью (`<img>`, до `max-h-32`) с кнопкой "×" поверх, которая сбрасывает
   `imageData` на `null` и возвращает кнопку "Attach" на место
10. Отправка (`handleSubmit`):
   1. Не выполняется, если `message.trim()` пуст (дополнительная защита
      сверх задизейбленной кнопки)
   2. `fetch("/api/feedback", { method: "POST", ... })` с JSON-телом
      `{ message: message.trim(), type, imageData: imageData ?? undefined,
      page: location.pathname }`, где `'type'` — выбранный вариант
      тумблера из п. 4 (`"bug"` или `"suggestion"`), `'page'` — путь
      текущего маршрута (`useLocation()`) на момент отправки
   3. При успешном ответе (`res.ok`) — `toast.success`, форма
      очищается (`message`/`imageData`/`type` сбрасываются, `type` — на
      дефолтное `"bug"`), диалог закрывается
   4. При неуспешном ответе или исключении (например, сеть недоступна) —
      `console.error`, `toast.error`, диалог остаётся открытым, введённый
      текст, прикреплённая картинка и выбранный тип не теряются

# Известные ограничения

1. `FEEDBACK_BETA_ENABLED` — единственный механизм отключения фичи;
   когда бета закончится, предполагается либо переключить константу в
   `false`, либо вовсе удалить `<FeedbackBanner />` из `RootLayout.tsx` и
   папку `src/widgets/feedback` целиком (см. `LEARNING.md`,
   `docs/BACKLOG.md`). Соответствующий серверный роут при этом сам по
   себе не отключается (см.
   [10.01. Feedback Widget-BACKEND](./10.01.%20Feedback%20Widget-BACKEND.md),
   "Известные ограничения")
2. Нет ограничения на частоту отправки — ни на клиенте, ни на сервере;
   один и тот же пользователь может отправить сколько угодно отзывов
   подряд без задержки
3. Ограничение на размер картинки (5MB) проверяется только на клиенте по
   размеру исходного файла (`file.size`) — фактическое ограничение на
   сервере (`imageData` до ~7 000 000 символов base64-строки, см.
   backend-документ) немного шире, так как base64 увеличивает размер
   примерно на треть; расхождение не критично, но означает, что
   теоретически возможен файл, прошедший клиентскую проверку и всё же
   отклонённый сервером как `400`, если исходный файл близок к границе в
   5MB
