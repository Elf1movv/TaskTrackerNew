# 13.05. Push Notifications [Backend]

# Описание

Push-уведомления (с 2026-11-12, выпущено на прод в тот же день): сервер сам
присылает напоминания на телефон или компьютер, даже если MyTracker не
открыт. Решения владельца — `docs/PRODUCT_LOGIC_DECISIONS.md`, «Push-напоминания
— 2026-11-12»:

1. Напоминание со временем — в его время
2. Напоминание без времени — утром в его день (время утра выбирает человек)
3. Критичное напоминание — ещё за 24 ч и за 1 ч (как окно на сайте,
   [13.04. Critical Reminder Alerts-FRONTEND](./13.04.%20Critical%20Reminder%20Alerts-FRONTEND.md))
4. Утренняя сводка — сколько задач со сроком сегодня, просроченных,
   привычек и напоминаний на день; не приходит, если всё по нулям, её можно
   отключить
5. Начало планов календаря — **не** присылаем

Сообщения подписаны ключами VAPID — по ним push-сервис браузера (Google,
Apple, Mozilla) понимает, что сообщение от нашего сервера. Библиотека —
`web-push` 3.6.7.

# Где находится (файлы)

- `server/src/routes/push.ts` — ключ, подписки, тестовое уведомление
- `server/src/routes/me.ts` — `GET`/`PUT /api/me/notifications` (настройки)
- `server/src/validation/push.ts` — схемы `zod`
- `server/src/lib/push/schedule.ts` — **что и когда** отправлять: чистые
  функции без базы и сети, покрыты `schedule.test.ts`
- `server/src/lib/push/scheduler.ts` — проверка раз в минуту
- `server/src/lib/push/sender.ts` — отправка и уборка мёртвых подписок
- `server/src/lib/push/messages.ts` — тексты на русском и английском
- `server/prisma/migrations/20261112200000_push_notifications/` — таблицы
  `PushSubscription`, `PushSent` и поля `User.timeZone/notifyTime/notifyDigest`
- `server/src/routes/push.test.ts` — тесты маршрутов

# Схема данных

1. `PushSubscription` — один браузер / одно установленное приложение:
   `'endpoint'` (уникальный адрес у push-сервиса), ключи `'p256dh'` и
   `'auth'`, `'language'` (`"ru" | "en"`, язык интерфейса при включении —
   для текстов), `'createdAt'`, `'lastSuccessAt'`, `'userId'` (удаляется
   вместе с пользователем)
2. `PushSent` — журнал отправленного: `'key'` (например
   `reminder:<id>:at`, `reminder:<id>:1h`, `digest:2026-11-15`),
   `'sentAt'`, `'userId'`; пара `userId + key` уникальна — одно и то же не
   уходит дважды. Записи старше 7 дней удаляются раз в час
3. `User.timeZone` — часовой пояс IANA (например `"Europe/Moscow"`), из
   браузера при включении и при каждом входе; `User.notifyTime` — `"HH:mm"`,
   по умолчанию `"09:00"`; `User.notifyDigest` — по умолчанию `true`

# Ключи VAPID

1. Переменные `server/.env`: `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`,
   `VAPID_SUBJECT` (на проде `https://mytracker.space`)
2. Если хоть одной нет — push просто выключен: `GET /api/push/key` отвечает
   `503`, переключатель в настройках скрыт, сервер запускается как обычно
3. **Ключи прода нельзя менять**: подписки привязаны к ключу, после смены
   всем пришлось бы включать уведомления заново (`docs/BACKLOG.md`, «копия
   секретов вне сервера»)

# Методы

Все методы требуют входа (`requireAuth`) и работают только с записями
`req.userId`.

1. При получении `GET /api/push/key` сервер должен:
   1. Если ключи не настроены — вернуть `503 { error }`
   2. Иначе вернуть `200 { publicKey }` — открытую половину ключа, браузеру
      она нужна для подписки
2. При получении `POST /api/push/subscriptions` сервер должен:
   1. Проверить тело `{ endpoint, keys: { p256dh, auth }, timeZone, language }`:
      `'endpoint'` — URL до 2048 символов, `'timeZone'` — известный пояс
      (`isValidTimeZone`), `'language'` — `"ru" | "en"`; иначе `400`
   2. Одной транзакцией: создать или обновить подписку **по `'endpoint'`**
      (тот же браузер присылает её при каждом входе; браузер, в который
      вошёл другой аккаунт, переходит к нему) и записать `'timeZone'`
      пользователю
   3. Вернуть `201 { ok: true }`
3. При получении `DELETE /api/push/subscriptions` сервер должен: удалить
   подписку с этим `'endpoint'`, только свою; вернуть `204`
4. При получении `POST /api/push/test` сервер должен:
   1. Если подписок нет — `404`
   2. Отправить «Уведомления работают 👍» на все устройства, каждому — на
      его языке
   3. Вернуть `{ result: "delivered" | "failed" | "gone" }`
5. При получении `GET /api/me/notifications` сервер должен: вернуть
   `{ notifyTime, notifyDigest, timeZone }`
6. При получении `PUT /api/me/notifications` сервер должен: принять любую
   часть из `{ notifyTime: "HH:mm", notifyDigest: boolean, timeZone }`
   (`400` при неверном формате), сохранить и вернуть то же, что `GET`

# Расписание (раз в минуту)

1. `startPushScheduler()` запускается вместе с сервером, если ключи есть.
   Проверка не начинается, пока не закончилась предыдущая
2. Берутся пользователи с `'timeZone'` и хотя бы одной подпиской
3. Для каждого «сейчас» переводится в его местную дату и минуту
   (`toLocalNow`), из базы — его невыполненные напоминания со вчера по
   послезавтра и ключи `PushSent` за 3 дня
4. `duePushes` решает, что пора отправить:
   1. Выполненные напоминания пропускаются
   2. Без времени — один раз в его день, в окне 30 минут от утреннего
      времени (`MORNING_WINDOW_MINUTES`)
   3. Со временем — в момент наступления; если минуту пропустили
      (перезапуск), догоняется в пределах 15 минут (`AT_WINDOW_MINUTES`)
   4. Критичное — раз в последние 24 ч и раз в последний час; если
      напоминание создали меньше чем за час, приходит только «за 1 ч»
   5. Сводка — раз в день в утреннем окне, если включена и не всё по нулям.
      Привычки дня — по `Habit.activeDays` (0 = воскресенье)
5. Каждое событие уходит на все устройства человека, сгруппированные по
   языку. Тег уведомления — один на напоминание: «через час» заменяется
   «пора» вместо того, чтобы копиться. Нажатие открывает `/today`
6. Срок жизни сообщения у push-сервиса — 1 час (`TTL: 3600`): телефон,
   выключенный дольше, не получит пачку устаревшего. Напоминания уходят с
   `urgency: "high"`, сводка — `"normal"`
7. Запись в `PushSent` — только если хоть одно устройство получило или все
   подписки оказались мёртвыми. При временной ошибке везде событие
   остаётся неотправленным и повторяется на следующей минуте, пока длится
   окно
8. Ответ push-сервиса `404`/`410` (браузер отписался, приложение удалено) —
   подписка удаляется

# Известные ограничения

1. Время напоминаний хранится как местное `"HH:mm"` без пояса; используется
   последний известный пояс человека. В поездке он обновится при следующем
   входе
2. Один процесс сервера — обычный таймер. Если серверов станет несколько,
   `PushSent` защитит от повторов, но проверка будет идти в каждом
3. Повторная попытка удаления подписки при ошибке сети не делается
   (осознанно, BACKLOG)
