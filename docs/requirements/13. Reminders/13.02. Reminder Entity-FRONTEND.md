# 13.02. Reminder Entity [Frontend]

# Описание

Полноценная сущность "Напоминание" — заголовок, дата, необязательное
время и приоритет (`'normal'`/`'critical'`), со своим хранением и CRUD,
отдельная от механизма `13.01. Due Date Reminders` (тот — просто toast
поверх уже существующих сроков задач и целей, ничего не хранит; см.
`13.01. Due Date Reminders-FRONTEND.md`, не спутать). Напоминание не
привязано к задаче или цели — самостоятельная запись. Ручного
переупорядочивания (drag-and-drop) у напоминаний нет — список всегда
отсортирован по дате, затем по времени.

Видно в нескольких местах: свёрнуто — карточкой на Today (в паре с
прогрессом целей, см. `05.01. Today Dashboard-FRONTEND.md`) и компактным
списком в глобальном колокольчике, видном на каждой защищённой странице
(см. `13.03. Reminder Bell-FRONTEND.md`); полностью — в панели дня на
странице Calendar, которая одновременно является "домашней страницей"
напоминаний (см. `04.01. Calendar-FRONTEND.md`). Критичные напоминания
(`'priority' === "critical"`) дополнительно всплывают отдельным
модальным окном при приближении срока — отдельный механизм, см.
`13.04. Critical Reminder Alerts-FRONTEND.md`.

# Функциональные требования

## Модель и CRUD

1. `'title'` — обязательное поле, `.trim()` проверяется перед сохранением
   (`ReminderForm.handleSubmit`, `src/features/reminder-form/ui/ReminderForm.tsx:54`)
2. `'date'` — обязательное поле, строка `"YYYY-MM-DD"`, тот же формат,
   что у `Task.dueDate`/`Goal.targetDate`
3. `'time'` — необязательное, строка `"HH:mm"` либо `null`, выбирается
   кастомным `TimePicker` (`src/features/reminder-form/ui/components/TimePicker.tsx`),
   не нативным `<input type="time">` — сознательная замена, штатный
   браузерный виджет времени не совпадал со стилем приложения (см. п. 11)
4. `'priority'` — `ReminderPriority` (`"normal" | "critical"`), по
   умолчанию `"normal"` — и на клиенте (начальное значение состояния
   формы для нового напоминания), и на сервере
   (`Reminder.priority @default("normal")`). `"critical"` переиспользует
   тот же красный цвет, что уже используется для `Task.priority ===
   "high"` (`REMINDER_PRIORITY_COLORS.critical = "#c9503a"`,
   `src/entities/reminder/model/reminder.ts`) — единое значение красного
   во всём приложении, а не два независимых оттенка. Влияет на: иконку
   приоритета рядом с заголовком в списках (п. 17), фон плашки в сетке месяца
   (п. 18), счётчик `'critical'` в бейджах (п. 25-26, `13.03.`) и на
   срабатывание модального окна (`13.04.`)
5. `'completed'` — булево, переключается отдельно от редактирования
   заголовка/даты/времени/приоритета (см. п. 15)
6. У напоминания **нет** поля `'order'` — сортировка всегда по `'date'`,
   затем по `'time'` (см. `04.01. Calendar-FRONTEND.md`, п. 18), ручного
   drag-and-drop переупорядочивания не существует. Это единственная
   CRUD-сущность проекта без `PATCH /reorder`
7. Создание (`addReminder`) генерирует `'id'` на клиенте
   (`generateId()` = `crypto.randomUUID()`) — тот же паттерн, что у
   Task/Goal, ради оптимистичного показа на экране до ответа сервера
8. Удаление (`deleteReminder`) — без диалога подтверждения, как у
   milestone'ов цели и у самих задач

## Форма (`ReminderForm`)

9. Принимает необязательный проп `'reminder'` — так же, как
   `TaskForm`/`GoalForm`: передан → режим редактирования
   (`updateReminder`), не передан → режим добавления (`addReminder`)
10. Принимает необязательный проп `'lockedDate'` (только для режима
    добавления) — если передан, поле выбора даты (`DatePicker`) в форме
    скрыто вовсе, а новое напоминание создаётся сразу на эту дату. Тот же
    паттерн, что `'lockedCategory'` у `TaskForm`, только для даты, а не
    категории. Используется при добавлении из панели дня календаря — там
    дата уже известна из контекста (см. `04.01. Calendar-FRONTEND.md`).
    При добавлении с Today (`ReminderSummary`) `'lockedDate'` не
    передаётся — дату нужно выбрать явно, по умолчанию подставляется
    сегодняшняя (`getTodayKey()`)
11. Поле времени (`TimePicker`) показывается всегда, независимо от
    `'lockedDate'` — необязательное в обоих режимах:
    1. Кнопка-тумблер "Без времени"/"Есть время" — тот же принцип, что у
       тумблера срока в `TaskForm`/`GoalForm`: по умолчанию выключено
       (`'time' = null`); клик включает поле и подставляет значение по
       умолчанию `"09:00"` (`DEFAULT_TIME`, `TimePicker.tsx:9`)
    2. Когда включено — два `Select` в теме приложения вместо свободного
       ввода: час (`00`–`23`) и минуты с шагом 5 (`00, 05, ..., 55`,
       `MINUTES`, `TimePicker.tsx:8`) — минутный список не по одной
       минуте намеренно, чтобы не превращаться в список из 60 строк
    3. Повторный клик по тумблеру выключает поле и возвращает `'time'` в
       `null`
12. Циклический переключатель приоритета (`PriorityToggle`, тот же
    визуальный паттерн, что у `PriorityToggle` в `TaskForm.tsx`, только
    с двумя значениями вместо трёх) — клик переключает
    `"normal" → "critical" → "normal"`; цвет кнопки — рамка, фон и текст
    — берётся из `REMINDER_PRIORITY_COLORS[priority]`
    (`nextPriority`, `ReminderForm.tsx:18-20`)
13. Enter в поле заголовка отправляет форму (`onKeyDown`,
    `ReminderForm.tsx:70`)
14. Кнопка сохранения подписана `"Добавить напоминание"`/`"Add reminder"`
    в режиме добавления и `"Сохранить"`/`"Save"` в режиме редактирования

## Переключение и удаление (`ReminderToggleCheckbox`, `DeleteReminderButton`)

15. `ReminderToggleCheckbox` — кружок с иконкой галочки при `'completed' =
    true`, без неё — при `false`; клик вызывает `toggleReminder`.
    Переиспользуется во всех местах отображения напоминания (карточка на
    Today, панель дня календаря, попап глобального колокольчика — см.
    `13.03. Reminder Bell-FRONTEND.md`); в сетке месяца — нет, там нет
    чекбокса, см. `04.01. Calendar-FRONTEND.md`
16. `DeleteReminderButton` — иконка корзины, видна только при наведении
    родительской строки (`group-hover`) — тот же визуальный паттерн, что
    у удаления milestone'а цели

## Визуальный признак приоритета

17. Иконка приоритета (`ReminderPriorityIcon`,
    `src/entities/reminder/ui/ReminderPriorityIcon.tsx`) рядом с текстом
    напоминания — показывается для **обоих** уровней приоритета, не
    только критичного: `'normal'` → знак "равно" (`Equal`, цвет
    `REMINDER_PRIORITY_COLORS.normal`), `'critical'` → двойной шеврон
    вверх (`ChevronsUp`, `REMINDER_PRIORITY_COLORS.critical`, тот же
    красный, что у `Task.priority === "high"`). До 2026-09-22 признак был
    красной точкой (`size-1.5 rounded-full`) и рисовался только при
    `'priority' === "critical"` — обычный приоритет не имел никакого
    визуального признака вовсе; замена на иконку для обоих уровней читается
    как единая система координат приоритета, а не "есть только тревожная
    метка". Показывается в четырёх местах: `ReminderRow.tsx` (карточка
    Today, `src/widgets/reminder-summary/ui/components/ReminderRow.tsx`),
    `DayReminderRow.tsx` (панель дня календаря,
    `src/widgets/day-detail-panel/ui/components/DayReminderRow.tsx`),
    попап глобального колокольчика
    (`src/widgets/reminder-bell/ui/ReminderBell.tsx`, см. `13.03. Reminder
    Bell-FRONTEND.md`) и, впервые с 2026-09-22, компактная плашка в сетке
    месяца Calendar (`CalendarDayCell.tsx`, см. `04.01.
    Calendar-FRONTEND.md`, п. 14.2) — раньше там не было вовсе никакого
    признака приоритета, кроме фона плашки (п. 18)
18. В сетке месяца на Calendar приоритет, помимо иконки (п. 17), виден и
    через фон самой плашки, как и раньше: критичное напоминание получает
    красноватый фон (`bg-destructive/15 text-destructive`) вместо
    нейтрального (`bg-primary/10 text-primary`), см. `04.01.
    Calendar-FRONTEND.md`, п. 14.1
19. Вне сетки месяца Calendar (где приоритет виден и через фон плашки,
    п. 18) иконка (п. 17) — единственный визуальный признак приоритета;
    обычный приоритет (`'normal'`) больше не "молчаливое" состояние без
    какого-либо признака, как было до 2026-09-22

## Карточка на Today (`GoalReminderSwapCard`)

20. На Today напоминания не показываются отдельным постоянным блоком — они
    делят одну и ту же ячейку сетки с карточкой прогресса целей
    (`GoalProgressSummary`) через переключатель `GoalReminderSwapCard`, а
    не два раздельных виджета рядом. Это компонент уровня страницы
    (`src/pages/today/ui/components/`), а не виджет — виджет не может
    напрямую импортировать другой виджет по правилам FSD-слоёв, а
    `GoalReminderSwapCard` объединяет сразу два (`GoalProgressSummary` и
    `ReminderSummary`)
21. Круглая кнопка-переключатель (иконка `Bell`, когда видна карточка
    целей → показать напоминания; иконка `Target` — та же иконка, что у
    пункта "Цели" в боковом меню, когда видна карточка напоминаний →
    вернуть цели) прибита к правому верхнему углу именно этой карточки
    (`absolute -top-3 -right-3`), не к вьюпорту — в отличие от кнопки
    настроек и глобального колокольчика, которые зафиксированы
    относительно экрана. Эта же кнопка несёт бейдж и обёрнута в
    `Tooltip` — см. п. 25-26
22. По клику карточки "Прогресс целей" и "Напоминания" меняются местами.
    Обе смонтированы **всегда** (не через условный рендер/unmount) —
    лежат в одной CSS Grid-ячейке (`col-start-1 row-start-1` у обеих) и
    анимируются через `motion.div`'s `animate` (`transform`/`opacity`/
    `z-index`, `transition: 0.3s easeOut`), а не через
    `AnimatePresence`-монтирование. Задняя карточка не полностью
    невидима — смещена (`x: 10, y: 10`), уменьшена (`scale: 0.96`) и
    полупрозрачна (`opacity: 0.55`), создавая эффект "видна за передней"
23. Задняя (неактивная в данный момент) карточка получает
    `pointer-events-none` — клики/наведение сквозь неё не проходят, хотя
    физически она отрендерена и видна частично
24. `ReminderSummary` (содержимое карточки напоминаний) показывает список
    через `selectUpcomingReminders` — напоминания от сегодняшнего дня и
    позже (`'date' >= сегодня`), отсортированные по дате, затем по
    времени; прошедшие напоминания в этом списке не показываются вовсе,
    список не ограничен по длине (не capped) — весь объём "полной
    картины" целенаправленно оставлен для календаря, эта карточка —
    только "беглый взгляд"
25. Круглая кнопка-переключатель несёт красный кружок-бейдж
    (`bg-destructive`, `-top-1 -right-1`) с числом `'total'` из
    `summarizeReminders(reminders)`
    (`src/entities/reminder/lib/summarizeReminders.ts`) — считает
    незавершённые (`'completed' = false`) напоминания среди уже
    предстоящих (`selectUpcomingReminders`, `'date' >= сегодня`).
    Бейдж рендерится, только если `total > 0` — при отсутствии подходящих
    напоминаний кнопка остаётся без него
26. Кнопка обёрнута в `Tooltip` (`src/shared/ui/tooltip.tsx`) с
    `delayDuration={1500}` — задержка 1.5 секунды перед показом, дольше
    значения по умолчанию `0`, которое использует любой другой `Tooltip`
    в проекте (см. п. 34 ниже про сам компонент). Текст тултипа — ключ
    `reminders.badgeTooltip` = `"Напоминаний: {total} · критичных:
    {critical}"`/`"Reminders: {total} · critical: {critical}"`,
    показывается только вместе с самим бейджем (`total > 0`)
27. Карточка при заходе на Today автоматически открывается на
    "Напоминаниях" вместо "Прогресса целей", если среди `reminders` есть
    хотя бы одно подходящее под `summarizeReminders` (`total > 0`) на
    момент, когда список реально загрузился. Если подходящих напоминаний
    нет — карточка остаётся на "Прогрессе целей" (`showReminders =
    false` по умолчанию), как и раньше
28. Решение принимается через `useEffect`, ожидающий `'remindersLoaded'`
    (проп `GoalReminderSwapCard`, прокинутый из `TodayProvider`/
    `todayContext.ts` как одноимённое поле `TodayContextValue` —
    значение берётся из `'isLoaded'` `ReminderProvider`'s
    `usePersistedCollection`), а **не** через ленивый инициализатор
    `useState(() => ...)`. Причина: `reminders` на самом первом рендере
    всегда `[]`, потому что `ReminderProvider` грузит их с сервера
    асинхронно (`GET /api/reminders`); ленивый инициализатор `useState`
    вызывается ровно один раз, на первом рендере, когда список ещё точно
    пуст независимо от того, что реально лежит на сервере — карточка
    никогда не открылась бы сама, какие бы данные ни пришли позже. Баг
    найден `qa-tester`-агентом 2026-09-22 и исправлен переходом на
    `useEffect` (см. `LEARNING.md`, `docs/ARCHITECTURE.md`, 2026-09-22)
29. `useRef` (`hasSetInitial`, `GoalReminderSwapCard.tsx:42`) гарантирует,
    что решение об автооткрытии принимается ровно один раз за время
    жизни компонента — после того как оно однажды принято, дальнейшие
    изменения `reminders` (добавление, выполнение, удаление) не
    передёргивают карточку обратно на "Напоминания" или обратно на
    "Прогресс целей"
30. `ReminderSummary` содержит кнопку "+" в шапке — открывает/закрывает
    инлайн `ReminderForm` (без `'lockedDate'`, дата выбирается явно)
31. `ReminderSummary` дополнительно показывает фильтр приоритета — две
    кнопки-пилюли "Все"/"Критичные" (`reminders.filterAll`/
    `reminders.filterCritical`, тот же визуальный паттерн, что у фильтра
    статуса в `TaskBoard`), локальный `useState`, без похода на сервер —
    фильтрует уже загруженный список на клиенте. Показывается только при
    `reminders.length > 0` — до первого добавления напоминания фильтр не
    рендерится вовсе, даже пустым
32. Клик по строке напоминания (`ReminderRow`) — не по чекбоксу — переходит
    на Calendar: `navigate('/calendar?date=' + reminder.date)`. Клик по
    чекбоксу переключает выполнение и не переходит никуда
    (`stopPropagation` на обёртке чекбокса, `ReminderRow.tsx:18`)
33. Пустое состояние `ReminderSummary` — "Пока нет напоминаний"/"No
    reminders yet", не показывается, пока открыта инлайн-форма добавления

## `Tooltip` с настраиваемой задержкой

34. `Tooltip` (`src/shared/ui/tooltip.tsx`) получил необязательный проп
    `'delayDuration'`, по умолчанию `0` — то же значение, что было жёстко
    зашито раньше, поэтому все прежние места использования `Tooltip` в
    проекте не изменили поведения. Проп прокидывается во внутренний
    `TooltipProvider`. Единственные места, где передаётся отличное от `0`
    значение (`1500`) — бейджи напоминаний: эта карточка (п. 26) и
    глобальный колокольчик (`13.03. Reminder Bell-FRONTEND.md`)

# Известные ограничения

1. Нет пагинации/лимита в `ReminderSummary` на Today — при большом
   количестве предстоящих напоминаний карточка может стать длинной;
   осознанно не ограничивается, так как в проекте это не наблюдалось на
   практике
2. Просроченные (прошедшие, но не выполненные) напоминания не попадают ни
   в `selectUpcomingReminders` (карточка Today, глобальный колокольчик),
   ни выделяются каким-либо особым образом где-либо ещё — в отличие от
   `13.01. Due Date Reminders`, у этой сущности нет отдельного
   "скоро/просрочено" предупреждения для обычного приоритета. Календарь
   остаётся единственным местом, где такое напоминание вообще видно (см.
   `04.01. Calendar-FRONTEND.md` — известное ограничение про отсутствие
   переключателя видов календаря). Критичные напоминания в момент
