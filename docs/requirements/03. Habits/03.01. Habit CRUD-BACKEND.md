# 03.01. Habit CRUD [Backend]

# Где находится (файлы)

- `server/src/routes/habits.ts` — все методы
- `server/src/validation/habit.ts` — схемы валидации (`zod`)
- `server/prisma/schema.prisma` — модель `Habit`
- `server/src/middleware/requireAuth.ts` — проверка сессии

# Авторизация и разграничение по пользователю

Тот же паттерн, что у `Task` (см.
[01.01. Task CRUD-BACKEND](../01.%20Tasks/01.01.%20Task%20CRUD-BACKEND.md),
раздел "Авторизация и разграничение по пользователю"): `habitsRouter.use(requireAuth)`,
`401` без сессии, `'userId' = req.userId` на `GET`/`POST`, `userId` в
`WHERE` у `updateMany`/`deleteMany` для `PATCH reorder`/`PATCH :id`/
`DELETE :id` — привычка другого пользователя ведёт себя как
несуществующая (`404`, не `403`).

# Методы

Тот же паттерн, что у Task и Goal (см. `01.01. Task CRUD-BACKEND.md` —
здесь только отличия по полям):

1. `GET /api/habits` — все привычки по `'order'`, клиенту отдаются
   `'id'`, `'title'`, `'icon'`, `'color'`, `'completedDates'`,
   `'updatedAt'`
2. `POST /api/habits` — валидация `createHabitSchema`, `'order'` =
   минимум минус 1, код `201`. Streak (серия дней подряд) на сервере не
   хранится и не вычисляется — это чисто клиентский расчёт по
   `'completedDates'` (см. `03.01. Habit CRUD-FRONTEND.md`)
3. `PATCH /api/habits/reorder` — меняет только `'order'`, зарегистрирован
   до `PATCH /:id`
4. `PATCH /api/habits/:id` — атомарное условное обновление по
   `'expectedUpdatedAt'`, `404`/`409`/`200` — идентично Task
5. `DELETE /api/habits/:id` — `404`/`204` — вместе с привычкой удаляется
   вся история `'completedDates'`, отдельно не хранится и не
   архивируется

# Известные ограничения

1. `'completedDates'` — массив строк без ограничения на формат/дубликаты
   на уровне схемы валидации (только на клиенте гарантируется формат
   `"YYYY-MM-DD"` и отсутствие дублей через `toggleHabit`) — сервер
   технически примет любые строки в этом массиве
2. `'userId'` — `String?` (nullable): привычки, созданные до авторизации,
   имеют `'userId' = NULL` и не видны ни одному пользователю, пока не
   выполнена разовая миграция продовых данных (см.
   [09.01. Account Access-BACKEND](../09.%20Authentication/09.01.%20Account%20Access-BACKEND.md))
