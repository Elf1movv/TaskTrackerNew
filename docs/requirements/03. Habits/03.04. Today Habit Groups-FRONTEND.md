# 03.04. Today Habit Groups [Frontend]

# Описание

С 2026-09-24 виджет "Привычки" на главном экране (Today) тоже показывает
привычки сгруппированными в блоки — до этого он был плоским списком
(`HabitCard`/`HabitListRow` без обёртки по блокам). Сущность блока
(`HabitGroup`), её CRUD и общий с `/habits` список/порядок блоков
описаны в `03.03. Habit Groups-FRONTEND.md` — этот файл описывает только
то, что отличается на Today: привычки без блока простым списком
(`GeneralHabitsList`), карточка блока (`TodayHabitGroupCard`),
показ всех блоков с фильтром привычек по сегодняшнему расписанию и независимый от `/habits`
порядок привычек внутри блока (`'todayOrder'`).

Своей серверной логики нет — использует те же методы `Habit`/
`HabitGroup` CRUD, что и `/habits` (см. `03.01. Habit CRUD-BACKEND.md`,
`03.03. Habit Groups-BACKEND.md`), включая отдельный роут `PATCH
/api/habits/reorder-today`.

# Функциональные требования

## Какие блоки показываются

1. `HabitTrackerGrid` делит блоки на встроенный «Общие» (`'isGeneral' =
   true`) и именованные (`HabitTrackerGrid.tsx:142-144`). С 2026-11-08
   (итерация 3.1) привычки «Общих» показываются не карточкой блока, а
   простым списком без заголовка (`GeneralHabitsList`, см. пп. 5-8).
   Данные не меняются — это по-прежнему привычки группы «Общие».
2. Все группы выводятся в общем серверном порядке (`'order'`, общий с
   `/habits`): список «Общих» стоит там, где его поставил пользователь, —
   с 2026-11-08 он больше не прибит наверх (см. п. 8а). Именованные блоки —
   по одной карточке `TodayHabitGroupCard`, включая пустые и блоки без
   привычек на сегодня.
   Созданный блок виден сразу, до добавления первой привычки.
3. Внутри блока и в списке «Общих» отображаются только привычки
   сегодняшнего расписания. Счётчик блока — по этим привычкам, пустой
   блок даёт `0/0`. Счётчик в заголовке виджета («N из M сегодня») — по
   всем сегодняшним привычкам, включая «Общие».
4. Общее пустое состояние виджета («Пока нет привычек») показывается,
   только если именованных блоков нет, в «Общих» нет сегодняшних
   привычек и закрыты обе формы — создания блока и добавления привычки
   (`HabitTrackerGrid.tsx:233-243`).

## Привычки без блока (`GeneralHabitsList`)

5. Список без заголовка, иконки замка и счётчика — бейдж «Основной»
   (`habits.group.general`) удалён вместе с ключом перевода. Вид
   (сетка/список) — общий для виджета. Клик «изменить» у привычки
   открывает `HabitForm` над списком с `'lockedGroupId'` = «Общие».
6. Кнопка «Добавить привычку» в заголовке виджета (показывается, если
   группа «Общие» загружена) открывает/закрывает `HabitForm` с
   `'lockedGroupId'` = «Общие» над списком — привычка создаётся без
   блока (`HabitTrackerGrid.tsx:185-194`). Привычку в именованный блок
   добавляют кнопкой внутри его карточки (п. 11).
7. Весь список — цель переноса типа `"habit-move-today"`: брошенная на
   него привычка из блока переходит в «Общие» через
   `moveHabitToGroupToday(habitId, general.id)`; перенос на строку
   привычки «Общих» из того же списка переставляет её
   (`reorderHabitsToday`), из блока — тоже переносит в «Общие»
   (`GeneralHabitsList.tsx:37-42`).
8а. Перестановка списка среди блоков (2026-11-08, без новых элементов
   интерфейса): список — участник того же порядка блоков
   (`useDragReorder`, тип `"habit-group"`, `reorderHabitGroups`).
   Блок, перетащенный за шапку через список, меняется с ним местами;
   зажатое пустое место списка (не карточка) тащит весь список среди
   блоков, пока он полупрозрачен. Зажатая карточка привычки — свой,
   вложенный источник перетаскивания: тащит только эту привычку, и
   брошенная на шапку блока она по-прежнему переносится в блок.
8. Если в «Общих» нет сегодняшних привычек и форма закрыта, список не
   рендерится. Во время перетаскивания привычки (`useIsDragging(
   "habit-move-today")`, `src/shared/lib/dnd/useIsDragging.ts`) вместо
   него появляется пунктирная зона «Отпустите здесь, чтобы убрать
   привычку из блока» (`habits.dropOutOfBlock`), подсвеченная при
   наведении.

## Карточка блока

9. Заголовок — цветная полоса с иконкой, названием, счётчиком и
   стрелкой. Иконка окрашена цветом блока, фон полосы — приглушённая
   смесь этого цвета с фоном карточки (`TodayHabitGroupCard.tsx`).
   Заголовок служит ручкой перестановки блока и целью переноса привычки
   из другого блока. Справа — кнопки редактирования и удаления блока.
10. Каждая карточка — свой `Accordion`, по умолчанию **свёрнут**
    (с 2026-11-08; раньше был открыт). Открытие/закрытие запоминается
    для каждого блока отдельно на время сессии браузера —
    `useTodayGroupOpen(group.id)` (`lib/todayGroupOpen.ts`) хранит
    карту `{ [groupId]: boolean }` в `sessionStorage` под ключом
    `"mytracker-today-habit-groups-open"`. Новая сессия снова начинается
    со свёрнутых блоков. Если хранилище недоступно, блок
    переключается, но состояние не запоминается.
11. Добавление привычки в блок — кнопка «Добавить привычку» внутри
    раскрытой карточки (`HabitForm` с `'lockedGroupId'` = этого блока).
12. Если в блоке нет привычек на сегодня и форма добавления закрыта:
    1. В полной коллекции нет привычек с его `'groupId'` → «В этом блоке
       пока нет привычек» (`habits.group.empty`).
    2. Привычки есть, но вне расписания сегодня → «На сегодня привычек
       нет» (`habits.group.noneToday`).
    3. «Добавить привычку» доступно в обоих случаях. Переход на `/habits`
       для добавления первой привычки не требуется.

## Независимый порядок привычек внутри блока (`'todayOrder'`)

13. Привычка внутри одного блока переставляется перетаскиванием карточки/
    строки на другую в том же блоке — `reorderHabitsToday(groupId,
    draggedId, targetId)` (`HabitProvider.tsx`), пишет `'todayOrder'`, а
    не `'order'`. Это тот же общий `useDragReorder`/`usePersistedCollection
    .reorder()` механизм, что и везде в приложении, но использует
    отдельный тип перетаскивания `"habit-move-today"` (не пересекается с
    `/habits`' `"habit-move"` — технически не может, так как это разные
    страницы, но типы разведены явно, а не полагаются на это)
14. Привычку можно перетащить в **другой** блок на Today — на заголовок
    другого блока, на строку конкретной привычки в нём или в список
    привычек без блока (п. 7) —
    `moveHabitToGroupToday(habitId, targetGroupId)`: сначала дожидается
    серверного подтверждения смены `'groupId'` (`update()`), затем одним
    отдельным вызовом переставляет привычку в конец списка привычек
    целевого блока по оси `'todayOrder'` (`reorder(...,
    habitRepository.reorderToday)`) — тот же порядок действий и та же
    причина (избежать ложного конфликта "changed elsewhere"), что и у
    `moveHabitToGroup` на `/habits`, см. `03.03. Habit
    Groups-FRONTEND.md`, п. 22
15. Принадлежность привычки к блоку (`'groupId'`) — общая с `/habits`:
    `moveHabitToGroupToday` и `moveHabitToGroup` меняют один и тот же
    `'groupId'`. Независим только порядок **внутри** списка — привычка,
    переставленная внутри блока на Today, не меняет свою позицию среди
    привычек того же блока на `/habits`, и наоборот
16. `usePersistedCollection.reorder()` принимает необязательный второй
    аргумент — какую сетевую функцию вызывать вместо `repository.reorder`
    по умолчанию (`src/shared/lib/storage/usePersistedCollection.ts`).
    `reorderHabitsToday`/`moveHabitToGroupToday` передают
    `habitRepository.reorderToday` этим аргументом — так вся защита от
    гонок (очередь запросов, оптимистичное обновление, "посев" свежего
    `updatedAt` в `pendingUpdates` после ответа сервера, см.
    `LEARNING.md`, 2026-09-20/23) достаётся независимой оси `'todayOrder'`
    бесплатно, без дублирования кода `usePersistedCollection`
17. Новая привычка (`addHabit`) получает от сервера оба поля —
    `'order'` и `'todayOrder'` — сразу равными "последняя позиция в
    группе" на обоих экранах одновременно (см. `03.01. Habit
    CRUD-BACKEND.md`, `POST /api/habits`)

# Известные ограничения

1. Как и на `/habits`, перетаскивание привычки на конкретную строку в
   другом блоке не ставит её на позицию этой строки — она всегда
   добавляется в конец целевого блока по оси `'todayOrder'`
