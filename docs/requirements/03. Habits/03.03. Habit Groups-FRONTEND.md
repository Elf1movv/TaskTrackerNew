# 03.03. Habit Groups [Frontend]

# Описание

На странице `/habits` (не на Today — см. `05.01. Today
Dashboard-FRONTEND.md`, там виджет привычек остался плоским списком без
группировки) привычки собраны в именованные сворачиваемые блоки
("Утро" 🌅, "Вечер" и т.п.), по аналогии с тем, как цели разворачиваются
аккордеоном на странице Goals. Каждый блок — своя карточка со своим
независимым переключателем периода (Неделя/Месяц/Год), своей сеткой,
своим графиком и своим сворачиванием/разворачиванием. Привычки, не
отнесённые ни к одному пользовательскому блоку, лежат в специальном
неудаляемом блоке "Общие". Блоки и привычки внутри блока
переставляются перетаскиванием; привычку можно перетащить и в другой
блок целиком.

# Функциональные требования

## Блок "Общие"

1. "Общие" — не псевдо-группа и не `groupId: null`, а обычная запись
   `HabitGroup` с `'isGeneral' = true`, автосоздаётся на сервере лениво
   (см. `03.03. Habit Groups-BACKEND.md`) и приходит в общем списке
   `GET /api/habit-groups` наравне с остальными
2. Название и иконка "Общие"/📋, приходящие с сервера, — заглушки, нигде
   не показываются как есть: `getHabitGroupTitle()`/`getHabitGroupIcon()`
   (`src/entities/habit-group/lib/habitGroupDisplay.ts`) всегда
   подставляют локализованную подпись (`habits.group.generalTitle`) и
   фиксированную иконку `📋` для группы с `'isGeneral' = true`
3. Для этой группы кнопки редактирования/удаления не отрисовываются
   вовсе (`!group.isGeneral && (...)`,
   `HabitGroupAccordionItem.tsx:121`) — не задизейблены, а отсутствуют.
   Сама группа при этом полноценно участвует в drag-and-drop
   переупорядочивания блоков, как и любая другая
4. По умолчанию (`'order' = 999999` на сервере) "Общие" сортируется
   последней среди блоков, но её можно перетащить на любую позицию

## Блок — CRUD

5. Форма блока (`HabitGroupForm`) — поля `'title'` (обязательное,
   `.trim()`, Enter сохраняет) и `'icon'` (кнопка с эмодзи по умолчанию
   `"✨"`, открывающая `EmojiPicker` с набором `HABIT_ICONS` — тот же
   набор, что у иконки привычки)
6. Кнопка "+ Добавить блок" на странице (`HabitHistoryGrid`) открывает
   форму добавления в режиме создания; повторный клик закрывает её
   (переключатель, `isAddingGroup`)
7. Клик по иконке редактирования в заголовке блока открывает ту же
   форму в режиме редактирования этого блока, предзаполненную его
   `'title'`/`'icon'`
8. Удаление блока (`DeleteHabitGroupButton`) требует подтверждения —
   `AlertDialog` с текстом, явно предупреждающим, что привычки блока не
   удаляются, а переезжают в "Общие" (`habits.group.deleteBody`, с
   подстановкой `'title'` блока). После подтверждения — `deleteHabitGroup`,
   затем `refreshHabits()`: локальная коллекция привычек не знает сама
   по себе, что сервер переставил `'groupId'` у чьих-то привычек в той же
   транзакции, поэтому требуется явный полный рефетч (тот же паттерн, что
   у удаления категории с задачами)
9. Новый блок добавляется в конец списка блоков (тот же порядок, что у
   задач/целей/привычек — новое всегда последнее)

## Блок — карточка и сворачивание

10. Каждый блок — отдельная `Accordion`-карточка
    (`HabitGroupAccordionItem`), развёрнутая по умолчанию (`isOpen =
    true`, локальный `useState`, не персистится). Несколько блоков могут
    быть открыты одновременно — сворачивание одного не влияет на другие
11. Заголовок блока — иконка, название, счётчик привычек
    (`habits.group.habitCount`), сам является ручкой перетаскивания
    (`cursor-grab`) для переупорядочивания блоков между собой
12. У каждого блока — собственный, полностью независимый от других
    блоков: переключатель периода (Неделя/Месяц/Год, по умолчанию
    "Неделя"), переключатель стиля графика (area/bar/step, по умолчанию
    "area"), состояние формы добавления/редактирования привычки. Все
    локальные (`useState` внутри `HabitGroupAccordionItem`), не
    персистятся и не синхронизированы между блоками — сетка/график
    внутри блока устроены идентично тому, что было описано для единой
    страницы до этой фичи, см. `03.02. Habit History-FRONTEND.md`,
    разделы "Сетка" и "График и сводка" (там же остаётся точное описание
    поведения ячеек дня/месяца, стилей графика и сводки — теперь в
    масштабе одного блока, а не всей страницы)
13. Кнопка "+ Добавить привычку" внутри блока открывает `HabitForm` в
    режиме создания с `'lockedGroupId'` = этого блока — см. ниже

## Привычка — выбор блока в форме

14. `HabitForm` принимает необязательный проп `'lockedGroupId'` — когда
    задан (привычка добавляется через "+" конкретного блока), поле
    выбора блока в форме скрыто вовсе, а не задизейблено, и новая
    привычка создаётся сразу в этом блоке
15. Поле выбора блока (`<Select>`, `habitForm.group`) показывается,
    когда: форма в режиме редактирования существующей привычки (тогда
    блок всегда можно сменить, даже если открыта из конкретного блока),
    либо форма добавления открыта без `'lockedGroupId'` (общий сценарий
    добавления вне блока, на практике сейчас недостижим — "+ Добавить
    привычку" есть только внутри блока, но форма поддерживает и этот
    случай)
16. Список вариантов в `<Select>` — все блоки пользователя, с иконкой и
    локализованным названием через `getHabitGroupIcon()`/
    `getHabitGroupTitle()` (включая "Общие")
17. Значение по умолчанию — `'groupId'` редактируемой привычки, либо
    `'lockedGroupId'`, либо первый блок в списке
18. Кнопка сохранения задизейблена и при пустом `'groupId'` (наравне с
    пустым названием и пустым `'activeDays'`, см. `03.01. Habit
    CRUD-FRONTEND.md`, п. 4)

## Перетаскивание блоков и привычек

19. Блоки переставляются перетаскиванием заголовка (`useDragReorder`,
    тип `"habit-group"`) — тот же общий drag-and-drop механизм, что у
    задач/целей/привычек, включая "Общие": она перетаскивается наравне
    со всеми, без исключения
20. Привычка внутри одного блока переставляется перетаскиванием строки
    на другую строку того же блока (`reorderHabitsInGroup`) — переставляет
    только привычки этого блока, остальные блоки не задеты
21. Привычку можно перетащить в **другой** блок — либо на конкретную
    строку привычки в другом блоке, либо на заголовок другого блока
    целиком (сам заголовок — тоже drop-зона, тип `"habit-move"`,
    `HabitGroupAccordionItem.tsx:66-69`):
    1. Drop на заголовок другого блока или в пустую область блока —
       привычка перемещается туда через `moveHabitToGroup`, добавляется
       **в конец** списка привычек целевого блока
    2. Drop на конкретную строку привычки того же блока —
       `reorderHabitsInGroup` (переупорядочивание внутри блока)
    3. Drop на конкретную строку привычки **другого** блока —
       `moveHabitToGroup` (точная позиция внутри целевого блока не
       учитывается, привычка всё равно попадает в конец — возможное
       будущее уточнение, сейчас не реализовано)
22. `moveHabitToGroup` — сначала дожидается серверного подтверждения
    смены `'groupId'` (`update()`), затем переставляет привычку в конец
    списка привычек целевого блока (`reorder()`) — оба шага должны
    выполняться по очереди, не параллельно, иначе возможен ложный
    конфликт "запись изменена в другом месте" (см. `usePersistedCollection`
    ниже)
23. Вложенность drop-зон одного типа (строка привычки — внутри
    заголовка блока, который тоже принимает `"habit-move"`) не приводит
    к двойному срабатыванию — общий хук `useDropTarget`
    (`src/shared/lib/dnd/useDropTarget.ts`) проверяет
    `monitor.didDrop()` и не вызывает `onDrop` повторно для внешней
    drop-зоны, если внутренняя уже обработала этот же drop. Это общее
    исправление на уровне переиспользуемого хука, действует для всех
    мест приложения с вложенными drop-зонами одного типа, не только для
    привычек

# Известные ограничения

1. Перетаскивание привычки на конкретную строку в другом блоке не
   ставит её на позицию этой строки — она всегда добавляется в конец
   целевого блока (см. п. 21.3)
2. `reorderHabitsInGroup`/`moveHabitToGroup` используют общий
   `usePersistedCollection.reorder()`, рассчитанный на то, что вызывающий
   может передать лишь подмножество коллекции (привычки одного блока) —
   элементы вне этого подмножества сохраняются в локальном состоянии, а
   не отбрасываются (иначе привычки остальных блоков пропадали бы из UI
   до следующей перезагрузки/рефетча)
