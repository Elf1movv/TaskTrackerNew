# 02.01. Goal CRUD [Frontend]

# Описание

Создание, редактирование, удаление и переупорядочивание целей, плюс
управление деревом внутри каждой цели. С итерации 3.1 (2026-11-08) цель
— двухуровневое дерево: подцели (`'subgoals'`), у каждой свои этапы, и
собственные этапы самой цели (`'milestones'`). Для этапов любого уровня —
добавление, переключение, редактирование текста, удаление и
переупорядочивание; для подцелей — добавление, переименование, удаление
и переупорядочивание.

# Функциональные требования

## Форма цели

1. Форма `GoalForm` принимает необязательный проп `'goal'` — так же, как
   `TaskForm`: передан → режим редактирования (`updateGoal`), не
   передан → режим добавления (`addGoal`)
2. Поле `'title'` — обязательное, `.trim()` проверяется перед
   сохранением. В отличие от `TaskForm`, Enter в этом поле **не**
   сохраняет форму
3. Поле `'description'` — многострочное, необязательное, `.trim()`
4. Поле `'targetDate'` — необязательное (`null` = "бессрочная"),
   управляется тем же полем `DateTimeField`
   (`src/shared/ui/date-time-field.tsx`), что и `'dueDate'` у `TaskForm`
   (см. `01.01. Task CRUD-FRONTEND.md`, п. 5 — там же описана замена
   прежнего стека кнопок-тумблеров одним попапом), но без пропов
   `'time'`/`'onTimeChange'`/`'endTime'`/`'onEndTimeChange'` вовсе: у
   цели нет поля времени суток, только дневная точность. Их **отсутствие**
   (а не значение `null`) — то, что говорит `DateTimeField` вообще не
   рендерить `TimePicker`. `'hasTargetDate'` управляется неявно, тем же
   принципом, что и `'hasDueDate'` у `TaskForm` — выбор дня в календаре
   включает его, "×" на кнопке выключает. По умолчанию **выключен** для
   новой цели; значение самого поля даты (используется, если дату всё же
   выберут) по умолчанию — сегодняшняя дата
   1. Проп `'defaultTargetDate'` (используется при добавлении цели из
      панели дня/квик-адда в Calendar — см. `04.02. Month
      View-FRONTEND.md` и `04.04. Day & Week Timeline-FRONTEND.md`)
      только подставляет значение поля даты на случай ручного включения
      тумблера, сам тумблер не включает — тот же принцип, что у
      `'defaultDueDate'` в `TaskForm`
5. Поле `'color'` — один из `PALETTE_COLORS` (`src/shared/lib/colors.ts` —
   12 фиксированных цветов, общих с привычкой и блоком привычек), по
   умолчанию первый цвет из списка
6. `'milestones'`, `'subgoals'` и `'progress'` не редактируются через эту
   форму — `'milestones'` и `'subgoals'` при создании всегда `[]`,
   `'progress'` всегда `0`
   1. Поле `'category'` описано в разделе «Категория цели», п. 24

## Этапы (milestones)

Всё в этом разделе действует одинаково для этапов самой цели и для этапов
подцели: операции `GoalProvider` принимают необязательный `'subgoalId'` —
без него меняются `'goal.milestones'`, с ним — `'milestones'` этой
подцели (`GoalProvider.tsx:58-106`).

7. Добавление milestone (`AddMilestoneForm`) — одно текстовое поле +
   кнопка (задизейблена, если поле пустое/пробелы), Enter тоже
   отправляет. Поле очищается после добавления
8. Переключение выполнения (`toggleMilestone`) — клик по кружку у
   milestone
9. Редактирование текста — клик по названию milestone превращает его в
   поле ввода; сохраняется по потере фокуса или Enter, отменяется по
   Escape или если после `.trim()` осталась пустая строка (возвращается
   исходный текст)
10. Удаление milestone — иконка корзины, видна только при наведении,
    без диалога подтверждения
11. Переупорядочивание этапов — drag-and-drop, работает **только
    внутри одного списка**: собственные этапы одной цели или этапы одной
    подцели (тип перетаскивания `milestone-<goalId>-<subgoalId | "own">`,
    `MilestoneRow.tsx`). Этап нельзя перетащить в другую цель или подцель
12. `'progress'` — `computeGoalProgress(milestones, subgoals)`
    (`src/entities/goal/lib/computeGoalProgress.ts`):
    `round((выполненные этапы цели + Σ доля выполненных этапов каждой
    подцели) / (этапы цели + подцели) × 100)`; `0`, если нет ни этапов,
    ни подцелей (не `NaN`); подцель без этапов даёт `0`. Без подцелей
    совпадает с прежней формулой `round(выполнено / всего × 100)`
13. Каждая операция с этапами и подцелями — локальный пересчёт массивов
    `'milestones'`/`'subgoals'` и `'progress'` и один вызов `update()` цели
    целиком (`saveTree`, `GoalProvider.tsx:52-56`) — при любом действии,
    включая переименование и перестановку. Клиентский `'progress'`
    нужен только для мгновенного оптимистичного показа — сервер
    пересчитывает его сам, и его значение побеждает (см.
    [02.01. Goal CRUD-BACKEND](./02.01.%20Goal%20CRUD-BACKEND.md), п. 4.2).
    Отдельных серверных методов на этапы и подцели нет

## Список целей (страница Goals)

14. Список — аккордеон, в любой момент **развёрнута только одна цель**;
    по умолчанию при загрузке страницы развёрнута первая цель в списке,
    либо, если страница открыта по deep link с Today (п. 23), сразу та
    цель, на которую был клик
15. В свёрнутом виде видно: кольцо прогресса, заголовок, описание,
    `"{выполнено}/{всего} этапов"` (только собственные этапы цели), при
    наличии подцелей — `" · подцелей: N"` (`goals.subgoalsCount`), срок
    (`'dueLabel'`) и, если `'category'` задано, метка категории (п. 25).
    Подцели и этапы видны только когда цель развёрнута
16. Кнопки редактирования и удаления цели видны всегда, независимо от
    состояния развёрнутости
17. Удаление цели — через диалог подтверждения (`AlertDialog`, «Отмена» /
    «Удалить», `src/features/delete-goal/ui/DeleteGoalButton.tsx`); после
    подтверждения цель удаляется вместе со всеми этапами и подцелями безвозвратно
18. Новая цель (`addGoal`) добавляется **в конец** списка, не в начало —
    то же правило, что у задач, см. `01.01. Task CRUD-FRONTEND.md`, п. 8
19. Переупорядочивание целей — drag-and-drop по всей строке цели, тот же
    общий механизм (`useDragReorder` + `usePersistedCollection.reorder()`,
    один сетевой запрос за раз), что у задач — см. `01.01. Task
    CRUD-FRONTEND.md`, п. 9
20. Пустое состояние — «Пока нет целей» (только если форма добавления не
    открыта в этот момент)
    1. Подзаголовок страницы — «Большие результаты и шаги к ним»
       (`goals.subtitle`)

## Сводка целей на Today

21. `GoalProgressSummary` получает с Today только активные цели
    (`'progress' < 100`, `TodayProvider.tsx:14`) и с 2026-11-08 показывает
    **первые 5** из них (`goals.slice(0, 5)`, `GoalProgressSummary.tsx:18`)
    в порядке вкладки Goals (общий порядок `reorderGoals`), каждую
    строкой: заголовок (обрезан до 2 строк), `{progress}%`, полоса
    прогресса. Остальные — по ссылке «Все цели» на `/goals`
22. Здесь тоже доступно переупорядочивание — использует ту же
    операцию `reorderGoals`, что и список на странице Goals (это один и
    тот же порядок, просто два разных места, откуда его можно менять)
23. Прямого редактирования (инлайн-форма) и удаления здесь по-прежнему
    нет — клик по строке цели (не по операции перетаскивания) переходит на
    страницу Goals, раскрывает там именно эту цель в аккордеоне и
    переставляет её первой в списке: `navigate('/goals?goal=' + goal.id)`
    (`GoalProgressRow.tsx:23`). Полноценное редактирование по-прежнему
    доступно только через карандаш (`EditGoalButton`) у цели в аккордеоне
    на странице Goals (п. 16) — этот переход его не заменяет и не
    открывает. Клик и drag-and-drop (п. 22) сосуществуют на одном и том же
    элементе строки без конфликта — обычный клик навигирует, а начатое
    перетаскивание переупорядочивает, не запуская навигацию
    1. До 2026-09-22 клик по строке цели на Today переходил на страницу
       Goals с сразу открытой формой редактирования этой цели
       (`?edit=<goalId>`) — это была первая версия поведения, введённая
       вместе с сущностью `Reminder` взамен полного бездействия клика (см.
       `13.02. Reminder Entity-FRONTEND.md`, п. 20); заменена
       раскрытием/переносом как более лёгким действием — увидеть
       milestones цели больше не требует входа в форму редактирования
    2. Deep link реализован через query-параметр `?goal=<goalId>` (было
       `?edit=`) в URL страницы Goals: `GoalsPage` читает его
       (`useSearchParams`) и сразу же чистит из URL (`replace: true`),
       передавая исходное значение в `GoalList` как проп `'initialGoalId'`
       (переименован из `'initialEditGoalId'`)
    3. `GoalList` держит раскрытую цель в управляемом `Accordion`
       (`value={openGoalId} onValueChange={setOpenGoalId}`,
       `GoalList.tsx:81-91` — раньше был неуправляемый
       `defaultValue={goals[0]?.id}`). `'openGoalId'` инициализируется
       ленивым `useState(() => initialGoalId ?? goals[0]?.id ?? "")`.
       Обычный клик (не по deep link) по любой цели в аккордеоне после
       этого раскрывает/закрывает её как раньше — просто через
       `onValueChange`, без побочных эффектов на порядок списка
    4. Отдельный `useEffect` с флагом "выполнить один раз за жизнь
       компонента" (`useRef`, `hasReordered`, `GoalList.tsx:36-43`)
       переставляет цель, пришедшую по deep link, на первое место в
       списке через `reorderGoals(initialGoalId, goals[0].id)` — тот же
       вызов, что уже использует drag-and-drop цели в
       `GoalAccordionItem.tsx`, здесь вызван программно. Эффект
       перепроверяется при каждом изменении `goals` (не только на
       монтировании), потому что на самом первом рендере `goals` может
       быть ещё не загружен с сервера — реордер выполняется, как только
       запрошенная цель реально находится среди уже загруженных
    5. Гонки с асинхронной загрузкой у самого `'openGoalId'` нет — в
       отличие от похожего по форме прошлого бага автораскрытия карточки
       напоминаний на Today (см. `13.02. Reminder Entity-FRONTEND.md`,
       п. 27), ленивый инициализатор `useState` здесь безопасен:
       `'openGoalId'` не решает, показывать ли что-то в принципе по
       количеству уже загруженных данных, а хранит только `'id'`, которому
       достаточно совпасть с уже отрисованным `AccordionItem`, когда бы
       тот ни появился

## Категория цели (третья итерация, 2026-11-08)

24. `GoalForm` (`src/features/goal-form/ui/GoalForm.tsx`) показывает
    `Select` «Категория» после поля срока:
    1. Первый пункт — «Без категории» (внутреннее значение `"__none__"`,
       при сохранении превращается в `'category' = null`)
    2. Далее — имена категорий из `useCategories()` в их порядке
    3. Новая цель по умолчанию «Без категории»; при редактировании
       выбрано текущее `'category'`
    4. Если у цели сохранено имя, которого уже нет среди категорий, оно
       добавляется последним пунктом и остаётся выбранным, пока его не сменят
    5. `'category'` уходит и в `addGoal`, и в `updateGoal`
25. Карточка цели в аккордеоне (`GoalAccordionItem.tsx`) при непустом
    `'category'` показывает рядом со сроком иконку `Tag` цветом категории
    (`resolveCategoryColor`) и имя категории. Без категории метки нет
26. На странице Goals над списком — фильтр-чипы (только если целей больше
    нуля):
    - «Все» (значение `"all"`, по умолчанию)
    - по чипу на каждую категорию, с цветным кружком
    - «Без категории» (`NO_CATEGORY_FILTER`)
    1. Активный чип залит основным цветом (`aria-pressed=true`)
    2. `filterGoals` (`src/pages/goals/lib/filterGoals.ts`): `"all"` —
       все цели; «Без категории» — цели с пустым `'category'`; иначе —
       `'category' ===` имя категории
    3. Фильтр не сохраняется в URL и сбрасывается на «Все» при уходе со страницы
    4. Перетаскивание при включённом фильтре безопасно: `reorderGoals`
       переставляет полный список (`reorderById`), скрытые цели не теряют
       позиции
27. После удаления категории на странице Tasks коллекция целей
    перечитывается (`collection-invalidated` с `"goal"`,
    `src/shared/lib/storage/invalidate.ts`) — у её целей метка пропадает,
    сами цели остаются (см. `01.02. Categories-FRONTEND.md`, п. 4.5)

## Подцели (итерация 3.1)

28. Раскрытая цель (`GoalAccordionItem.tsx`, блок `data-goal-tree`)
    показывает один общий список **без заголовков разделов** (решение
    владельца 2026-11-08: заголовки «Подцели» и «Этапы самой цели»
    путали — выглядели как лишние сущности; тот же подход, что у привычек
    «Без блока»). По порядку:
    1. Собственные этапы цели (`MilestoneRow`) и поле «Добавить этап…»
    2. Если подцели есть — после тонкого разделителя список `SubgoalItem`
    3. Поле «Добавить подцель…» (`AddMilestoneForm` с `kind="subgoal"` →
       `addSubgoal`; то же поведение поля, что в п. 7)
    4. Если нет ни этапов, ни подцелей — одна подсказка «Добавьте этапы
       или разбейте большую цель на подцели» (`goals.emptyTree`)
29. Строка подцели (`SubgoalItem.tsx`):
    1. Ручка `GripVertical` («Переместить подцель») — перестановка
       подцелей перетаскиванием только внутри своей цели
       (`reorderSubgoals`, тип `subgoal-<goalId>`)
    2. Стрелка раскрывает/скрывает этапы подцели («Показать/Скрыть этапы
       подцели»); по умолчанию свёрнута. В раскрытом виде — этапы
       (`MilestoneRow` с `'subgoalId'`), «Пока нет этапов», если их нет, и
       поле «Добавить этап…» для этой подцели
    3. Клик по названию превращает его в поле ввода: Enter или потеря
       фокуса сохраняют (`renameSubgoal`), Escape или пустая строка после
       `.trim()` возвращают прежнее название
    4. Полоса прогресса цветом цели (`GoalProgressBar`) и подпись
       `"{выполнено}/{всего} · {процент}%"` — доля выполненных этапов
       подцели (`subgoalFraction`)
    5. Удаление — иконка корзины (видна при наведении/фокусе) →
       подтверждение `ConfirmAction` «Удалить подцель» / «Подцель «{title}»
       и все её этапы будут удалены.» → `deleteSubgoal`

## Вторая итерация, 2026-10-10

Цели независимы от общих задач и календарных планов. Преобразования в
задачи и отдельного achievedAt в интерфейсе/API нет. (Тогда подцели
жили в `'milestones'`; с итерации 3.1 — отдельный уровень `'subgoals'`,
см. «Подцели».)
Удаление цели не меняет задачи, планы или заметки.
