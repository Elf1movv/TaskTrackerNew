# 02.01. Goal CRUD [Backend]

# Описание

Цель описывает результат и объединяет обычные задачи через `'Task.goalId'`.
Достижение результата (`'achievedAt'`) подтверждается отдельно от процента
выполненных задач. Спецификация ветки product-logic-redesign.

# Где находится (файлы)

- `server/src/routes/goals.ts`, `server/src/validation/goal.ts`
- `server/src/routes/transition.ts`
- `server/prisma/schema.prisma`

# Методы и правила

1. Все методы требуют сессию и работают только с данными владельца.
   Без сессии — `401`, чужая/несуществующая цель — `404`.
2. `GET /api/goals` возвращает свои цели по `'order'`: `'id'`, `'title'`,
   `'description'`, `'targetDate'`, `'color'`, `'progress'`, `'achievedAt'`,
   исторические `'milestones'` и `'updatedAt'`.
3. `'progress'` в ответе вычисляется по связанным задачам, исключая
   `'legacyPending'` и `'retiredAt'`: округлённое отношение выполненных
   к общему количеству. При отсутствии задач — 0. Сохранённое старое
   значение процента не является источником истины.
4. `POST /api/goals`: UUID задаёт клиент, новая цель добавляется в конец
   своего списка. Новая форма передаёт пустой `'milestones'`; старый JSON
   сохранён для разбора исторических подцелей.
5. `PATCH /api/goals/:id` принимает `{ patch, expectedUpdatedAt }`.
   Несовпадение версии — `409 { error, current }`. `'achievedAt'` —
   ISO-8601 либо null для возврата в активные. Выполнение всех задач
   не выставляет его автоматически, достижение цели не завершает задачи.
6. `PATCH /api/goals/reorder`: только `'order'`, транзакция в порядке id,
   ответ `200 { id, updatedAt }[]`. Остальные поля не перезаписываются.
7. `DELETE /api/goals/:id`: одна транзакция отвязывает задачи и удаляет
   цель. Их версии обновляются, планы и напоминания остаются. Ответ `204`.
8. `POST /api/transition/milestone`: подтверждённая старая подцель
   становится новой связанной задачей с прежним выполнением или ссылкой
   на существующую задачу. Статус существующей задачи сохраняется;
   перед запросом интерфейс показывает возможное различие. Снимок
   исходных данных и принятое решение сохраняются в LegacyTransition.
   Проверяются владельцы, версии цели/задачи; повторный запрос не
   создаёт копию. До решения старый JSON остаётся доступным для разбора.

# Ограничения

API продолжает принимать исторические `'progress'`/`'milestones'` ради
совместимости перехода. Новое приложение не создаёт отдельные подцели.
